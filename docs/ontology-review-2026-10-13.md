# MedDB 온톨로지 분석 — 2026-10-13

## 결론

현재 MedDB는 출처와 버전을 추적하는 의료 지식 그래프 및 탐색 도구로서 기반이 갖춰져 있다. 대회용 능동 진료 지원에는 관계의 부정 의미 처리, 환자 표현 정규화, 후보 구분 및 다음 행동 지식이 추가로 필요하다. 현재 데이터 규모나 구조 검증 통과를 진단 성능 개선의 증거로 해석할 수 없다.

분석 범위: Python KB/API/CLI, importer, 용어 처리, RDF/SHACL, 실제 최신 JSON, 테스트, 웹의 후보 표시 코드. 브라우저 시각 검수, 전체 최신 RDF 검증, 원문 문헌의 임상 타당성 검수, 대회 증례 성능 비교는 수행하지 않았다. 구현·데이터는 수정하지 않았다.

## 잘 구성된 점

- 개념, 관계 주장, 출처, 외부 매핑을 분리한다. 관계의 source_id/locator/context와 검수 상태를 추적할 수 있다.
- 버전별 파일과 SHA-256이 있어 에이전트 실험의 데이터 판을 고정할 수 있다.
- ID 중복, 끊긴 끝점, 관계 타입, 출처 참조, 검수자 없는 승인을 구조 검증에서 거부한다.
- present/absent/unknown을 구분하고 확률이 아닌 직접 소견 공통점임을 결과에 명시한다.
- 기본 조회에서 draft/rejected를 제외하고 RDF에서 관계 주장을 별도 Assertion으로 보존한다.
- Python KB를 직접 import할 수 있어 대회 실행 중 외부 DB 서버에 의존할 필요가 없다.

## 문제와 재현

### P0: EXCLUDED 관계의 부정 의미가 순위에서 뒤집힌다

has_phenotype 중 frequency_label=EXCLUDED가 21개 존재한다. rank는 frequency_label을 보지 않고 모두 양성 연관으로 grouped/findings에 넣는다. 첫 EXCLUDED 관계의 object를 present로 입력하면 해당 subject 질환이 matched 후보로 반환됨을 재현했다. 원문 맥락에는 해당 소견의 부재나 진단 구분 기준이 명시되어 있다.

권장: polarity와 적용 조건을 명시하고, 양성 표현형과 부정 관계를 분리한다. EXCLUDED를 단순한 낮은 빈도로 변환하지 않는다. present가 반박 근거, absent가 지지 근거가 되는지는 관계의 맥락을 함께 검수한다.

### P0: 기본 agent 조회에서 관계가 모두 제외된다

114,088개 관계와 8,448개 매핑이 모두 draft다. 기본 rank({'nova:fever':'present'})는 후보 0개다. 이것은 의도된 신뢰 정책이지만, 연결 팀이 모르고 쓰면 KB가 작동하지 않는 것으로 보인다.

권장: 대회용으로 사용할 검수 범위를 정하고 별도 검수판을 만든다. 개발 실험에서 draft 포함을 명시할 수 있으나 모든 관계를 일괄 reviewed로 바꾸지 않는다.

### P1: 순위는 질병 후보 정렬이지 진단 추론이 아니다

rank는 양성 일치 수 내림차순, 음성 충돌 수 오름차순, 질환 ID 오름차순이다. 양성 일치가 없는 질환은 제외된다. 모든 증상의 가중치가 같으며 환자 나이/성별/기간/약물/위험 인자 및 관계의 조건을 반영하지 않는다. 음성 충돌은 양성 일치 수가 같은 경우에만 순서를 바꾼다.

발열 하나로 draft 포함 조회 시 215개 후보가 나왔다. 상위 결과는 Acute Promyelocytic Leukemia, PML-RARA; Acrodermatitis Enteropathica; Actinomycosis 등이었고 모두 일치 1개다. 상위 표시는 ID 동률 정렬의 결과이며 임상 우선순위가 아니다. 기본 상위 30개 제한은 이러한 순서를 잘라 반환한다.

권장: 질병별 증상 수/자료 밀도 편향, 소견의 구별력, 질환 간 구분 정보와 반박 근거를 고려한다. 빈도 문자열만으로 사전확률이나 진단 확률을 만들지 않는다. 빈도가 없는 phenotype 관계도 26,016개다.

### P1: 한국어 자연어 정규화와 HPO 계층 확장이 없다

search는 ID/명칭/별칭/매핑의 부분 문자열 비교다. Finding 검색에서 발열은 1개, fever는 15개, 열이 나요와 배가 아파요와 기침은 0개였다. 현재 데이터에서 한글을 가진 소견 이름은 46/5,612개다.

read_obo는 부모를 읽지만 importer는 이를 그래프에 저장하지 않는다. rank는 동일 소견 ID만 비교하며 HPO 상위·하위 소견 매칭을 하지 않는다.

권장: 대회 주호소 범위의 한국어 표현 사전, 부정·기간·강도·과거력 구분, 불확실한 개념 매핑 후보를 구현한다. 계층 확장은 부모/자식의 방향과 구별력 손실을 고려해 적용한다.

### P1: 다음 문진·진찰·계획을 제공하는 지식이 없다

기전/표현형 연관은 많지만 질문 템플릿, 진찰 동작, 후보 구분 기준, 위험 신호 대응, 검사·치료·추적 계획을 위한 전용 관계가 없다. Test/Exposure는 타입만 있고 실제 개념은 없다. rank 결과에는 매칭된 관계만 들어가므로 후보를 구분할 미확인 소견은 별도 조회가 필요하다.

권장: 후보별로 아직 확인하지 않은 구별 소견과 그 확인 방법, 근거 및 적용 조건을 짧게 반환하는 에이전트용 인터페이스를 추가한다. 누락된 소견을 음성으로 간주하지 않는다.

### P1: 대회 진단 범위의 커버리지 확인이 필요하다

예시 진단인 수면제 의존과 연결할 후보를 Sedative/Hypnotic 문자열로 검색했을 때 Disease 결과는 0개다. use disorder 검색에는 Alcohol Use Disorder와 Opioid Use Disorder만 나왔다. 이것만으로 모든 의미상 관련 개념의 부재를 증명할 수는 없지만, 대회에서 요구하는 진단 명칭을 찾는 경로가 부족함을 보여준다.

권장: 공개 증례와 허용된 개발 자료의 주호소/질환군으로 커버리지 표를 만들고 검색·동의어·관련 소견을 검수한다. 전체 희귀질환 수 확대보다 대회 범위의 구분 정보를 우선한다.

### P2: 변환 과정은 무손실이 아니다

importer는 context를 1,200자, description을 1,600자, SUPPORT 참조를 최대 8개로 제한한다. 실제 1,200자 context는 107개, 1,600자 description은 690개다. 제한 길이와 일치하는 기록에 대해서는 원본 대조로 실제 잘림을 확인해야 한다. upstream의 다른 필드와 SUPPORT 이외의 근거를 모두 구조화해 가져오는 구현은 아니다. 원본 URL/해시는 있지만 원본 전체 YAML은 이 저장소에 포함되어 있지 않다.

동일 subject/predicate/object 중복은 223개 초과 레코드가 있다. rank의 일치 수는 set으로 계산하므로 중복이 점수를 직접 올리지는 않지만 근거를 길게 만들 수 있다.

RDF exporter에는 references/frequency_label/description/identifier_verified/개별 source sha256 등이 전부 반영되지 않는다. 따라서 JSON을 RDF로 대체하면 정보 보존 범위가 줄어든다. 영어 fallback label_ko도 RDF에서는 @ko로 출력된다.

권장: 원본 보존층과 에이전트 요약층을 나누고, 자른 정보와 생략 필드를 기록한다. 단순 중복 삭제 전에 서로 다른 출처나 조건인지 확인한다.

### P2: 배포 경로와 응답 길이

현재 파일 구조는 로컬 Python 직접 import에 적합하지만 pip 패키지에는 데이터가 포함되지 않는다. 서버 실행은 외부 접속이 제한되므로 로컬 웹 서버 주소를 외부 KB로 사용하지 말고 필요한 데이터와 코드를 ZIP에 포함한다. 최신 gzip 한 판은 약 14.9 MB이지만 여러 릴리스와 참고 PPT 전체를 함께 제출할 필요는 없다. 50MB 규칙은 개회식 자료 기준이며 최종 제출 규칙도 확인해야 한다.

rank의 발열 상위 30개 전체 응답은 기본 json.dumps(ensure_ascii=True) 직렬화 기준 68,471 bytes였다. 측정 실행에서 조회는 약 0.037초였지만 이는 현재 컴퓨터의 단일 실행 측정이며 대회 성능 보장은 아니다. 긴 그래프 전체를 매 턴 모델에 넣는 대신 근거와 구분 정보만 제한해서 반환하는 것이 적합하다.

## 권장 작업 순서

1. EXCLUDED 및 적용 맥락을 정리하고 관계 polarity를 구현한다.
2. 대회용 검수 데이터 범위와 draft 정책을 에이전트 팀과 합의한다.
3. 주호소별 한국어 표현 정규화와 질환 커버리지를 확보한다.
4. 후보 구분 소견·다음 질문·진찰 동작·위험 신호를 반환하는 작은 API를 만든다.
5. 동일 에이전트의 KB 없음/현재 KB/개선 KB를 비교한다. 진단 정확도, 정보수집, 질문·진찰 수, 비용, 기록의 관찰 사실과 근거를 평가한다. 작은 공개 샘플의 결과만으로 일반화하지 않는다.

DB 교체, 웹 UI 추가 개선, 전체 기전 확장보다 위 작업이 대회 에이전트에 직접 연결되는 우선순위다.
