# 출처·라이선스·검수 기록

대회 규정상 외부 데이터·모델·도구는 **연구 출판이 가능한 라이선스만**, **출처를 밝히고** 써야 합니다.
새 자료를 쓰기 전에 이 문서에 먼저 적습니다.

## 1. 현재 KB에 들어 있는 것

| 구분 | 내용 | 출처 | 라이선스 |
|---|---|---|---|
| 스키마·코드 | `meddb/*.py` | 팀 자체 작성 | 팀 소유 |
| 온톨로지 내용 | `meddb/data/*.json` 전부 | 팀 자체 작성 (아래 2절) | 팀 소유 |
| KCD 코드 | `diseases.json`의 `kcd` | 한국표준질병·사인분류 코드 체계를 기억에 의존해 기입 | 검증 필요 (아래 4절) |

외부 자료의 문장·표·데이터 파일은 들어 있지 않습니다.

## 2. 내용 작성 방법

- 2026-10-10, AI 코딩 도구(Claude, 모델 설정 `claude-opus-5-5`)로 초안 작성. 대회 규정상 AI 코딩 도구 사용은 허용됩니다.
- 일반 임상 지식(주호소별 감별진단, 위험 징후, 초기 검사·처치)을 팀 스키마에 맞춰 새로 정리했습니다.
- **임상 검수 전입니다.** `common.json`의 `meta.review`를 검수 후 갱신합니다.

## 3. 구조를 참고한 공개 저장소

아래 두 저장소는 설계를 정할 때 읽었습니다. 코드와 데이터 파일은 가져오지 않았습니다.

| 저장소 | 참고한 점 | 비고 |
|---|---|---|
| [yunseul6028/Doctor-Agent](https://github.com/yunseul6028/Doctor-Agent) | KB를 CPU·표준 라이브러리만으로 조회하는 구성, 출처 장부를 두는 방식 | 2026-10-10 기준 LICENSE 파일 없음 |
| [BBI-BBO/medagent-kb](https://github.com/BBI-BBO/medagent-kb) | 질환–소견–검사를 관계로 두는 구성, 판 고정 | 2026-10-10 기준 LICENSE 파일 없음. 일부 연결은 AI 생성·검수 전이라고 README에 명시 |

두 저장소는 공개되어 있지만 라이선스가 명시되어 있지 않습니다. 코드나 가공 데이터를 직접 넣으려면 저장소 주인에게 이용 조건을 확인한 뒤 이 표에 적습니다.

## 4. 앞으로 넣을 후보 자료

원본 배포처에서 직접 받아 빌드 단계에서 넣습니다. 받기 전에 라이선스를 다시 확인합니다.

| 자료 | 쓰임 | 라이선스 (재확인 필요) | 배포처 |
|---|---|---|---|
| 건강보험심사평가원 상병마스터 | KCD 코드·한글 병명 검증 | 공공누리 제1유형 (출처표시) | 공공데이터포털 |
| 건강보험심사평가원 주부상병 성·연령군별 진료 통계 | `freq`를 성·연령별 사전확률로 교체 | 공공누리 제1유형 | 공공데이터포털 |
| Human Disease Ontology | 영문 병명·동의어 | CC0 1.0 | DiseaseOntology GitHub |
| Orphadata | 희귀질환 표현형·빈도 | CC BY 4.0 | orphadata.com |
| DDXPlus | 질환–증상 연결 보강 | CC BY 4.0 | figshare |

상병마스터를 받은 뒤 코드 검증:

```bash
python -m meddb kcd-check <상병마스터 파일>
```

## 5. 검수 체크리스트

- [ ] 주호소별 감별진단 범위와 red flag 지정

- [ ] `rule_out` 소견이 실제 배제에 충분한지
- [ ] 계획(검사·치료·처치 결정)과 금기(`unsafe`)
- [ ] 설명 문장(`explain`)의 표현
- [ ] KCD 코드 (`kcd-check`)
- [ ] 활력징후 기준값
