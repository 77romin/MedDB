# B1 관찰 연결 확장 (B1O1)

병합된 main의 B1을 기반으로 한 별도 실험 경로다. B1의29턴 문진 예산·DONE·질문 선택·기록·마무리·모델 설정을 유지하며 관찰 해석만 선택적으로 바꾼다. Q1/RAG/추가 Doctor 추출 호출은 결합하지 않는다.

- 기본: examples/agent_b1.py (기존 reader_g)
- 확장: examples/agent_b1_observed.py + reader_b1_observed.py
- 공통 연결: agent_b1.consult의 reader 인자. 생략하면 원래 처리 방식이다.

표준 질문에 정확히 일치하는 개념이 하나면 그 개념에 짧은 예·아니요를 연결한다. 그 외에는 질문 개념이 하나이고 응답이 엄격한 단순 예·아니요인 경우만 연결한다. 복합 질문·부분 부정·불확실·가족/과거 표현을 환자 현재 양음성으로 확대하지 않는다. 실제 질문·응답·턴·연결 결과를 메모리에 보존하고 전체 대화는 기존 SOAP 생성에 남긴다. 기존 소견과 명확한 새 응답이 충돌하면 Tracker의 미확인/상충 처리를 따른다.

이는 정규식 기반 보수적 처리이며 의료 의미 전체를 해석하는 엔진이 아니다. 가족과 현재 증상이 섞인 답, 조건부·주체·과거 표현의 변형은 처리 누락/오탐 가능성이 있다. 초기 진술 해석·진찰 해석은 기존 B1과 같다. 의미 반복 차단·임상 종료 판단·마무리 완전성을 해결했다고 주장하지 않는다.

패키지 생성:

```sh
python tools/make_b1_observed_submission.py --starter /path/to/starter/run.py --out dist/submission_B1O1.zip
```

기존 B1 패키저를 그대로 호출한 다음 새 모듈2개와 진입점만 추가한다. 기본 B1 빌드는 변경하지 않는다. 개발 API 비교와 공식 점수는 별개이며 최신 개발 결과는 nova_harness/reports/development_057.md에 기록한다.

향후 충돌을 줄이기 위해 확장을 고유 파일에 두었다. 최신 main이 작업 브랜치의 조상이지만, 이후 같은 공통 연결부를 양쪽에서 수정하면 충돌 가능성은 남는다. main 재반영과 테스트 후 PR을 병합해야 한다.
