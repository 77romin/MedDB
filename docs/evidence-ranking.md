# 증상·조건 기반 후보 조회

`진료` 화면에서 소견을 있음/없음/미확인으로 입력하고 질환 범주를 선택하면 후보를 정렬한다. 나이·성별도 입력할 수 있지만 검수된 해당 질환의 적용 조건이 있을 때만 필터링한다. 현재 배포 데이터에는 이 조건이 없으므로 반영되지 않았다는 안내가 나온다.

```python
from meddb import KB
kb = KB(version='meddb-2026.10.10.4')
result = kb.rank(
    {'nova:vomiting': 'present', 'nova:fever': 'absent'},
    include_draft=True,
    patient={'age': 35, 'sex': 'female'},
    limit=10,
)
```

HTTP `POST /api/rank`와 `KB.call('rank', args)`도 같은 인자를 받는다. `category`는 질환 개념에 저장된 category 문자열을 정확히 지정한다. 의료적 자동 필터가 아니라 사용자가 선택하는 자료 범위 필터다.

## 점수의 의미

- 소견별 가중치는 `1 + log((1 + 전체 질환 수)/(1 + 해당 양성 소견이 연결된 질환 수))`다. 이는 데이터 내 구별력이며 의학적 유병률이 아니다.
- 양성 연관 소견이 있으면 가중치를 더한다. 없으면 가중치의 0.25배를 뺀다. 선택적 소견의 부재가 확정 배제가 되지 않도록 둔 실험적 계수다.
- `EXCLUDED` 소견이 있으면 가중치를 빼고, 없으면 더한다. 이는 현재 원본에 기록된 부정 의미를 반영하는 처리이며 적용 맥락의 임상 검수를 대체하지 않는다.
- 동일 질환·소견에 양성/부정 관계가 함께 있으면 해당 소견을 점수에서 제외하고 `uncertain`으로 반환한다. 원본 관계는 보존한다.
- 알려진 입력 소견 전체의 가중치 합으로 점수를 나눈다. 진단 확률·정확도·신뢰도 퍼센트로 해석하지 않는다. 음수 점수도 가능하다.
- 미확인은 반영하지 않는다. 지지 소견이 하나 이상 있는 후보만 반환한다. 같은 점수·지지 수·반박 수는 같은 rank를 갖는다.
- `next_findings`는 해당 질환에 연관된 미확인 소견 중 데이터 내 구별력이 높은 최대 5개다. 후보 간 최적 질문이나 기대 정보량을 계산하는 정책은 아니다.

현재 정책은 질병의 사전확률, 증상 간 상관, 시간 변화와 환자군별 빈도를 모델링하지 않는다. 실제 진단 확률을 표시하려면 목표 환자군의 데이터, 평가 증례, 확률 보정 및 검증이 필요하다. 단순 softmax로 점수를 100% 합계로 만들지 않는다.

## 질환 적용 조건

Disease 개념에 선택적으로 아래 구조를 추가할 수 있다. 숫자는 구조 예시이며 실제 질환의 의료 규칙이 아니다. 해당 필드는 현재 JSON 조회용이며 RDF export에 포함되지 않는다.

```json
{
  "clinical_constraints": {
    "min_age": 18,
    "max_age": 65,
    "sex": "female",
    "source_id": "기존_sources의_ID",
    "locator": "적용 조건의 원문 위치",
    "review_status": "draft",
    "reviewer": null
  }
}
```

`reviewed`, 검수자, 출처, 원문 위치가 모두 있어야 후보 제외에 사용한다. 단순히 흔한 연령·성별은 강제 제외 조건으로 등록하지 않는다. 입력하지 않은 조건은 필터링하지 않는다. 제외된 후보는 `filtered`에 근거와 함께 반환한다.

현재 의료 데이터와 기존 릴리스는 변경하지 않았다. 알고리즘 변경은 `score_method: phenotype-idf-v1`로 표시되므로 데이터 해시만으로 순위 계산 버전을 식별하지 않는다.
