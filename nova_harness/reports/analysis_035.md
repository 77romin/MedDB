## 코드로 확인된 설명과 확인되지 않은 가설

`nova_agent/e2_rag.py`는 `H.write_record()`만 감싼다. 검색은 문진·진찰 수집 뒤에 실행되고, 이후 note를 받아 종료 설명을 생성한다. 검색 결과가 질문 선택 프롬프트로 전달되지는 않는다. 정보수집 하락을 검색이 나쁜 질문을 고르게 한 결과로 단정하는 것은 시간 순서와 맞지 않는다. 모델·환자 응답의 변동, 수집한 사실의 최종 기록 반영 차이, 샘플 채점 변동을 구분할 자료가 필요하다.

의사소통 +1.05는 계획·설명 근거 개선과 양립하지만 실제 설명과 채점 이유가 없어 인과 확인은 아니다. C01/C10의 늘어난 턴이 어느 질문·설명에 쓰였는지도 집계 화면만으로 알 수 없다. R1/R2의 live 원문 로그나 서버 최종 SOAP는 이번에 제공되지 않았다. 과거 저장 응답 재생을 최신 제출 대화로 대신하지 않는다.

현재 검색어는 관찰 기반 상위 감별명뿐이고 환자 연령·약물·금기·치료 단계를 검색 적합성 입력으로 사용하지 않는다. 제목·본문의 관련 용어 일치는 임상 적용 적합성을 보장하지 않는다. R2 점검에서도 오래된 지침이나 특정 소아·유전질환 문서가 남았다. 근거 선별 역할은 이 코드 격차를 직접 다룰 수 있다.

## 권고

R3 개발은 타당한 실험이지만 점수 상승이 보장되는 다음 단계는 아니다. R2를 성능 채택본으로 누적하지 않고 검색 실험 기반으로 보존한다. 이전의 단계 계획을 세분화해 처음에는 R3a 근거 적합성 선별만 비교할 것을 권한다.

1. **R3a 근거 선별:** R2의 인덱스·검색어·상위 2개 후보·기존 기록 생성 프롬프트를 고정한다. 실제 시작 정보·관찰과 검색 발췌를 별도 필드로 주어 적용 대상, 시점, 치료 조건, 예외·금기, 불확실성을 확인한다. 적합한 근거 ID만 기록 생성에 전달하고 모두 부적합/불확실하면 지침 없이 기존 기록 경로로 복귀한다. 이 분류는 모델 판단이며 의학적 정확성을 보증하지 않는다.
2. **검증 출력:** usable/rejected/uncertain, 사유와 출처 ID를 구조화한다. 원문에 없는 환자 속성 생성, 미확인=음성, 후보 밖 출처, 환자 근거와 지침 근거 혼합을 검증한다. 적합한 후보가 처음부터 없으면 선별 모델도 올바른 근거를 만들 수 없다.
3. **비용·운영:** 우선 기록 생성 시 1회 선별 호출을 실험한다. 반복 기록 시 관찰이 달라졌다면 이전 선별을 무조건 재사용하지 않는다. 총 호출·시간 예산과 제한된 재검토 조건을 두고 실패·예산 부족은 지침 미사용으로 복귀한다. 추가 호출은 실제 효율 점수에 영향을 줄 수 있다.
4. **후속 역할:** R3a가 효과를 보이면 R3b 검색 요청 작성 프롬프트를 추가하고, 마지막에 R3c 근거 기반 생성 역할을 명시적으로 분리한다. 서로 다른 세 역할을 매 환자 턴마다 호출하지 않는다. LangGraph는 이 결과 뒤에 검토한다.

환자 질문의 질과 안전 10점을 직접 개선하려면 별도로 실제 문진·진찰·안전 안내·환자 질문 답변을 분석해야 한다. 기록 시점 RAG 선별만으로 정보수집 25점이나 안전 15점 회복을 기대한다고 보고하지 않는다. 같은 시점 원본 E2 대조군과 R2 반복은 변동을 이해하는 데 유용하며, 최신 로그가 있으면 회귀 분석에 우선 사용한다.

이번 회차는 사용자 요청에 따른 검토·문서화다. R3 런타임 코드·유료 API 실행·새 ZIP은 만들지 않았다. 다음 구현은 이 수정된 R3a 범위를 사용자가 진행하도록 지시할 때 착수한다.
