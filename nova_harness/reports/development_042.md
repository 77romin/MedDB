# 42차 개발: 안전 의무 원장과 실제 수행 기록 분리(S2)

2026-10-22. D078 설계에 대한 사용자 구현·커밋·푸시 승인을 받았다. S2는 R3a+S1 마무리에 명시적으로 추가하는 실험 후보이며 기본 실행과 동결 R3a/S1 ZIP을 교체하지 않는다. 공식 점수는 미측정이다.

## 구현

`nova_agent/safety_obligations.py`는 계획 버전, 원문 필드/인용, 관찰 해시, 조건, 행동, 시점, 부정 원문, 현재/조건부 적용, 우선순위, 제안 문장과 전달 이벤트를 관리한다. 조건·행동·시점은 원문 부분 문자열이어야 하고, 메시지에도 보존돼야 한다. 새 수치·원문에 없는 인용·일부 부정/즉시성 누락·30자 초과·지정 종결형이 없는 축약형을 거절한다. 단순 문자열 검사가 임상 의미 전체를 증명하지는 않는다.

계획은 생성/성공 전송과 분리된다. 전체 문장 묶음의 성공 발화가 있어야 `sent_success`가 되며, 일반 경고나 계획 생성만으로 전달됐다고 보지 않는다. 발화 요청 ID를 타임라인에 보존한다. 환자의 자발적 약속이나 '네'를 의사의 교육 또는 이해 확인으로 바꾸지 않는다. 모든 발화 원문과 환자 답변은 기존 비공개 타임라인에 남는다.

`nova_agent/e2_safety_obligations.py`는 S1의 마무리를 유지하면서 추가 Doctor 호출 1회(2048토큰, low, 남은 시간 120초 이상)로 의무 후보를 작성한다. 기존 검색·문진·진단·종료 정책은 바꾸지 않는다. 추가 의무의 critical 그룹을 우선 배정하고 기존 후속 질문/답변/teachback용 3턴을 예약한다. 문장 그룹이 예산에 들어가지 않으면 일부만 전송하지 않고 미해결로 남긴다. 남은 기본 마무리도 통째로 들어갈 때만 추가한다. 따라서 설명 순서/내용과 추가 호출 비용은 달라진다.

최종 DIAGNOSE 경로는 S1의 완료형 단어 치환을 거치지 않는다. P 원문은 명시적인 '계획 원안 인용(수행 여부 미확인)'으로 보존하고, 실제 수행 구역은 성공 SAY의 발화 index·요청 ID·문구로 결정적으로 만든다. 원문에 남아 있는 '교육 완료'도 이 인용의 주장이지 수행 확인으로 취급하지 않는다. S/O/A와 진단은 바꾸지 않는다. 현재는 계획 원문을 그대로 보존하므로 기록 길이 최적화는 후속 과제다.

계획 변경 시 이전 버전·변경 필드·관찰 해시를 보존하고 동일 인용이 살아 있는 의무만 이어받는다. 이전 버전의 발화로 변경 후 설명을 완료 처리하지 않는다. 변경의 임상 이유는 모델 기록에서 별도 검토해야 하며 코드가 임의 이유를 만들어 쓰지 않는다. 최종 변경 이후 환자에게 정정 설명을 보내는 새 대화 루프는 아직 없다. 대신 최종 SOAP와 감사에 재설명 확인 필요를 명시한다.

## 검증과 한계

- 단위·전체 회귀: 결과는 최종 게시 항목에 기록한다. 전송 실패, 조건/부정/수치/시점 손실, 일반 경고의 잘못된 완료 처리, 부분 그룹, 턴 경계, 계획 변경, 최종 기록 불변성, 요청 ID 전달을 검사한다.
- 저장된 실제 20세션 재생: 입력·S/O/A 불변, P 원문 인용 보존, 성공 발화 반영을 확인했다. `obligations_replay_042.json`은 집계만 담는다. 새 환자 응답이나 공식 점수 실험이 아니다.
- 의무 추출은 모델의 부분집합이다. 누락 의무를 모두 찾았다고 주장하지 않도록 `coverage_verified=false`와 미검증 계획 필드를 항상 남긴다. 미해결 ID가 0이어도 전체 안전 의무가 완료됐다는 뜻이 아니다.
- 정확한 원문 anchor 요구는 바꿔 말한 좋은 안내도 거절할 수 있다. 반대로 일치하는 단어가 있어도 임상적으로 부적절한 안내를 완전히 걸러내지는 못한다. 적용 판단·우선순위·진료 계획 자체의 임상 적절성은 별도 검증 대상이다.
- 현재 구현은 미래 계획/확인된 전달의 출처를 분리한다. 실제 환자 이해 여부의 자동 판정, 의미적으로 다른 중복 안내 제거, 모든 미해결 의무의 자동 복구까지 완료한 것으로 표현하지 않는다.

## 실행과 게시

명시적 후보 실행: `.venv-rag/bin/python tools/safety_session.py --case <공개 UUID> --mode R3a_obligations`.

원격 `codex/nova-harness-rebuild`의 `nova_harness/`로 소스·테스트·공개 집계·문서만 동기화한다. 원문 로그·키·인덱스·ZIP은 게시하지 않는다. 공식 제출·PR 병합은 수행하지 않는다. S2 제출 ZIP은 이번 요청 범위에서 만들지 않는다.

## 실제 API 결과와 마지막 수정의 범위

첫 C10 실행(`090525_696166`)은 49턴·311.418초, Doctor 29/29회, API 오류·출력 절단 0건으로 정상 종료했다. 결정적 수행 구역을 갖춘 최종 SOAP를 실제 DIAGNOSE로 전달했다. 그러나 모델이 원문의 '하도록 안내/설명'까지 action에 넣거나 메시지에서 해당 조건/행동을 바꿔 써 의무 검증 전체가 거절됐다. 생성 의무 0·확인 전달 0은 전체 안내 완료가 아니라 추출 실패다. 기존 S1 마무리로 복귀한 것이며 안전 전달 개선의 성공으로 계산하지 않는다.

이후 action을 기록 행위가 아닌 최소 핵심 행동 구절로 인용하고 실제 메시지의 정확한 보존을 스스로 확인하도록 프롬프트를 보강했다. 동일한 저장 계획을 사용한 새 Doctor-only 호출(`091217_obligation_planning_probe`)에서 원문·조건·행동·형식 검사를 통과한 의무 1개를 확인했다. 이 호출은 환자 세션을 만들거나 SAY를 보내지 않았다. 제안을 실제 전달로 기록하지 않는다.

최종 기록에는 '추출 의무 중 미확인 0건'도 전체 안내 완료가 아니며 추출 누락/임상 적절성이 미검증이라는 문장을 추가했다. 이 마지막 문구 수정과 프롬프트 보강 후 전체 환자 API를 새로 완료했다고 표현하지 않는다. 소스 해시별 전체 실행과 마지막 Doctor-only/저장 재생 범위는 `obligations_live_042.json`에서 분리한다.

최종 전체 테스트는 236개 통과했다. S2는 구조 개선 실험 후보이며 공식 안전 점수 회복·78점 달성·임상적 완전성은 미입증이다. 후속 검증에서는 전체 환자 세션에서 실제로 채택/전달되는 의무 수와 누락 내용을 확인하고, 계획 변경 후 정정 발화 및 의미적 중복 제거를 별도로 개선해야 한다.

## 두 번째 전체 실행과 최종 게시

C10 두 번째 실행(`090806_610820`)은 49턴·332.035초, Doctor 28/28회, API 오류·출력 절단 0건으로 정상 종료했다. 이 실행에서는 의무 **3개가 검증을 통과하고 세 묶음 모두 실제 성공 SAY와 연결**됐다. 계획 버전은 1개였고 해당 추출 의무 중 미전달은 0개였다. 전체 계획의 완전성·임상 적절성은 여전히 `coverage_verified=false`다. 첫 실행의 추출 실패와 두 번째의 3개 전달을 함께 보고하며 단일 실행 성공을 일반화하지 않는다.

두 번째 전체 실행의 런타임은 `694dd67`에 게시된 세 모듈과 일치한다. 이후 `c37a0e9`의 변경은 최종 교육 구역에 '추출 0건≠전체 완료'를 명시한 문구와 추출 프롬프트 보강이다. 최종 프롬프트는 별도 Doctor-only 1회로, 최종 기록 문구는 저장 세션 재생으로 검증했다. 최종 소스로 새로운 전체 환자 세션을 완료했다고 주장하지 않는다.

저장 기록 재생은 두 새 세션을 포함해 **22개**로 갱신했다. 최종 테스트 **236개 통과**. 공식 점수·C01/C03 전체 회귀·Docker 검증은 이번 S2에 대해 수행하지 않았다. 새 전체 세션에서 채택된 의무의 성공 전송은 확인했지만 S2를 공식 제출 권장본으로 채택하지 않는다.

기능 커밋: `78761d8` 안전 의무/실제 발화 분리, `694dd67` S2 전달·SOAP 연동, `c37a0e9` 부분 범위 명시·생성 프롬프트 보강. 같은 브랜치/PR #5에 공개 집계와 문서를 함께 반영한다.
