# 개발 15차 — E2 최종 질문 직접 답변 단일 실험

2026-10-19. 원본 E2 77.714점을 기준으로, 안전·진단·효율 경로를 바꾸지 않는 첫 단일 변경을 구현했다.

## 가설

E2의 의사소통은 7.72/15점이다. 종료 단계에서 환자가 질문하면 E2는 이미 한 번 답변 모델을 호출하지만, 기존 프롬프트는 쉬운 한 문장과 기록 범위만 요구한다. 질문의 핵심에 직접 답하라는 우선순위는 없다.

기존 `ANSWER_SYSTEM` 마지막에 다음 한 줄만 추가했다.

> 환자 질문의 핵심에 먼저 직접 답하세요.

이 프롬프트는 환자가 마지막에 명시적 질문을 했을 때만 사용된다. E2의 문진 선택, 종료 설명 JSON, 안전 문장, 진료 기록, 모델 호출 수, 수집 31턴과 마무리 6턴은 바꾸지 않는다.

## 검증

- 설치 중 `ANSWER_SYSTEM`만 바뀌고 `CLOSING_SYSTEM`과 `_closing_sentences` 함수 객체가 동일함을 확인했다.

## 개발 API 상태

C01 한 건을 먼저 실행했지만 진료 시작 전 세션 생성에서 `API_UNAVAILABLE`가 6회 발생했다. Doctor 호출 0회, 서버 턴 0회, 제출 시도 0회다. 코드 또는 임상 성능 실패로 해석하지 않는다.

API가 복구되면 C01 후보를 먼저 완료하고 원본 E2의 같은 시점 실행과 비교한다. 마지막 환자 질문이 실제로 발생했고 직접 답변이 전송됐는지 확인한 뒤 C03/C10으로 확장한다. 안전·추론·효율 회귀가 있거나 질문이 없어 변경이 작동하지 않았다면 공식 후보로 승격하지 않는다.

현재 공식 최고는 원본 E2의 77.714점이고 1차 목표 78점은 미달성이다. 이 ZIP은 개발 API 검증 전 구조 후보이며 현재 제출 권장본이 아니다.

## 로그 기반 문구 보강과 제출 권장 결정

보유한 원본 E2 C01 로그를 다시 확인했다. 환자는 `수면제 말고 다른 방법도 있나요?`라고 명시적으로 질문했고, 당시 기록의 치료 계획에는 CBT-I와 수면위생 중재가 있었다. 하지만 실제 답변은 `검사 결과를 보고 자세히 알려 드릴게요.`여서 기록 안의 답을 전달하지 못했다. 개발 검토에서도 이를 의사소통 감점의 구체적 원인으로 지적했다.

이에 단일 추가 문구를 `기록에 답이 있으면 질문에 먼저 직접 답하고 검사 후로 미루지 마세요.`로 확정했다. 기록 범위 제한, 한 문장·30자 제한, 원본 기본 답변, 질문 감지와 호출 횟수는 그대로다. 전체 테스트는 153개가 통과했다.

기준 ZIP과의 내용 비교 결과, 기존 47개 파일은 그대로였고 변경은 오버레이 설치를 위한 `run.py`와 새 모듈 2개뿐이다. 원본 종료 설명·안전·추론·수집 코드는 바뀌지 않았다.
