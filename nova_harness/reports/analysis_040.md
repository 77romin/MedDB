# 40차 분석: R3b·R4 샘플 점수 하락

2026-10-22. 출처는 사용자가 제공한 두 서버 샘플 검증 캡처, R3a의 기존 캡처 기록(D073), 동결 ZIP 및 현재 코드·로컬 개발 로그다. 서버 실행의 대화·진찰·최종 SOAP·항목별 감점 사유는 확보하지 못했다. 개발 로그를 서버 감점의 직접 증거로 대체하지 않는다. 이번에는 분석·기록만 수행하며 런타임 수정·유료 API·새 ZIP·공식 업로드는 실행하지 않는다.

## 코드·로그가 뒷받침하는 실패 경로와 한계

1. **검색어 생성이 근거 구성을 바꾼다.** `nova_agent/rag_query.py`는 실제 관찰에 근거한 임상 질문 하나를 골라 기존 질환명 검색을 대체한다. 인용·ID 검증은 환자 출처를 확인할 뿐, 그 한 질문이 필요한 모든 안전 조건을 포괄하는지는 보장하지 않는다. R3a 선별 코드를 그대로 유지해도 들어오는 후보가 바뀌면 최종 계획은 달라질 수 있다. 이는 R3b 변경의 직접 영향 경로지만 서버 안전 감점 원인으로 확정하지 않는다.
2. **설명 후 기록 재작성 시 근거가 달라진다.** 로컬 R4 C01은 첫 기록에 적합 지침을 사용했지만 새 관찰 후 재작성에서는 요청 상한 때문에 기존 검색으로 복귀했고, 두 번째 후보는 모두 제외됐다. 관찰이 추가됐을 때 재검증하는 것은 필요하지만 기존에 확보한 안전 근거가 새 기록에서도 충실히 보존됐는지 확인하는 검사가 없다. 서버에서 동일하게 발생했는지는 모른다.
3. **안전 계획과 실제 전달 사이의 검사가 없다.** `vendor/meddb/examples/hybrid_comm.py`는 기록을 짧게 잘라 마무리 생성에 넣고, 각 설명을 30자 이내로 제한한다. 실패·길이 위반 시 일반적인 기본 문장으로 대체한다. SOAP에 구체적인 계획이 있어도 해당 조건·주의가 실제 SAY로 전달됐는지 의미 단위로 검사하지 않는다. 로컬 C03의 마무리 생성 빈 응답·절단은 이 경로가 실제 작동한 근거다. 이번 서버의 감점 증거는 아니다.
4. **최종 SOAP와 이미 한 설명이 불일치할 수 있다.** 같은 파일은 마무리 대화에서 관찰이 바뀌면 기록을 다시 생성하고 이전 교육 필드를 이어 붙인다. 새 계획이 이전 설명과 달라졌는지, 추가 설명이 필요한지 검증하지 않는다. R3c의 조건부 표현·내용 순서 변경이 이 경로에 영향을 줄 가능성은 있으나 R3c 단독 서버 점수가 없어 효과를 분리할 수 없다.
5. **검증 기준이 부족했다.** 테스트·저장 응답 재생·SOAP 형식·정상 종료·허용 출처 ID는 연결과 계약을 검증했다. 임상적으로 필요한 안전 행동·금지 행동·실제 설명의 보존을 검사하지 않았다. 따라서 기존 검증 통과를 안전 개선의 근거로 사용해서는 안 된다.

R4는 R3b에 R3c 생성 지시와 LangGraph를 함께 추가했다. 재생 6쌍에서 R3c/R4 요청·행동 동일성을 확인했으므로 LangGraph 자체가 계획 내용을 개선한다는 근거는 없으며, 이번 하락을 LangGraph 자체의 원인으로 단정할 수도 없다. 추가 모델 호출·시점·응답 변동, 생성 지시 변경, 다른 검색 근거를 분리해야 한다. R3a 역시 단일 실행이므로 안전 15의 반복 안정성이 입증된 것은 아니다.

## 다음 실험 권고

- R3b/R4는 개선본 채택·제출 권장을 철회한다. 현재 비교·복구 기준은 동결 R3a로 되돌린다. 기존 코드·ZIP은 삭제하지 않는다.
- 우선 서버의 세 증례 대화·진찰·최종 SOAP와 감점 사유를 확보할 수 있는 범위에서 비교한다. 어느 증례가 안전 감점을 받았는지 총점만으로 추정하지 않는다.
- 개발 실험은 같은 기록 직전 관찰을 고정해 R3a와 R3b를 비교한다. 검색 요청·후보·선별 결과·기록·실제 설명을 모두 저장한다. 별도로 R3b/R3c만 비교해 생성 지시의 영향을 분리한다. 저장 응답 재생은 품질 측정으로 쓰지 않는다.
- 다음 구현은 프레임워크 확장이 아니라 안전 행동의 근거·조건·계획·실제 전달을 잇는 검사로 한정한다. 새 관찰이 기존 안전 근거를 무효화하는지 확인하고, 최신 SOAP와 이미 전달한 설명이 다르면 필요한 추가 설명을 식별한다. 근거가 없으면 일괄 경고나 임의 처방을 만들지 않는다.
- 안전 검사 통과와 실제 전달을 확인한 단일 변경 후보만 새 ZIP으로 만든다. 여유가 있으면 R3a 자체도 반복해 변동 폭을 확인한다. 이번 결과는 리더보드 목표 달성이 아니다.

구현은 아직 하지 않았다. 이전 통합본을 최종 제출 대상으로 안내한 것은 실험 후보 전달이었으나, 사용자에게 중요한 안전 보존을 확인하지 못한 상태였다. 이후 제출 권장 판단에는 정상 종료와 별개로 안전 계획·실제 전달 검증을 포함한다.
