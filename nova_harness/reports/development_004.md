# 개발 4차 보고 — PR과 실제 대화·기록 개선

기준일: 2026-10-18 KST. Doctor `openai/gpt-6-luna`. 사용자 요청으로 목표 달성 전 [PR #5](https://github.com/SSAFY16-S11-NOVA2026/MedDB/pull/5)를 생성했다. 공식 목표 ≥78 → ≥85 → ≥90은 그대로이며, PR 생성·테스트 통과를 목표 달성으로 보지 않는다.

## 문제와 구현

3차 로그에서는 설명 5개 태그를 전송해도 환자의 구체적인 질문에 답하지 않고 같은 의뢰 안내를 반복했다. 긴 설명에서 한 문장만 고르면 뒤의 중요한 조건이 빠질 수 있었다. 모델이 적은 교육 계획과 실제 전달한 설명도 한 필드에서 섞였다.

v0.4.0의 새 하네스에서는 다음과 같이 바꿨다.

- 판단·계획·추적·안전·걱정 응답을 항목당 최대 3개의 완결 문장으로 생성한다. 각 SAY는 NFC 30자 이하로 검증한다. 긴 문장은 잘라 전송하지 않고 1회 분할 수리를 요청한다.
- 각 항목에 먼저 한 문장씩 배정한 뒤 보완 문장을 전달한다. 미전송·턴 부족을 로그로 남긴다. 실제로 보낸 문장만 설명의 수행 근거다.
- 환자가 중간에 명시적 질문을 하면 실제 자료와 계획으로 최대 2회 답변을 생성한다. 질문 감지는 문장부호·한국어 표현 휴리스틱이며 모든 질문을 인식한다고 보장하지 않는다.
- 마지막 이해 확인 후 최종 판단을 재검토하고, 필요한 경우 한 번 실제 교정 문장을 보낸다. 추가 왕복을 무한 반복하지 않는다.
- 설명에 필요한 여유를 위해 종료 예약을 8→12턴으로 늘렸다. 전체 상한은 45턴으로 유지했다. 수집 턴이 줄어드는 대가가 있으므로 정보수집 회귀도 확인해야 한다.
- 성공한 SAY의 출처 ID·턴·원문과 목적 태그를 상태에 연결한다. 기록의 `P.education`은 실제 전달 원문과 추가 교육 계획을 명확히 나눈다. 태그는 목적 메타데이터이며 설명의 임상적 충분성을 증명하지 않는다.
- 분석에 종료 SAY 태그별 횟수·누락 이벤트·중간 질문 검토 수를 추가했다. 모델이 생성만 한 문장은 전송 횟수에 넣지 않는다.

원본 E2의 진료·문진·진단 루프는 이번에 바꾸지 않았다. 새 하네스의 대화 흐름을 개선하는 작업이다. 복용량 수치 정합성, 부분 부정의 범위, 표적 진찰 선택은 이 작업으로 모두 해결됐다고 보고하지 않는다.

## 실행에서 확인한 추가 문제와 v0.4.1

C10의 실제 SAY에 `그레이브스병이 가장 의심되지만`이 단독으로 들어갔다. 길이 제한을 통과해도 완결 문장은 아니었다. v0.4.1은 `지만/으나/이며/인데/다면/라면/하면/면서`로 끝나는 발화를 불완전한 연결절로 보고 수리 대상으로 돌린다. 한국어 문법 전체나 임상적 충분성을 검증하는 기능은 아니다.

또한 조기 DONE 후 남은 수집 턴이 모두 종료 설명으로 흘러가 C10에서 종료 단계에 19턴을 사용했다. v0.4.1은 예약과 별개로 **종료 단계 자체도 최대 12턴**으로 제한한다. 여유 문진 턴을 반복 설명에 전부 쓰지 않는다. 설명 일부가 빠질 수 있으므로 누락을 기록하며, 이 제한이 실제 점수를 높였다고 주장하지 않는다.

별도 E2 adapter는 기존처럼 전체 문자열이 30자 안이면 그대로 반환하도록 보존했다. 이 호환성 보완·연결절 거절·종료 단계 상한을 추가한 최종 v0.4.1은 단위·패키지 검증 대상이며, 아래 개발 API 실행은 수정 전 v0.4.0이다. 둘을 동일한 실험 버전으로 보고하지 않는다.

## 검증

실행 전 테스트 57개, 후속 연결절·호환성·종료 상한 보완 후 **60개**가 통과했다. 추가 회귀 사례는 다중 문장 보존, 중간 질문의 즉시 응답, 미전송·실패 SAY의 교육 완료 제외, 계획/실제 분리, 이해 확인 오해 교정, 턴 부족, 조기 DONE 시 종료 상한, 성공 이벤트만 집계하는 계측이다. 이 테스트는 모델 출력의 임상적 정확도를 검증하지 않는다.

공개 C01·C10을 같은 Doctor·전체 45턴 상한으로 각각 1회 실행했다. 개발용 별도 검토는 공식 점수와 구분한다. 이전 후보와는 예약 턴·프롬프트·종료 흐름이 달라 개별 기능의 인과 효과를 분리한 실험이 아니다. 두 증례는 이미 개발에 사용했으므로 독립 검증이 아니다.

## 비공식 평가와 채택 판단

같은 개발용 검토 모델 `openai/gpt-6.1-sol`과 같은 검토 프롬프트를 사용했다. 공개 기준 자료는 검토 도구만 읽으며 진료 에이전트에 주입하지 않았다. 상세 결과는 [비교 표](benchmark_004.md)에 있다.

| 증례 | 이전 통합 후보 추정 | v0.4.0 추정 | 의사소통 변화 | 주요 손실 |
| --- | --- | --- | --- | --- |
| C01 | v0.3.2: 62 | 45 | 7→9 /15 | 정보수집 15→9, 추론 11→4, 효율 14→8 |
| C10 | v0.3.0: 70 | 67 | 6→9 /15 | 정보수집 18→17, 효율 16→10 |

**판정: 의사소통 추정은 높아졌지만 전체 점수 개선은 입증하지 못했다. 제출 후보로 채택하지 않는다.** 단일 실행·상이한 이전 버전 비교이므로 특정 코드가 감점 원인이라고 단정하지 않는다. C01에서는 정보수집·진단의 회귀가 커서 설명만 개선하는 접근이 충분하지 않다는 근거로 삼는다.

v0.4.1의 문장 검증·턴 상한은 실행에서 확인한 문제를 해결하는 후속 수정이다. 이 버전의 개발 API 점수는 아직 측정하지 않았다. 다음 유료 실행 전에는 수집 완료 조건과 출처·의미 검증을 먼저 개선해 단순 설명 문구 튜닝의 반복을 피한다.

## 다음 구현 우선순위

1. 주호소별 중요 관찰을 `질문 시도 / 실제 답변 / 의미 확인 / 미확인·상충`으로 나누고, 답하지 않은 항목을 완료하지 않는다. 복합 질문의 부분 답변을 전체 음성으로 확장하지 않는다.
2. DONE을 진단명 발견으로 결정하지 않고 미해결 핵심 항목과 실제 안전 상태를 대조한다. 다만 긴급 처치나 제한된 시간 때문에 남기는 항목은 지연하지 말고 미확인으로 기록한다. 단순 종료 Critic 추가가 아니라 행동과 근거 연결을 개선한다.
3. 현재 위험 평가와 주진단의 근거·불확실성을 분리하고, A/P에서 환자 사실을 언급할 때도 출처가 실제 응답인지 검증한다. C01에서는 깨어 있다는 부분 답변이 '호흡도 편함'으로 확대된 사례가 있었다.
4. 필요한 내용을 적게 반복하면서 환자의 실제 질문과 실행 가능한 추적 시점을 설명한다. 증례 ID나 공개 정답을 런타임 분기로 사용하지 않는다.

현재 새 프로젝트의 공식 점수·Docker 검증은 미완료이며 공식 제출과 PR 병합은 수행하지 않았다. 기능 개선과 실패 분석 결과를 PR에 공유하되 성능 검증 완료로 취급하지 않는다.
