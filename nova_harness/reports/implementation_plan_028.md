# 28차 구현 계획 — 관찰 기반 감별 수렴 엔진

2026-10-20 KST

## 왜 구현하는가

현재 E2에도 기본 순환은 있다. 질문에 대한 환자 답변을 양성·음성·불확실로 갱신하고 후보를 다시 정렬하며, 후보의 미확인 소견을 다음 질문으로 제안한다. 그러나 세 가지가 빠져 있다.

1. 한 답변이 후보 순위와 간격을 실제로 얼마나 바꿨는지 기록하지 않는다.
2. 충분한 근거가 모였는지 판단하는 명시적인 수렴 조건이 없다.
3. 최종 진단은 matched 근거가 있는 상위 후보를 선택하며, 위험질환 배제·상충·미확인 핵심 근거를 제출 게이트로 확인하지 않는다.

그 결과 질문을 많이 해도 후보가 줄지 않을 수 있고, 반대로 충분히 좁혀졌는데도 낮은 가치 질문을 계속할 수 있다. 이전 전역 재정렬은 이 문제를 해결하지 못하고 원본 안전 흐름을 훼손했다. 수렴 엔진은 질문 목록을 전역 재정렬하는 기능이 아니라 매 답변의 진단적 효과를 측정하는 제어 계층이다.

## 데이터 흐름

```text
실제 SAY/EXAM 결과
  → 출처 있는 관찰 개념
  → 후보별 지지/반대/미확인 갱신
  → 답변 전후 rank·score gap·핵심 공백 변화
  → 다음 구분 행동 추천 또는 수렴
  → SOAP A와 최종 diagnosis 일치 검증
```

환자 관찰은 API가 돌려준 응답, 실제 진찰 결과, 초기 활력징후로 한정한다. 의료지식의 질환 관계는 환자 사실이 아니다.

## 상태 모델

각 관찰은 다음을 가진다.

```json
{
  "evidence_id": "e18",
  "source": "SAY",
  "target": "heat_intolerance",
  "assertion": "present",
  "subject": "patient",
  "temporality": "current",
  "turn": 18,
  "raw": "요즘 더위를 유난히 못 참겠어요"
}
```

후보 상태는 `matched_key`, `matched_support`, `against`, `unknown_key`, `score`, `rank`를 보관한다. 매 턴의 전후 snapshot을 비교해 순위 변화, 1·2순위 score gap 변화, 해소된 핵심 공백을 기록한다. `share`와 score는 확률이 아니다.

## 다음 질문 선택

질문 후보는 상위 K개 후보에 연결됐고 아직 미확인인 target만 사용한다. 각 후보 행동의 효용은 다음 요소로 구성한다.

```text
utility = 후보분리도
        + 위험질환 상태변화
        + 검사·치료 결정변화
        + 핵심근거 공백 해소
        - 이미 확인한 내용
        - 같은 의미 반복
        - 남은 턴 비용
```

후보분리도는 답이 양성 또는 음성일 때 상위 후보들의 지지·반대 관계가 얼마나 다르게 변하는지 계산한다. 같은 target이 명확히 확인됐으면 0점으로 제외한다. 상충·불확실·부분응답은 한 번만 구체적으로 명료화한다.

## 수렴 판정

종료는 한 개의 임의 확률 임계값으로 결정하지 않는다. 아래 조건을 함께 본다.

- 1순위에 실제 핵심 관찰근거가 있는가
- 1·2순위 score gap이 충분하고 최근 질문 뒤에도 안정적인가
- 두 후보를 가르는 미확인 핵심 소견이 남아 있지 않은가
- 즉시 위험한 후보의 필수 배제가 끝났는가
- 상충하거나 불확실한 핵심 답변이 남아 있지 않은가
- 약물·알레르기·금기 등 계획 안전정보가 확보됐는가

초기 threshold는 공식 점수를 맞추기 위해 임의 조정하지 않는다. 저장된 로그의 후보 궤적을 shadow mode로 재생해 오진 없이 종료할 수 있었던 구간을 먼저 측정한 뒤 고정한다.

## 단계별 도입

### 1단계: Shadow 계측

원본 E2의 질문과 진단을 전혀 바꾸지 않는다. 매 턴 후보 snapshot, 추천 행동, 수렴 여부만 별도 로그에 기록한다. 저장된 C01/C03/C10 로그를 재생하고, 개발 API에서도 원본 동작과 동일한지 확인한다.

### 2단계: 반복 방지

명확히 해결된 동일 target만 차단한다. 상충·불확실·부분응답의 명료화는 허용한다. 원본 후보 순서는 유지한다.

### 3단계: 기존 후보 안에서 선택

원본 E2가 이미 만든 질문·진찰 후보 안에서 가장 높은 분리 효용 행동을 선택한다. 새 질문을 추가하지 않는다. 안전·핵심 진찰·마무리 예약은 원본보다 줄이지 않는다.

### 4단계: 제한된 새 질문

상위 두 후보를 구분하는 핵심 target이 원본 후보 목록에 없고, 안전 완료 조건과 턴 여유를 만족할 때만 새 질문 하나를 허용한다. 답변 뒤 후보 상태가 변하지 않으면 같은 경로를 중단한다.

## SOAP 제출

S/O는 출처가 있는 관찰 개념으로 렌더링하되 원문을 반복 붙이지 않는다. A에는 주진단 근거, 주요 감별과 그것이 밀린 이유, 해결되지 않은 불확실성을 기록한다. P에는 그 불확실성을 해소할 검사·추적, 치료 조건과 안전망을 적는다. 실제 환자에게 말한 교육과 향후 계획은 구분한다.

## 검증과 채택

단위 검증은 양성·음성·불확실·상충·가족력·과거력·수치·부분응답을 포함한다. 저장 로그 재생에서 원본 행동 불변, evidence 누락 0, 후보 snapshot 결정성을 확인한다. 이후 C01/C03/C10 개발 API에서 진단 일치, 비정상 종료 0, 안전 발화와 핵심 진찰 보존을 확인한다.

공식 채택은 원본 E2의 진단 15와 안전 15를 유지하면서 정보수집·검사추적·의사소통 가운데 적어도 하나가 상승할 때만 한다. 효율 회귀도 별도로 확인한다.
