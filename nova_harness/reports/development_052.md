# 52차: 계획 원본과 실제 발화·수행 기록 연결

## 변경 범위

51차 관찰 상태를 고정하고 별도 `R3a_plan_delivery`를 추가했다. 기존 `ObligationLedger`의 원문 조건/행동/시점·부정·긴급성 및 완결 문장 검증을 재사용한다. 기존 S2/S3의 의무 추출·성공 발화 구분을 새 기능으로 주장하지 않는다. 이번 차이는 기존 closing 생성·30자 초과 일반 문구 교체·별도 발화 재생성 대신 길이 제한 없이 출처 계획 항목을 먼저 고정하고 별도 렌더러가 검증된 발화 그룹을 생성하는 실행 경로와, 같은 기록 버전의 순서 있는 성공 이벤트로 수행 기록을 확정하는 것이다.

계획 원안의 임상 적절성, 모델이 추출하지 않은 의무, 번역·의미 완전성은 이 검증만으로 확인되지 않는다. 진단 순위·진찰·문진·종료 정책은51차와 같다. 안전 그룹을 우선하고 남은 예산에 진단 설명과 걱정 답변을 넣으므로 의사소통/효율 회귀 가능성도 측정해야 한다.

## 구현과 불변조건

- `nova_agent/plan_delivery.py`: 원안 버전 해시·출처 의무 그룹을 유지한다. source_field/source_quote/condition/action/timing과 완결 messages는 기존 검사에 통과해야 한다. 메시지 검증에 실패한 항목도 원장에 남기며 일반 경고로 교체하거나 완료 처리하지 않는다. 두 번째 렌더러의 응답에서는 항목 ID와 messages만 사용해 원안 필드 변경을 막는다.
- 전체 그룹을 담을 턴이 없으면 그룹을 배정하지 않는다. 발화 도중 실패/예산 종료로 일부만 전달되면 미완료다. 실제 요청의 원자성이나 네트워크 완전 전달까지 증명하는 것은 아니다.
- 같은 기록 버전에서 순서대로 API 성공 응답을 받은 메시지만 그룹 완료다. 과거/다음 기록의 같은 문장으로 승계하지 않으며, 설명 이후 원안이 바뀌면 현재 계획 완료로 인정하지 않는다.
- SOAP의 P 원문은 수행 미확인 계획 인용으로 분리하고 실제 전달 구역은 성공 SAY만 결정적으로 나열한다. 환자가 이해했다는 추론은 하지 않는다. 기존 원안의 완료형 동사는 인용 구역에 남을 수 있다.
- 도구 `safety_session.py`의 별도 모드, 엄격 재생 `replay_plan_session.py`, 원문 없는 집계 `summarize_plan_delivery.py`를 추가했다. 기본 모드·동결 R3a는 변경하지 않는다.

## 검증

최종 전체318테스트 통과. 새15개는 일반 경고로 특정 경고를 완료 처리하지 않음, 동일 성공 발화, 이전/이후 기록 제외, 계획 변경 무효화, 실제 수행 구역의 미발화 제거, upstream 부가 완료 문구 분리, 그룹 예산·순서, 긴급성 소실 거절, 초과 길이 무절단, 부분 전달 미완료와 실제 closing→TimelineClient→diagnose 연결을 검증한다. 모델 응답을 주입한 제어 경로 테스트이며 임상 의미의 모델 검증과 다르다. 추가4개는 렌더링 실패/누락 시 항목 보존·빈 그룹 완료 방지·고정 행동 변경 방지·출처 없는 조건 거절을 검증한다.

전체 개발 API와 결과·소스 범위는 아래 후속 기록에 추가한다. 공식 점수·Docker·제출 환경은 미검증이며 새 ZIP·공식 업로드·병합은 하지 않는다.

## 중간 실패 보존

최초3세션은 원본 hybrid_comm의 closing만 교체하고 관찰 모드의 동적 consult globals에는 연결하지 못한 것을 발견해 SIGINT로 중단했다. C01/C03/C10 관찰 턴32/31/31이며 완료 검증으로 세지 않는다. 중단 로그는 로컬에 보존하고 집계는 `plan_delivery_interrupted_052.json`에 있다. 해당 조합의 호출 경로 테스트를 보완했다.

연결을 고친 단일 단계 방식(소스78d9f67)은 C01 43턴/321.387초, C03 28턴/180.826초, C10 42턴/281.871초로 오류·절단 없이 종료했다.3세션 엄격 저장 재생에서 모델 입력·행동·최종SOAP가 일치했다. 하지만 수용 항목은 각각3/1/2개뿐이었다. C03은 추적1개, C10은 약물 임의 복용 금지/카페인·운동 주의2개로 원안의 구체 경고가 빠졌다. 전체 계획 누락을 검증 거절 수만으로 파악할 수 없다는 사례다. 짧게 표현하기 어려운 의무를 추출 단계에서 제외하도록 한 결합을 해소하기 위해 두 단계 inventory→rendering으로 보완했다.

이 단일 단계 결과와 재생은 `plan_delivery_single_stage_052.json`, `plan_delivery_single_stage_replay_052.json`에 소스별로 동결한다. 당시 source_matches_current=true는 이후 보완본까지 검증한다는 의미가 아니다. 최종 런타임 소스는73336e5다. 이번에는 중단3·단일 단계 완주3·최종 두 단계3의 실행을 구분한다.

## 채택 판단과 다음 설계

**이번 후보를 성능 개선본/제출 권장본으로 채택하지 않는다.** 기본 경로와 동결 R3a를 변경하지 않으며 공식 점수·78점 예상·새ZIP은 없다. 다음 개선은 같은 프롬프트를 더 엄격하게 쓰는 것이 아니라 계약을 바꾸는 것이다.

1. 원문 인용은 출처로 유지하되 행동은 `진료/응급실 방문/연락/복용 금지/감독하 조정/추적` 같은 타입과 대상·조건·시점·금지·행위 주체·권고 강도·계획 ID로 표현한다. 기록 동사 원문을 발화에 문자 그대로 넣는 계약과 분리한다. 이는 아직 미구현 설계다.
2. 같은 대처·긴급성·대상을 가진 대체 위험 조건만 그룹으로 묶고, 조건→행동 관계를 보존해 결정적 템플릿으로 렌더링한다. 다른 시점/행동/부정 범위를 합치지 않는다. 긴 그룹은 완결된 조건·대처 쌍으로 나누고 예산을 함께 배정한다. 단순 문자열 느슨화로 완료 수만 높이지 않는다.
3. 구조화 계획의 의미 정확성·지시 대상·임상 적절성 및 실제 발화의 의미 보존을 별도 검증한다. 후기 위험 응답의 즉시 재계획과 재전달도 현재의 완료 무효화와 별개로 남아 있다. intro/concern의 확정적 진단 표현도 별도 회귀 대상이다.

이 후속 설계를 이미 구현한 것으로 표현하지 않는다. 현 소스는 재현 가능한 실험/실패 분석을 위해 별도 모드로 보존하며 제출 패키지에 자동 연결하지 않는다.
