## 2. MedDB에서 가져올 가치가 있는 부분

### 임상 그래프와 행동 연결

MedDB는 질환명 사전만 있는 구조가 아니다. 주호소별 감별 후보, 질환의 핵심·보조·반대 소견, 문진 슬롯, 진찰 동작, 기록 필드가 연결되어 있다. `hybrid_agent.Tracker`는 소견의 양성·음성·미확인·상충 상태와 출처 턴을 보관한다. `CareCoverage`는 필요한 항목을 실제 행동으로 만들고 조건부 약물 문진·소아 연령 맥락을 적용한다.

현재 프로젝트의 초진 정보 시드보다 임상 범위가 넓어 재사용 가치가 크다. 다만 저장소는 이 지식을 **임상 검수 전 팀 작성 초안**으로 표시한다. 임의 가중치나 후보 비중을 진단 확률로 해석하지 않고, 응답과 모순되는 진단을 확정하는 규칙으로 사용하지 않는다.

### 별도의 의사소통 단계

`hybrid_comm`은 걱정 확인과 진료 마무리를 별도 단계로 수행하며 E2는 추적·위험 증상·teach-back을 추가한다. 계획을 P에 적는 것과 환자에게 말한 것을 구분하는 구조는 현재 하네스에도 필요하다. 수행한 SAY만 교육 완료로 기록한다.

### 과도한 재구성 방지

원본 E2는 필요한 질문 일부를 코드로 선택해 Doctor 선택 호출을 줄인다. C01 직접 비교에서 이 흐름을 유지한 원본 E2가 단순히 그래프 힌트를 추가한 새 하네스보다 높은 개발용 추정 점수를 보였다. 따라서 모든 것을 새 Planner로 대체하지 않고 **원본 보존 후보와 통합 후보를 분리**했다.

## 3. 코드에서 확인한 개선 위험

1. `CareCoverage`의 항목 추적은 행동 누락 방지에 유용하지만, 질문에 대한 모름·부분 답변이 어떤 진단 소견까지 해결하는지 별도로 확인해야 한다. 질문 수행과 확정 음성을 같게 보지 않는다.
2. 자유형 질문은 표준 문장과 정확히 같지 않으면 target 연결이 사라질 수 있다. 이를 위해 새 하네스에는 검증된 target과 원문 응답을 연결했다.
3. `read_answer()`의 짧은 답변 규칙과 `read_exam()`의 포괄적 정상 처리에는 부정 범위를 넓힐 가능성이 있다. 현재 포트는 실제 원문과 개별 소견의 출처를 요구하고, 진찰 결과가 없는데 신체 소견을 생성하지 않는다.
4. `write_record()`는 KB가 정규화하지 못하는 진단에서 P를 비울 수 있는 분기가 있다. 모든 증례에서 발생한다고 단정할 수는 없지만 향후 계획 누락의 회귀 대상이다. E2의 `contextual_plan=True`가 기존 개인별 P를 보존하는 부분은 유지한다.
5. 종료 설명은 생성만으로 완료되지 않는다. 실제 새 통합 후보 C01에서는 30자를 넘은 문장 5개가 모두 전송되지 않았다. 로그를 근거로 길이 수리와 완결 문장 선택을 추가했다.
6. 그래프를 붙였다고 정보수집이 자동으로 보장되지는 않는다. 특히 C01은 급성 위험에 집중하면서 만성 문제를 구분할 질문을 일찍 끝내는 현상이 남았다.

이 항목은 저장소 정적 분석과 공개 개발 실행에서 찾은 위험이다. 비공개 공식 증례의 감점 원인을 직접 확인한 것은 아니다.

## 4. 이번 적용 내용

### A. 경량 임상 지식 통합

`nova_agent/clinical_graph.json`에 주호소 19개·질환 134개·소견 289개·진찰 56개·문진 슬롯 19개를 약 94KB로 가져왔다. 공개 샘플·정답·채점 체크리스트·대형 온톨로지 전체·치료 계획 자동 실행 규칙은 포함하지 않았다. 원본 소스 해시와 고정 커밋, 출처 문서는 `third_party/meddb/`에 보관했다. `tools/import_meddb.py`로 재현하며, 소스가 달라지면 자동 갱신하지 않는다.

`clinical.py`는 실제 주호소 표현과 확인된 사실로 감별 후보·아직 확인하지 못한 핵심 소견·다음 행동을 제안한다. 점수는 미보정 휴리스틱이다. 상충 소견은 양성/음성 중 하나로 임의 선택하지 않는다. 소아의 사춘기 단계 진찰을 일괄 추천하지 않는다. 범위 밖 주호소는 기존 Planner로 처리한다.

### B. 근거·기록·설명

환자 사실에 연결된 target을 추가하고, 신체 징후는 실제 EXAM 결과에만 연결하도록 검증했다. S/O는 실제 응답으로 구성한다. 마무리는 걱정 확인 → 판단·계획·추적·안전 설명 → 이해 확인으로 분리했다. 길이 초과는 문자열을 자르지 않고 한 번 다시 생성하며, 필요하면 이미 생성된 완결 문장 중 30자 이하 문장을 선택한다. 실패한 설명을 했다고 기록하지 않는다. 이해 확인에서 새 정보가 나오면 최종 판단을 재검토한다.

### C. 입력·출력 비용

초기 통합은 문맥이 커져 입력 토큰이 증가했다. 압축 후보는 전체 그래프를 로컬에 두고 상위 가설 3개·다음 행동 8개·그에 필요한 개념만 전달한다. 모든 실제 응답은 유지하되 같은 원문을 사실 목록에 중복해서 적는 부분을 줄였다. 단순히 적게 물어서 효율 점수를 높이는 것을 목표로 하지 않는다.

### D. 원본 E2를 보존한 확장 후보

`meddb_overlay.py`는 원본 E2의 문진·진단 루프를 바꾸지 않는 별도 확장이다.

- 수면제 사용이 관찰된 경우에만 한 알 함량·마지막 복용·최근 24시간 총 정수를 확인한다. 약물 사용이 확인되지 않은 증례에 일괄 적용하지 않는다.
- 실제 답변을 질문·턴과 함께 기록한다. 모른다는 답을 정상이나 확인된 용량으로 바꾸지 않는다.
- 개인별 기록을 근거로 마무리 설명을 만들고 길이 검증을 적용한다.
- 원본 파일을 수정하지 않으며 설치·복원이 가능한 독립 후보로 실험한다.

## 5. 측정과 패키지

이번 개발 API 실행의 상세 수치는 별도 `meddb_benchmark_003.md`에 정리한다. 모든 점수는 공식 점수와 구분한 개발용 추정이며, 증례·턴 정책·버전이 다른 결과를 한 평균으로 합치지 않는다. 공개 C01·C10·C03는 이미 개발 과정에서 확인한 자료이므로 독립 검증 세트로 부르지 않는다.

Doctor는 모든 실행에서 `openai/gpt-6-luna`이며, 별도 개발용 검토자는 `openai/gpt-6.1-sol`이다. 같은 검토 프롬프트를 사용했지만 평가자 재실행 변동을 측정하지 않았다.

### 로그에서 재확인한 실패와 다음 수정 기준

- **짧은 문장 통과가 충분한 설명은 아니다.** 5개 태그의 SAY가 전송돼도 환자의 감량·비약물 치료 질문에 직접 답하지 않고 의뢰 안내를 반복했다. 다음에는 항목 하나를 억지로 30자로 압축하기보다, 필요한 설명을 여러 개의 완결 문장으로 나누고 그만큼 턴을 예약한다. 설명의 진단 근거·불확실성·계획·시점·위험·걱정 응답을 각각 원문 SAY와 대조한다.
- **계획과 수행을 기록에서 분리해야 한다.** E2 확장은 상세 P가 만들어져도 실제 대화에서는 일부만 전달됐다. 추후 교육 완료 필드는 모델이 만든 계획문을 복사하지 않고 실제 SAY로만 구성한다. 검사를 제안한 것과 실제 시행한 것도 구분한다.
- **복용 내역의 수치 모순을 해결해야 한다.** v0.3.2 C01은 평소와 최근 용량을 명확히 정리하지 않은 채 '평소보다 크게 초과'라고 적었다. 질문 추가만으로 해결되지 않는다. 함량·시각별 정수·하루 합계의 근거를 연결하고 불일치는 재확인하며, 확인 전 비교 표현을 금지한다.
- **부분 부정을 전체 음성으로 만들지 않는다.** '평소보다 심하지 않다'는 현재 증상 자체가 없다는 뜻이 아니다. '악화 부인'과 '현재 유무 미확인'을 나누는 회귀 사례로 남긴다.
- **안전 확인을 일반 문진보다 먼저 수행한다.** 확인된 약물 위험에서 현재 상태·병용 물질·실제 이동 계획을 우선 확인하도록 원본의 조건부 수집 정책을 보완한다. 구체적인 처치·감량 내용은 검수된 근거 없이 그래프 초안에서 자동 실행하지 않는다.

현재 코드에는 임상 관계 통합·출처 추적·길이 수리·조건부 복용 질문이 적용되어 있다. 위의 의미 검증과 기록 분리는 다음 개선 과제로 명시하며 구현 완료로 보고하지 않는다. 이번 7회 진료 실행과 7회 검토 결과를 보존하고 추가 유료 실행은 이 단계에서 종료했다.

- `submission.zip`: 경량 통합 하네스 후보.
- `submission_meddb_E2_reference.zip`: 고정 커밋의 E2 재현 비교본. 캡처의 ZIP과 동일하다고 검증한 파일은 아님.
- `submission_meddb_E2_plus_candidate.zip`: E2 보존 확장 후보. 개선이 검증되기 전 자동으로 기존 공식 제출을 대체하지 않음.

어떤 ZIP도 공식 리더보드에 자동 제출하지 않았다. 키·결과 로그·샘플 정답은 ZIP에서 제외했다. 패키지는 별도 폴더에 풀어 prepare·확장 적용을 확인했다. Docker 기반 전체 서버 환경 검증과 공식 점수 재측정은 별도다.

최종 확인: 프로젝트 테스트 **49개**, 원본 `test_care.py` **11개** 통과. 두 후보 ZIP은 키 없는 별도 임시 폴더에서 prepare를 실행했고 E2 확장의 설치·복원도 확인했다. ZIP 무결성·제외 경로 및 현재 개발 키의 실제 바이트가 소스·보고서·로그·ZIP에 포함되지 않았는지 검사했다. 이는 임상 정확도나 서버 실행 전체 검증을 의미하지 않는다.

개발 API 실험은 시작 시점의 `source_snapshot.zip`을 기준으로 실행했다. 최종 패키지에서는 사용하지 않는 구형 설명 모듈을 제거했으므로, 실험 스냅샷과 최종 ZIP을 바이트 단위로 동일하다고 주장하지 않는다. 최종 ZIP 자체의 Docker·공식 서버 재실행은 아직 하지 않았다.

## 6. 100점에 접근하기 위한 다음 검증

1. **정보수집:** 중요한 소견별로 질문 수행, 응답 획득, 의미 확인, 기록 반영을 나누어 측정한다. 모호한 답을 한 번 더 확인할지 판단하는 정책을 개선한다.
2. **의사소통:** 실제 전송된 설명에 진단의 불확실성·개인별 계획·구체적인 재평가·경고 증상·걱정 응답이 있는지 검토한다. 문장 길이 통과와 임상적 충분성을 따로 평가한다.
3. **효율:** 원본 E2의 코드 기반 선택을 기준으로, 어떤 모델 호출이 실제 판단을 개선하는지 제거 실험한다. 관계 지식 전체를 매 턴 반복 전송하지 않는다.
4. **진단추론·안전:** 확인하지 않은 사실을 진단 근거로 추가하거나 위험 대응을 무조건 무시해 점수를 올리지 않는다. 약물의 장기 문제와 현재 위험을 구분해 임상 검토한다.
5. **공식 검증:** 후보 ZIP·해시·개발 결과를 고정한 뒤 공식 평가의 영역별 변화를 확인한다. 목표선과 측정값을 분리해 기록한다.
