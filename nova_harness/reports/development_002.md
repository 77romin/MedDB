# 개발 2차 보고 — 공개 샘플 확장과 종료 검토 실험

기준일: 2026-10-18 KST. 이번 차수에서 개발 샘플 진료 5회, 세션 밖 검토 모델 호출 5회를 수행했다. 리더보드 평가나 코드 업로드는 하지 않았다. 모든 실험의 턴 상한은 30이며 Doctor는 `openai/gpt-6-luna`, 검토자는 `openai/gpt-6.1-sol`이다.

## 결과와 채택 결정

| 공개 증례 | 기본 에이전트 자가평가 | 하네스 자가평가 | 관찰 |
| --- | --- | --- | --- |
| C01 | 40 | v0.1.2: 44 / 종료 검토 v0.2.0: 36 | 종료 검토가 긴급 이송을 우선해 추가 문진을 수행하지 않았으며 핵심 감별 누락이 지속됨 |
| C10 | 63 | v0.1.2: 66 | 계획·안전은 높지만 정보수집·의사소통은 낮음. 하네스의 입력·출력 토큰도 더 많음 |
| C03 | 58 | v0.1.2: 53 | 가족 성장력 등 감별 정보와 설명이 부족. 주진단은 원인 미확정 수준 |

점수는 **공식 점수가 아닌 별도 개발 모델의 추정**이며 임상 전문가가 검증하지 않았다. 각 조건 1회 실행으로 응답 변동·검토자 변동을 통제하지 못했다. 증례별 차이를 숨기는 통합 평균이나 검증된 정확도 개선을 보고하지 않는다. 공개 비교 기록의 모든 항목을 반드시 해야 한다고 해석하지 않는다.

현재 하네스를 기본 에이전트보다 전반적으로 우수하다고 판단할 수 없다. v0.2.1에는 프로토콜·기록 보존·실험 도구를 유지하지만 **종료 검토는 기본 비활성화**한다. `--closure-audit`로만 선택적 실험할 수 있다. v0.2.1은 설정 기본값 변경과 계측 보완 버전이며, 임상 결과 표는 실제 실행한 v0.1.2/v0.2.0의 결과다.

## 종료 검토 구현과 실제 관찰

첫 DONE에서 응답 증거 5개 이상, 남은 턴 7 이상, 기록 작성 여유 외 추가 180초가 있을 때 한 번만 검토한다. 검토자는 중요한 누락 최대 3개와 다음 행동 하나를 제안한다. 긴급 이송·처치를 지연할 우려가 있거나 중요한 추가 정보가 없으면 종료한다. 검토 실패·형식 오류로 제출을 막거나 검토를 반복하지 않는다.

C01 v0.2.0에서는 검토 호출 1회, 후속 행동 0회였다. `urgent_exit=true`를 반환했고 결과적으로 10턴에 진료를 마쳤다. 해당 처분의 임상적 타당성은 별도 검토 대상이며, 점수를 얻기 위해 긴급 대응을 무조건 무시하거나 특정 정답으로 진단을 강제하지 않는다. 이 실험은 간단한 종료 Critic만으로 문진 누락이 해결된다는 가설을 지지하지 않는다.

## 로그를 통해 확인한 공통 문제

1. **정보 구조만으로 질문 우선순위가 보장되지 않는다.** 현재 온톨로지는 초진 항목과 약물 사용 확인 관계의 시드다. 질환 가설별로 어떤 관찰이 구분에 기여하는지를 연결한 검토된 임상 관계가 없다.
2. **“확인할 항목”과 “실제로 답을 얻은 항목”을 더 세밀하게 나눠야 한다.** 약물·사회력·관련 증상을 묶어 물으면 일부만 답하고 나머지를 미확인으로 남기는 문제가 지속된다. 원문 인용이 있어도 부정의 적용 범위까지 검증됐다는 뜻은 아니다.
3. **환자 설명과 기록 계획의 차이가 남아 있다.** P에는 계획이 있어도 실제 SAY는 전문진료 권고 한 문장에 그치는 사례가 있었다. 필요한 설명을 쪼개 실제로 전달했는지 확인해야 한다.
4. **짧은 진료가 항상 효율적인 진료는 아니다.** 하네스는 C10 15턴, C03 17턴에 종료했지만 기본 에이전트보다 Doctor 토큰을 더 사용했고 중요한 정보도 덜 수집했다.
5. **기록을 원문으로 구성하는 이점과 한계가 모두 있다.** 임의의 나이·복용량 변경 경로를 줄였으나 구조화된 임상 요약과 근거 해석은 아직 부족하다. 반복 원문·미분류 대화가 많으면 기록 가독성도 떨어질 수 있다.

이 항목은 실제 로그와 개발용 검토를 종합한 구현 진단이다. 특정 증례의 공개 정답·대본을 런타임에 넣거나, 누락 단서를 증례 ID로 분기하는 방식으로 해결하지 않는다.

## 다음 구현 범위

다음에는 근거 문서와 연결된 `주호소 → 감별 가설 → 구분 소견 → 단일 질문/진찰 → 계획·설명` 관계를 구축한다. 개념 사전과 자유형 프롬프트만 전달하는 현재 구조에서, 아직 답을 얻지 못한 중요한 항목을 실제 행동 후보로 만드는 질문 계획으로 전환한다.

- 관계마다 문서·절·버전·적용 조건·검토 상태를 연결하고 미검증 관계를 확진·배제 규칙으로 쓰지 않는다.
- 임상 판단에 영향을 주는 동반 증상과 가족력은 이름이 같은 범주에 묻었다는 이유로 완료하지 않고 개별 항목을 추적한다.
- 질문·결과·정규화된 사실을 연결하고 부정·시간·수치의 원문 범위를 유지한다.
- 실제 설명 내용과 향후 교육 계획을 따로 기록한다. 선언된 communication 태그만으로 설명의 임상적 충분성을 인정하지 않는다.
- 검색·질문 계획 추가 효과를 같은 조건에서 비교하고, 개발에 반복 사용한 C01·C10·C03 외의 독립 검증 세트를 별도로 준비한다. 이제 세 공개 증례 모두 관찰했으므로 향후 결과를 독립 검증이라고 부르지 않는다.

## 검증과 산출물

자동 테스트 **35개 통과**. 새 테스트는 종료 검토의 단 한 번 실행, 후속 행동, 긴급 종료, 형식 오류·실패 시 제출, 기능 제거, 시간·턴 여유 조건과 미완료 로그의 오판 방지를 확인한다. 제출 ZIP을 별도 임시 폴더에 풀어 개발 키·정답 파일 없이 prepare가 되는지도 확인했다.

현재 패키지는 15파일·22,205바이트이며 개발 키·공개 정답·실험 결과를 포함하지 않는다. 생성만 했으며 업로드하지 않았다. Docker 데몬은 실행되지 않아 Docker 기반 자원·네트워크 격리 검증은 여전히 미완료다.

- [증례별 벤치마크](benchmark_002.md): 점수·주진단·토큰·시간·검토 의견.
- 각 `results/실험폴더/`: manifest, 코드 스냅샷, 원문 요청·응답, 분석, 비공식 검토.
- `tools/benchmark_report.py`: 명시한 실행 폴더들을 증례별로 묶는 보고 도구.
- 검토 결과에는 프롬프트·공개 비교 자료의 해시를 추가해 어떤 기준으로 검토했는지 추적한다.
