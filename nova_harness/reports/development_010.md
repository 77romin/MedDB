# 개발 10차 — 판단 범위·필수 계획 안내 개선

2026-10-18. **진행 중**. Doctor `openai/gpt-6-luna`, 세션 밖 개발 검토자 `openai/gpt-6.1-sol`. 공식 점수는 미측정이다.

## 요청과 ZIP 조건

사용자는 개선을 승인하고, 80점 이상을 기대할 근거가 생길 때 제출 ZIP을 만들도록 요청했다. 개별 공개 증례의 자체 검토 80점만으로 조건을 충족했다고 보지 않는다. 복수 증례의 반복·영역별 안전·실제 핵심 정보와 안내·사실 보존·비용을 함께 검토한다. 이 기준도 공식 점수 예측의 검증을 대신하지 않는다.

기존 v0.8.3 ZIP은 `results/submission_v083_009.zip`으로 보존했다. 새 테스트는 임시 폴더에서 허용 목록·독립 prepare를 검증하며 `dist/submission.zip`을 자동 생성하지 않는다. 공식 업로드·병합은 하지 않는다.

## 분리한 개선

1. **v0.9.0 판단 범위:** 실제 입력·응답 및 현재 가설에 따라 약물 실제/통상/24시간 사용, 병용 범위, 현재 안전과 이후 조절, 갑상선 치료 전 확인, 가족 성장력 대상·시간을 구분한다. 관찰이나 목표 완료를 코드로 추론하지 않는다. 기존 행동을 강제 대체하지 않는다. [출처·조건·제약](../docs/CLINICAL_DECISION_AXES.md).
2. **v0.9.1 필수 문장별 예산:** 목적 태그당 첫 문장뿐 아니라 `essential`로 지정한 실제 추가 문장 각각을 보호한다. 검사 결과 확인과 장기 성장 재측정처럼 시점·목적이 다른 계획을 나눠 전달하도록 한다. 환자 질문 후에도 남은 필수 문장 수를 다시 계산한다. 수정으로 문장 인덱스가 달라졌다면 기존 essential 인덱스를 재사용하지 않는다. 이는 필수 의미를 모델이 정확히 지정했음을 보증하지 않는다.

## 검증 계획과 진행

- 기존 v0.8.3 동일 소스 3증례 각 1회: 66/66/75. 같은 이전 기준 코드의 변동 범위도 함께 비교한다. 새 후보는 세 증례 각 1회로 먼저 측정하며 소스를 실행 전에 고정한다.
- 결과가 지지할 때만 반복·확장한다. 단계끼리 조건을 합치거나 낮은 비교 기준만 선택하지 않는다. 고정 로그 검토는 기존 프롬프트를 유지한다.
- 단위/회귀 테스트 140개 통과. 실제 API 성능과 구분한다. 문장 예산 테스트는 연속 환자 질문에도 두 별도 추적 문장과 안전·계획을 보존하는지 확인한다.

### v0.9.0 결과

고정 소스 `d8db277`의 C01/C03/C10 비공식 검토는 각각 44/66/71점이었다. C10에서는 임신 가능성·안구 증상·흡연·갑상선 가족력을 새로 확보했지만 운동 시 호흡곤란 이후의 심폐 진찰과 구체적 추적·치료 교육이 남았다. C03은 성장속도·중간부모키 계산을 의미상 중복 요청했고, C01은 다섯 번의 잘린 Planner 출력 뒤 수집 8회에서 종료됐다. 판단 범위 추가만으로 세 증례의 일관된 개선은 확인되지 않아 제출 후보에서 제외한다.

### v0.9.1 장애 실행

첫 세 실행 r1은 완료 이벤트 없이 마지막 HTTP 요청에서 멈췄다. 복구 실행 r2는 모두 완료 이벤트와 비공식 검토를 남겼지만, 세 증례 모두 524 `INVALID_API_RESPONSE` 직후 409 `REQUEST_PENDING`이 반복됐다.

| 증례 | 수집 행동 | 장애 포함 비공식 점수 | 해석 |
| --- | ---: | ---: | --- |
| C01 | 3 | 25 | 524/409 뒤 조기 종료; 비교 제외 |
| C03 | 4 | 41 | 524/409 뒤 조기 종료; 비교 제외 |
| C10 | 4 | 47 | 524/409 뒤 조기 종료; 비교 제외 |

이는 임상 로직의 낮은 점수 증거가 아니라 전송 복구 실패가 섞인 결과다. 서버가 접수한 요청을 처리 중일 수 있으므로 새 요청 ID로 행동을 다시 보내면 환자 턴을 중복 소비할 수 있다. v0.9.2는 524도 기존 502/503/504처럼 같은 요청 ID·본문으로 재시도하고, 409 `REQUEST_PENDING`이 해소될 시간을 위해 대기열을 2/5/10/20/30초로 확장한다. 인증·400·429 등 영구 오류는 이 규칙으로 재시도하지 않는다. 524→409→성공 회귀를 포함해 로컬 142개 테스트가 통과했다.

현재 80점 이상 기대 근거가 확인되지 않았으므로 제출 권장 ZIP은 만들지 않았다. v0.9.2의 정상 완료 여부를 먼저 확인하고, 장애 없는 결과만 임상 후보 성능으로 비교한다.

### v0.9.2 정상 완료 비교

동일 세 증례를 전송 복구 소스로 다시 실행해 모두 정상 종료했다. 이번에는 524/409가 발생하지 않아 실제 524 복구 분기는 재현되지 않았다. 524→409→성공은 회귀 테스트로만 확인됐고, 앞선 3/4/4회 조기 종료가 32/20/33회 수집으로 되돌아온 결과와 구분한다.

| 증례 | v0.9.0 | v0.9.2 | 수집 | 주요 남은 문제 |
| --- | ---: | ---: | ---: | --- |
| C01 | 44 | 62 | 32 | 다기관·낮 복용·기능 손상·중증 금단력, 실제 안전 교육 |
| C03 | 66 | 71 | 20 | 초기 성장·영양/생활·내분비 범위, 표적 진찰·검사 설명 |
| C10 | 71 | 75 | 33 | 배변·월경·수면·피로, 근력 진찰, 치료 경로·경고 증상 설명 |

각 값은 같은 공개 증례의 단일 비공식 검토다. C01은 Planner 출력 잘림 4건과 무효 응답 1건이 있었고, C10에는 핵심 미질문 13건이 남았다. C10은 눈 증상을 세 문장, 임신·갑상선 과거력을 각각 두 문장으로 나눴다. C01은 의료진 재평가 요청·확인을 여러 턴 반복했다. 더 많은 턴이 곧 더 많은 핵심 정보가 아니었다.

### v0.9.3 다음 분리 변경

판단 범위에 약물 접근 경로·중증 금단/기능 손상, 갑상선 전신 증상·근력 진찰, 성장 영양/생활·표적 진찰을 보강한다. 조기 DONE 검토가 이 범위와 실제 수집 상태를 함께 보게 하고, 시간과 수집 턴이 충분할 때만 최대 두 번의 후속 행동을 허용한다. 턴 한도 종료에는 적용되지 않는다. 환자 사실을 자동 생성하거나 모든 항목을 묻도록 강제하지 않는다.

로컬 143개 테스트가 통과했다. 고정 v0.9.3을 같은 3증례에서 한 번씩 실행해 C03 조기 종료의 핵심 누락이 줄어드는지, C01/C10의 우선순위가 실제로 바뀌는지, 호출·토큰 증가가 점수와 균형을 이루는지 확인한다. 현재도 80점 제출 기대 근거가 없어 ZIP은 만들지 않는다.

### 진행 중 확인한 활성 조건 누락

v0.9.0 C03 초기 실제 요청에서 성장 범위가 비활성임을 확인했다. “키가 또래에 비해 많이 작은” 같은 띄어진 표현이 짧은 키워드와 일치하지 않았다. 실행 중인 소스는 그대로 두고, v0.9.1에서 기존 그래프의 `short_stature` 주호소도 활성 조건으로 사용한다. 원문이 같아도 가족력·소견을 생성하는 것은 아니다. 따라서 v0.9.1은 필수 문장 예산 변경에 이 활성 조건 복구를 포함하며 완전한 단일 요인 실험은 아니다.

### 잘린 모델 응답 재시도

v0.9.0 C01에서 실제 `finish_reason: length`와 중간에서 끊긴 JSON을 확인했다. 다음 v0.9.1은 같은 행동 결정의 최대 3회 검증 시도 안에서, 잘림 이후에만 max_tokens를 max(기존 한도, 3072)로 높인다. 다음 환자 턴에는 기본 2048로 복귀한다. 모델·추론 강도·세션 예산과 최종 기록 예산을 유지한다. 확대된 한도로도 전체 출력 예약 예산을 넘으면 호출을 거절한다. 무효 JSON은 계속 실행하지 않는다. 따라서 v0.9.1 비교는 상담 예산·성장 활성 조건·잘림 재시도 복구를 포함한 복합 후보다.

## 로그로 확인한 남은 구조 문제

v0.9.0 C10의 실제 턴 18에서 운동 시 숨참 정보가 반환됐다. 다음 STEP 요청에는 `meddb:dyspnea`·`meddb:exertional_dyspnea` 개념이 없었고, 최종 추출 사실에도 이 두 개념이 없다. 원문은 보존돼 있으나 동반 증상 후보로 연결되지 않은 상태다. 당시 `collection_coverage.secondary_complaint`는 `palpitations`였다.

`ClinicalAdvisor.context`는 제한된 frontier와 상위 가설의 일부 supported/missing/opposed 개념만 보여 주며, `CoveragePlanner.secondary_complaint`는 한 번 선택한 동반 주호소 하나에 고정된다. 또한 `exertional_dyspnea`와 `dyspnea`는 서로 다른 ID인데 하위 증상에서 상위 주호소로 연결하는 명시적 관계가 없다. 따라서 지침에 심폐 관찰 필요성을 더해도 후보 접근 경로가 자동 보완되지는 않는다. 이 경로 결함은 확인됐으나, 수정 후 점수가 얼마나 변할지는 아직 미검증이다.

다음 구조 변경은 현재/운동 시·환자/가족 범위를 보존하면서 복수의 중요한 동반 증상을 후보에 노출하는 관계다. 단순 키워드로 양성을 생성하거나 안정 시 부정을 전체 호흡곤란 부정으로 확대하면 안 된다. 검토 모델이 여러 증상을 묶어 묻도록 제안한 부분은 그대로 구현하지 않는다. 대회의 한 번에 한 질문 원칙과 실제 부분 응답 범위를 우선한다.

v0.9.0 C03에서는 성장도표의 실제 반환에 이미 있는 성장속도·중간부모키를 턴 25의 다른 EXAM target으로 재요청했다. 같은 결과 의미를 가진 검사 target 간 관계가 없는 문제도 남았다. 원문 유지와 의미 기반 중복 방지는 별도다.

일부 최종 계획이 '신속히/결과가 나오면'에 머물면 필수 문장 예산 보호만으로 담당자·권고 시점을 만들 수 없다. 권고하는 추적 일정과 실제 예약 완료를 분리해 계획 생성 자체를 검증해야 한다. 가짜 예약이나 임의 환자 소견으로 빈칸을 채우지 않는다.
