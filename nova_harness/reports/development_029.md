# 29차 개발 보고 — 관찰 기반 감별 수렴 Shadow 엔진

2026-10-20 KST

## 구현 범위

`e2_convergence.py`는 매 턴 원본 E2의 실제 관찰 상태에서 다음을 결정론적으로 계산한다.

- 상위 5개 후보의 핵심·보조 지지근거, 반대근거, 미확인 핵심근거
- 1·2순위 근거점수 간격과 직전 snapshot 대비 안정성
- 미배제 위험질환, 상충, 약물·알레르기와 해당 연령·성별의 임신·수유 공백
- 원본 E2가 이미 만든 행동 후보의 후보분리·위험·계획 결정 효용
- 수렴 여부와 조건별 판정

`score`, `share`, margin은 보정된 진단확률이 아니다. `e2_convergence_shadow.py`는 이 계산을 `CareCoverage.needed()`에 붙이되 원본 action list를 그대로 반환한다. 따라서 1단계는 관찰·계측만 하고 진료 행동을 변경하지 않는다.

## 수렴 게이트

현재 shadow 게이트는 아래를 모두 요구한다.

1. 1순위에 관찰된 핵심 근거가 있다.
2. 1순위의 미확인 핵심근거가 없다.
3. 위험질환의 필수 배제 항목이 남지 않았다.
4. 핵심 상충이 없다.
5. 관련 안전정보가 확보됐다.
6. 두 연속 snapshot에서 1순위가 같고 margin이 0.25 이내로 유지·증가한다.
7. 근거점수 margin이 2.0 이상이다.

margin 2.0은 세 공개 로그의 shadow 동작을 관찰하기 위한 잠정 값이다. 질병 확률이나 임상 확진 기준으로 사용하지 않으며 능동 모드 전 추가 검증이 필요하다.

## 검증 결과

전체 단위·패키지 테스트 180개가 통과했다. 동일 입력의 snapshot 결정성, 명확한 반복의 비용, 상충 시 명료화 허용, 성별·연령별 안전정보, 두 snapshot 안정성, overlay 설치·복구와 원본 action list 불변을 확인했다.

이전에 정상 완료된 Evidence Ledger 세 증례를 저장된 판정과 함께 재생했다.

| 증례 | 관찰근거 | 최종 1순위 | 제출 진단 일치 | 최초 수렴 snapshot | 최종 margin |
| --- | ---: | --- | --- | ---: | ---: |
| C01 | 45 | 수면제 의존 | 일치 | 31 | 6.97 |
| C03 | 33 | 체질성 성장지연 | 일치 | 20 | 5.04 |
| C10 | 44 | 그레이브스병 | 일치 | 21 | 16.24 |

세 경우 모두 최종 미확인 핵심, 미배제 위험질환, 상충, 안전 공백이 0이었다. 같은 재생을 두 번 실행했을 때 전체 JSON과 증례별 trajectory SHA-256이 동일했다.

별도 세션 재생은 저장된 실제 API 요청·응답 64·46·73개를 원본 E2와 shadow E2에 각각 공급했다. 세 증례 모두 호출을 전부 소비했고 질문·진찰 순서, 생성 SOAP, 최종 진단 payload와 반환 결과가 완전히 동일했다.

## Live API 상태와 한계

C01 live shadow 실행을 두 번 시도했지만 모두 세션 생성 전에 `API_UNAVAILABLE` 6회로 실패했다. Doctor 요청·환자 행동·진단 제출은 0건이다. 이는 외부 API 상태이며 후보 성능으로 계산하지 않는다.

따라서 완료된 범위는 shadow 엔진 구현, 오프라인 실제 응답 재생, 결정성, 원본 행동 불변 검증이다. 능동 질문 선택과 수렴 시 조기 종료는 아직 구현 기본값으로 켜지 않았고, 개발 API·공식 점수 향상도 검증되지 않았다. API 복구 뒤 C01/C03/C10 live shadow를 먼저 통과한 후 기존 후보 안 선택 단계를 별도 실험해야 한다.
