# 39차 개발: R3c 생성 역할·R4 LangGraph 통합

2026-10-21. 사용자가 오늘 서버 검증 1회만 남아 남은 단계 전체 구현과 최종 제출 ZIP을 요청했다. 기존 단계별 서버 결과 대기 방침을 이번 승인으로 대체한다. 단계별 커밋·ZIP을 보존하되 사용자가 제출할 파일은 **`submission_R4_langgraph_final.zip`** 한 개다. 업로드·병합은 실행하지 않는다.

## 변경 범위

R3b 검색 요청 작성, R3a 근거 적합성 선별, R2 검색, R1 인덱스·LSA 임베딩을 유지한다. R3c는 기존 기록 생성 요청에 별도 생성 역할을 추가한다. 실제 관찰과 지침 구분, 미확인·부분 부정·시간·약물 정보 보존, 조건부 치료·안전·추적 계획, 교육 계획과 실제 수행 구분을 명시한다. 기존 JSON 스키마와 생성 재시도 한도는 유지하며 추가 Doctor 호출은 없다. 이후 짧은 설명이 사용하는 P 필드 앞부분에 중요한 행동·목적을 쓰도록 요청하지만 실제 전달 성공을 보장하지 않는다.

R4는 기록 단계만 다음 로컬 LangGraph로 조율한다.

`관찰 문맥 → 검색 요청 작성/검색 → 후보가 있으면 적합성 선별 → 기록 생성 → 형식·인용 감사 → 종료`

검색 요청과 선별은 원래의 호출 상한·시간 제한·실패 복귀를 유지한다. 후보가 없으면 선별을 건너뛴다. 감사는 SOAP 섹션·진단 존재와 선별 ID 대비 인용 ID를 검사해 로그에 남기며 임상 사실 검증·자동 수정·추가 생성은 하지 않는다. 진료 전체 문진 루프·다음 질문 정책·종료 정책은 변경하지 않았다. 진단 확률 보정이나 능동 수렴도 추가하지 않는다.

그래프는 동시 실행 수 1·재귀 한도 8, 체크포인터 없음으로 실행한다. 원격 추적을 비활성화하고 저장소·외부 그래프 서버를 쓰지 않는다. 그래프 작업 스레드에서도 기존 SQLite FTS 검색을 사용할 수 있도록 같은 행의 연결만 스레드 읽기 허용으로 구성한다. 검색 점수·후보·정렬은 바꾸지 않는다.

## 의존성·환경

LangGraph 1.0.3과 전이 의존성 전체 및 NumPy 2.2.6을 포함해 39개 패키지를 버전 고정했다. Linux x86_64 Python 3.12용 binary wheel만 사용한 전체 해석·다운로드가 성공했다. 이 목록만 설치한 별도 macOS Python 3.12 환경에서도 `pip check`, 최종 ZIP 독립 prepare, 그래프 설치·복구를 통과했다. Linux Docker 실행이나 공식 빌드 성공을 확인한 것은 아니다. ZIP에 의존성 wheel을 중복 포함하지 않고 서버가 고정 requirements로 설치한다.

## 재현 검증

- `.venv-rag/bin/python -m unittest discover -s tests -q`: 201개 통과. 그래프 실제 실행·후보 없음 분기·생성 1회·원래 함수 복구·외부 추적 차단을 확인했다.
- `python3 -m unittest discover -s tests -q`: 201개 실행, 선택 LangGraph 의존성이 없는 기본 환경에서 그래프 테스트 2개는 건너뜀.
- `tools/replay_rag_r4.py`: 세 저장 증례에서 유효/무효 합성 검색 요청·선별을 각각 사용해 R3c/R4 6쌍(12회 진료)을 비교했다. 모델 요청 내용·토큰 상한·행동 순서가 동일하고 저장 응답을 모두 소비했다. 집계는 `reports/langgraph_parity_039.json`에 있다. 합성 판단과 저장 모델 응답을 썼으므로 새로운 임상 정확도·점수 실험이 아니다.
- ZIP CRC·50,000,000바이트 제한·독립 prepare를 확인했다. R3c→R4는 `run.py`, `requirements.txt` 변경과 `nova_agent/rag_graph.py` 추가뿐이다. ZIP의 현재 모듈과 API 검증에 사용한 로컬 모듈의 바이트가 같다.

## 공개 증례 개발 API

통합 R4로 C01/C03/C10 각 1회가 모두 정상 종료했다. 집계는 `reports/live_rag_039.json`에 있으며 원문은 로컬 results에만 보존한다. 공식 서버 샘플·리더보드 점수 측정이나 제출 횟수 사용은 아니다.

| 증례 | 최대 턴 | 시간(초) | Doctor 성공/시도 | 요청/선별 시도 | 생성 역할 적용 | 실제 근거 문맥 요청 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| C01 | 45 | 371.875 | 22/22 | 1/2 | 2 | 1 |
| C03 | 33 | 231.730 | 15/16 | 1/1 | 1 | 0 |
| C10 | 45 | 311.080 | 29/29 | 1/1 | 1 | 1 |

C01 첫 기록에서 장기 복용·금단 관련 지침 1개가 선별됐고 기존 기록 호출에 제공됐다. 이후 관찰이 추가된 최종 기록에서는 요청 작성 상한에 따라 원래 질환명 검색으로 복귀했고 후보가 uncertain/rejected라 근거 미사용으로 완료했다. 따라서 첫 주입이 최종 기록에서도 유지됐다고 주장하지 않는다. C01에서 기존 진찰 요청이 `EXAM_NOT_SPECIFIC`으로 2회 거절됐다. 이 정책은 R4 변경 범위 밖이며 일반 질문·진찰 최적화 과제로 남는다.

C03은 소아에게 맞지 않는 골다공증·근감소증 문서를 모두 거절했다. 기록 생성 이후 마무리 설명의 1536토큰 요청에서 `PROVIDER_RESPONSE_INVALID` 1건과 출력 절단 1건을 확인했고 기존 복구 경로를 거쳐 종료했다. 생성 역할·그래프 오류로 확인된 것은 아니지만 설명 전달의 완전성·안전 점수 보존을 보증할 수 없다.

C10은 초기 갑상샘 평가 지침 1개를 통과시키고 이미 치료받은 환자 대상 발췌는 제외했다. 기록 요청 1회에 근거가 전달됐고 최종 기록의 허용 출처 ID 인용을 확인했다. API·행동 오류와 출력 절단은 없었다.

세 증례 모두 최종 그래프가 검색·선별·생성·감사를 완료했고 SOAP 섹션과 주진단이 존재했다. 최종 감사의 미확인 인용 ID는 0개였다. 감사는 추적된 출처 ID/형식 점검이며 문장별 임상 사실·최신 권고 검증을 대신하지 않는다. 진단 제출값은 C01 수면제 의존, C03 체질성 성장지연, C10 갑상샘항진증(그레이브스병)이었으며 별도 정답 판정은 하지 않았다.
