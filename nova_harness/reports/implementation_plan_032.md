# 32차 단계별 RAG 구현·공식 비교 계획

2026-10-21 KST

사용자가 단계별 개발·커밋·푸시·ZIP 생성을 승인했다. 각 ZIP의 공식 제출은 사용자가 수행하고, 결과를 함께 검토한 후 다음 단계로 진행한다. 네 단계 ZIP을 동시에 만들지 않는다.

## 기준과 변경 범위

원본 E2를 대조군으로 고정한다. D065의 동시점 대조군 측정은 계속 필요하지만 독립적인 RAG 개발 준비를 막는 조건으로 해석하지 않는다. 수렴 엔진의 능동 선택·조기 종료는 이번 범위에 넣지 않는다. 환자 관찰과 의료지식 검색 결과를 분리한다.

벡터 RAG에는 기본 검색이 필요하다. 따라서 1단계에 기본 코사인 유사도 검색을 포함하고 2단계는 검색 품질 개선으로 정의한다. 이 두 단계의 차이를 감추거나 중복 구현으로 설명하지 않는다.

## 1단계: 외부 지침 RAG 기반

- 공식 제공 임상 지침의 라이선스·원본 해시·메타데이터를 확인한다. 운영 규칙·공개 증례 정답·대본은 임상 검색 색인에서 제외한다.
- 절·권고·예외를 함께 유지하는 청킹을 구현한다. 청크 ID, 문서 ID, 출처, 버전, 대상, 절/행 위치, 원문 해시를 저장한다.
- 문서와 질의를 같은 임베딩 모델·정규화 규칙으로 변환한다. 인터넷 없는 CPU 실행, ZIP 50MB 및 메모리 제한에 맞는 로컬 모델과 벡터 저장소를 실제 검증 후 선택한다. 해시 벡터를 신경망 의미 임베딩으로 가장하지 않는다.
- 기본 코사인 검색으로 관련 근거를 얻고, 기존 최종 판단·치료·추적 계획 생성에 제한적으로 제공한다. 환자 사실이나 기존 안전 계획을 덮어쓰지 않는다. 다음 질문 정책은 변경하지 않는다.
- 검색 실패·부적합 결과 시 기존 흐름으로 복귀하고 출처·선택·실제 반영을 로그로 남긴다.
- 산출물 예정: `submission_R1_rag_baseline.zip`. 이름은 계획이며 현재 생성된 파일이 아니다.

## 2단계: 검색 품질 개선

1단계의 모델·청크·생성 프롬프트를 고정하고 적용 대상 필터, BM25와 벡터 후보 결합, 질의 구성·관련성 임계값을 비교한다. 한 번에 바꾸는 검색 요소를 기록한다. MMR은 중복 근거가 실제 병목일 때 별도 후보로 비교한다. 산출물 예정: `submission_R2_retrieval.zip`.

## 3단계: 세 역할 프롬프트

검색 요청 작성, 근거 적합성 선별, 근거 기반 계획·설명 생성을 분리한다. 관찰과 지침을 혼동하지 않도록 입력·출력 계약과 근거 ID를 연결한다. 매 환자 턴마다 세 호출을 강제하지 않고 필요한 시점에만 실행하며 재검색 상한·토큰·호출 예산을 둔다. 검색 인덱스는 2단계 채택본에 고정한다. 산출물 예정: `submission_R3_prompt_roles.zip`.

## 4단계: LangGraph로 실행 흐름 이전

채택된 검색·프롬프트·모델 설정을 고정하고 상태·분기·오류 복구만 LangGraph로 옮긴다. 저장 API 응답 재생에서 이전 구현과 행동·SOAP·진단 payload가 같은지 먼저 검증한다. 프레임워크 전환 자체는 점수 상승 가설보다 재현성·유지보수 실험이다. 산출물 예정: `submission_R4_langgraph.zip`.

## 공통 게이트

각 단계마다 의미 있는 단위·통합 테스트, 검색 근거 fixture, ZIP 허용 목록·CRC·독립 prepare·오프라인 실행 점검을 수행한다. Docker 미검증과 공식 미검증을 명시한다. 기능별 커밋과 보고서를 기존 브랜치·PR에 반영하고 ZIP·키·실행 원문은 Git에서 제외한다.

공식 비교는 같은 공개 증례·가까운 시점 대조군 기준으로 총점, 6영역, 턴·시간·실패를 기록한다. 가능하면 같은 ZIP 반복으로 변동을 확인한다. 안전·진단 하락이나 실행 실패가 생긴 후보는 자동 누적하지 않고 직전 채택본으로 되돌린다. 정보수집·의사소통 향상은 검색 근거가 실제 질문/설명에 반영됐는지와 함께 해석한다. 사용자가 단계 결과를 공유하기 전 다음 단계의 제출 후보를 확정하지 않는다.
