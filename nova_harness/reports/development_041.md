# 41차 개발: 안전 계획·실제 발화·최종 SOAP 비교와 S1 수정

최신 결론: 개발 키 인증은 정상이다. R3a/R3b에서 공통된 계획→발화 손실과 교육 수행 기록 불일치를 확인해 R3a 기반 S1을 구현했다. 테스트 222개, 세 증례 전체 API 및 C10 경계 추가 회귀를 완료했다. 마지막 기록 표현 사전 수정은 단위/20개 기록 재생으로 검증했다. **공식 점수·전체 의미 완전성은 미확인으로 제출 권장본은 아니다.** 중간 실패도 집계에서 숨기지 않는다.

2026-10-22. 사용자 승인으로 숨김 키 입력 명령을 열고 개발 API 인증을 확인했다. 키·토큰·원문 로그·증례 정답/대본은 Git과 제출 ZIP에 넣지 않는다. 첫 터미널 실패 뒤 재실행했고 실제 인증 요청은 성공했다. 인증 실패, 모델 빈 응답/절단, 진찰 거절, 프록시 오류를 구분한다.

## 비교 설계와 범위

R3a/R3b 원본 코드는 동결했다. `SafetyTimeline`은 각 실제 기록 반환값, 성공한 SAY와 환자 응답, 실패한 행동, DIAGNOSE에 실제 넘기는 최종 SOAP를 보존한다. 계측 자체는 입력·의학 계획을 변경하거나 모델을 호출하지 않는다. 원문 타임라인은 로컬 results에만 있다.

두 종류의 실험을 구분했다.

1. 같은 저장 관찰로 기록 직전 상태를 복구하고, 새 Doctor API로 R3a/R3b의 검색·선별·기록·설명을 생성한다. 해시로 관찰 동일성을 확인한다. 여기서 생성한 설명은 **미전달 제안**이며 환자에게 실제 말했다고 간주하지 않는다. 첫 실행은 저장 세션 기한을 잘못 사용해 검색 역할이 생략됐으므로 검색 효과 비교에서 제외했다. 수정 실행은 두 군에 같은 새 30분 비교 시각을 적용했다. 순차 1회 비교라 응답 변동·순서 효과가 남는다.
2. 실제 C01 환자 API 세션을 R3a/R3b 각각 1회 실행하고 계획·발화·최종 기록을 대조했다. 두 실행에서 환자와의 질문/응답이 달라질 수 있으므로 동일 관찰의 인과 비교로 간주하지 않는다.

개발 검토자 `openai/gpt-6.1-sol`은 공식 점수를 매기지 않고 원문 계획·성공 발화·최종 P만 검토했다. 인용과 발화 index는 코드로 확인했지만 의미 판정은 모델 의견이며 임상 정답·전문가 검증을 대신하지 않는다. 런타임 Doctor는 계속 `openai/gpt-6-luna`다. 검토 모델·정답 자료는 ZIP에 없다.

## 확인된 사실

- 실제 C01 R3a와 R3b 모두, 계획에 있던 임의 증량·갑작스러운 중단·운전·음주/진정제 병용 주의 중 일부를 의사가 말하지 않았는데도 최종 교육에 설명/안내 완료로 기록했다. 환자의 자발적 감량 약속을 의사의 금지 행동 설명으로 대신할 수 없다.
- C01 고정 관찰의 유효 시간 조건 비교에서는 R3a 선별 1회, R3b 요청 1회·선별 1회였고 모두 최종 전달 지침 0개였다. **기록 생성의 실제 메시지 해시도 같았다.** 그런데 R3b 실행은 구체적 추적·위험 설명을 일반 문장으로 대체했다. 이 실행 차이를 검색 근거의 임상 내용 차이로 설명할 수 없다. 동일 프롬프트에서도 생성·길이 검사 결과가 달라질 수 있다.
- 기존 C10 실제 Doctor 출력의 안전 필드는 23자와 28자의 완결된 두 문장이었지만 합산 30자 제한에 걸려 통째로 일반 경고로 바뀌었다. 같은 저장 모델 응답을 재사용한 재생에서 원본은 두 문장을 모두 잃었고 수정은 두 문장을 추가 모델 호출 없이 보존했다. 이는 특정 코드 경로 개선의 직접 검증이며 서버 점수·실제 새로운 전달 성공 실험은 아니다.
- 설명 후 관찰이 바뀌어 기록을 재생성하면 원래 계획의 조건·시점도 바뀔 수 있었다. 기존에는 이전 계획과 실제 발화를 명시적으로 대조하는 입력이 없었다.

R3a도 안전 전달이 완전한 기준이 아니다. 이전 샘플 안전 15를 반복 안전성으로 일반화하지 않는다. 이번 관찰만으로 40차 서버 감점 원인·증례를 확정하지 않는다.

## S1 구현

S1은 동결 R3a에만 추가한다. R3b 검색 요청 작성·R3c 전체 생성 역할·R4 LangGraph는 채택하지 않는다. 수집·진찰·종료와 원래 진단 선택 정책은 유지하지만 기록 재작성 입력·마무리 설명 입력이 보강되어 생성되는 내용은 달라질 수 있다.

- 기존 계획 전체를 설명 입력으로 제공하고 중요한 금지 행동·구체적 위험 증상/대응·원래 추적 조건을 보존하도록 요청한다. 새 진단·처방·수치·시점 생성을 금지한다.
- 한 필드의 여러 완결 문장을 각각 30자 이하 SAY로 전달한다. 긴 문장을 잘라 실행하지 않는다. 하나의 그룹은 턴 예산 때문에 중간에서 자르지 않으며 전달 불가·미해결 필드를 계측한다.
- 잘린 JSON에서도 완전히 닫힌 문자열 필드만 회수한다. 부분 안전 문장을 이어 붙이거나 내용이 없는 구간을 사실로 채우지 않는다.
- 안전/추적 필드가 없으면 한 번만 근거 계획 기반 복구를 시도한다. 각 문장 30자, 최대 두 문장, 실제 P의 정확 인용·새 수치 금지·120초 시간 조건을 검사한다. 이는 출처/형식 검사이고 임상적 의미 보존의 증명은 아니며 실패는 기존 경로와 미해결 로그로 남긴다.
- 설명 제안 후에도 원문 계획 대비 중요한 조건·금지·위험 증상/대응 누락을 한 번 점검한다. 실제 P 인용 검증을 통과한 원본 최대 2문장을 점검하고, 30자 그룹 분리 후에는 남은 턴 안에서 최대 4개 메시지를 허용한다. 이는 개발 검토에서 발견한 C03 경고 누락을 반영한 추가 수정이다. 모델의 의미 판정은 오류가 가능하므로 공식 안전성 증명으로 간주하지 않는다.
- 기록 재작성에는 이전 계획과 성공한 발화 목록을 참고 자료로 제공한다. 새 실제 관찰이 조건을 바꾸지 않으면 안전·금지·추적을 보존하고, 변경 시 근거와 차이를 명시하도록 요청한다. 이전 계획을 새 환자 관찰로 승격하거나 기계적으로 합치지 않는다.
- 최종 P.education은 교육 계획과 실제 수행 목록을 분리한다. 초안의 일반적인 설명/안내/교육 완료형은 계획형으로 바꾸고, 실제 수행 부분에는 성공한 의사 SAY만 정확히 열거한다. 실패한 SAY와 환자의 자발적 약속은 수행으로 올리지 않는다. 이해 확인은 실제 응답을 인용하며 이해 완료를 추론하지 않는다. S/O/A는 바꾸지 않고 P의 의료 조치·조건·수치는 유지하며 지정한 교육 완료형 표현만 계획형으로 정리한다.

완료형 정리는 지정한 한국어 표현을 대상으로 하며 모든 문장의 의미를 완벽히 분류하는 온톨로지 엔진은 아니다. 기록 전체의 임상 사실성이나 모든 필수 안전 안내의 자동 보장을 주장하지 않는다.

## 추가로 발견한 생성 예산 문제

기본 추론 강도에 기존 1,536토큰 한도를 둔 중간 후보에서 C03 설명 생성이 PROVIDER_RESPONSE_INVALID 8회 연속 실패했고 577.558초 뒤 복구·종료됐다. 기존 with_retry는 같은 조건의 모델 빈 응답을 최대 8회 재요청했다. 이는 인증 오류가 아니며 내부 추론 토큰이 원인이었는지 직접 확인한 것은 아니다. 1,536/기본 설정에서 반복 실패한 경로와 시간 낭비는 확인됐다.

낮은 추론 강도 수정 후 C03은 33턴·211.483초·오류/절단 0건으로 종료했으나, 형식상 완성된 안전 설명에도 원문 경고 일부가 빠져 있었다. 따라서 형식 복구만으로 충분하다고 판단하지 않고 원문 계획 대비 누락 검사까지 추가했다. 해당 실행은 최종 누락 검사 버전과 합치지 않는다.

최종 S1은 설명 호출만 reasoning_effort=low를 명시한다. 설명 빈 응답은 비재시도 로컬 오류로 기존 설명 생성 경로에 알린 뒤 최대 한 번의 근거 복구로 넘어간다. 다른 모델 역할·환자 행동의 재시도 정책은 바꾸지 않는다. 실패 버전과 이 수정 후 실행을 소스 해시로 분리하고 다시 검증한다.

## 검증

전체 테스트 222개 통과. 기본 Python에서는 선택 LangGraph 테스트 2개를 건너뛰고, 개발 의존성 환경에서는 모두 통과했다. 관찰 스냅샷·실패 발화 제외, 출처 ID/인용 조작 거절, 두 완결 문장 보존·단일 긴 문장 비절단, 잘린 JSON의 부분 문장 거절, 복구의 새 용량·없는 출처 거절, 실제 발화와 교육 계획 분리·원래 note 불변·함수 복구를 검증했다. 저장 경고 재생 집계는 `closing_replay_041.json`에 있다.

S1 ZIP은 독립 prepare/install/restore·CRC·50MB·허용 목록을 통과했다. 추가 패키지는 없고 R3a의 NumPy 요구사항을 유지한다. Docker·서버 점수는 미검증이다.

## 실제 API 최종 집계

R3a C01 44턴·321.308초, R3b C01 45턴·332.156초로 정상 종료했다. R3a는 HTTP 502의 INVALID_API_RESPONSE 1건, R3b는 EXAM_NOT_SPECIFIC 1건이 있었다. 개발 검토의 분류 수는 독립 항목 수·발화 차이가 있어 두 버전의 점수처럼 비교하지 않는다.

전달 복구·형식 검사·낮은 추론 설정·누락 검사 보강 과정을 구분해 당시까지 총 16개 진료 세션을 기록했다(이후 동결본 검증·C10 회귀까지 최종 20개). 중간 실행은 최종 결과와 합치지 않는다. 집계는 `safety_metrics_041.json`, 고정 관찰 비교는 `paired_safety_041.json`에 있다. 원문 로그·모델 출력·응답은 공개하지 않는다.

정확한 원문 범위·조건 목록 분리까지 적용한 마지막 API 검증 3건은 다음과 같다. **이 실행들은 마지막 한국어 출력 검사와 다른 P 필드의 교육 완료형 정리 전이다.** 최종 ZIP과의 소스 차이는 `safety_format_revision_041.json`에 기록했고, 이 후처리를 새 전체 API 제출로 검증했다고 주장하지 않는다.

| 증례 | 최대 턴 | 시간(초) | Doctor 성공/시도 | API/행동 오류 | 출력 절단 |
| --- | ---: | ---: | ---: | --- | ---: |
| C01 | 50 | 316.969 | 22/22 | EXAM_NOT_SPECIFIC 2 | 0 |
| C03 | 37 | 258.433 | 17/17 | 없음 | 0 |
| C10 | 47 | 328.241 | 30/30 | 없음 | 0 |

세 실행 모두 정상 종료했고 빈 Doctor 응답은 없었다. 각 증례에서 누락 검사로 2개의 보충 문장이 제안되고 실제 SAY 성공을 확인했다. C01은 혼자 약을 끊거나 용량을 바꾸지 않기, 졸릴 때 운전/위험 작업 회피, 음주/진정제 병용 회피가 실제 전달됐다. C03은 처음의 일반적인 경고 뒤 구체적인 두통·구토·시야 변화와 팔다리 위약/감각 이상 경고를 실제 전달했다. C10은 고열·의식 변화·흉통·호흡곤란의 즉시 응급 대응과 검사 전 임의 약 시작 금지를 실제 전달했다. 이는 이 실행의 실제 전달 확인이며 내용 전체의 임상 적절성·완전성 판정은 아니다.

검토 모델의 마지막 분류는 C01 covered 6/partial 4, C03 covered 3/partial 3/missing 4, C10 covered 3/missing 7이었다. 최종 계획 보존 분류는 각각 preserved 9/changed 1, preserved 10, preserved 8/changed 2였다. 해당 세 검토에서 실제 발화 근거 없는 수행 완료 주장은 0건으로 분류됐다. 항목은 실행마다 다르고 우선순위도 전문가가 검증하지 않았으므로 이 수치를 점수·버전 순위·안전성 보증으로 사용하지 않는다. 여전히 추적 조건·설명의 세부 누락이 남아 있다.

마지막 C10 실제 출력에는 일본어 검사 안내가 한 문장 포함됐다. 이 사실을 숨기지 않고, 한국어가 없거나 일본어 가나가 포함된 생성 설명을 차단하고 기존 한국어 기본 안내로 돌아가는 후처리를 추가했다. 완성된 문장과 인용을 복구했다고 언어·의미 전체가 적절해지는 것은 아니었다. 한국어 필터는 원문 재생/단위 검증을 통과했지만, 뒤따르는 누락 검사 입력도 바꿀 수 있어 당시에는 해당 출력 검사까지 포함한 새 전체 API 결과가 없었으므로 아래 동결본 검증을 추가했다.
