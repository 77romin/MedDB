# 21차 개발 보고 — E2 Evidence Ledger와 SOAP 완전성 감사

2026-10-20. 사용자가 승인한 `reports/implementation_plan_020.md`를 구현했다. 목적은 원본 E2의 질문·진찰·진단 정책을 바꾸지 않고, 긴 대화에서 성공한 SAY/EXAM 관찰근거가 최종 SOAP에서 조용히 사라지는 일을 막는 것이다.

## 구현

- `e2_evidence_ledger.py`: 성공한 SAY/EXAM의 턴, 임상의 발언, 실제 응답·진찰 결과를 append-only 원장에 기록한다. 실패는 임상 근거와 분리한다.
- `e2_tracking_client.py`: 원본 client를 투명하게 감싸고 `diagnose()` 직전에 SOAP를 대조·보완·감사한다.
- `e2_soap_router.py`: target과 질문 의미에 따라 HPI/PMH/FH/SH/O.exam/P.education으로 결정론적으로 보낸다. 중복·상충·비임상·길이 제외에는 사유를 남긴다.
- `e2_soap_audit.py`: 모든 원장 항목의 처리 상태, 중요 진찰 제외, 계획 교육과 실제 전달의 분리를 확인한다. 완전성 조건을 통과하지 못하면 제출 호출을 막는다.
- `e2_ledger_overlay.py`: 원본 E2의 `base_consult`와 `CareCoverage`에 가역적으로 설치하고 종료 후 원래 객체로 복구한다.

원본 SOAP가 실제 SAY 없이 `교육함`, `안내함`으로 기록한 문장은 삭제하지 않고 `교육 계획(실제 전달 여부 미확인)`으로 명시한다. 성공한 SAY 목록과 환자 질문·teach-back·안전계획 확인만 실제 의사소통 근거로 구분한다.

## 개발 API 관찰

Doctor는 `openai/gpt-6-luna`이고 세 실행 모두 정상 종료했다. 아래는 공식 점수가 아니라 공개 개발 증례의 실행·원장 감사 결과다.

초기 C01 로그에서는 마무리의 단순 수용 답변이 HPI를 부풀렸다. 1차 보정으로 단순 동의·중복을 제외하고 환자 질문과 teach-back을 P.education으로 이동했다. C03·C10까지 확인한 뒤에는 `검사로 확인할 수 있나요?`가 단순 수용으로 빠지고 안전 이행 답변이 HPI에 들어가는 오분류를 추가 발견했다. 최종 라우터는 설명 뒤 환자 질문과 안전계획 확인을 P.education에 보존한다.

최종 라우터는 저장된 세 실행의 제출 직전 SOAP와 ledger를 오프라인 재생했다. 총 122개 근거 모두 disposition이 지정됐고 unresolved 0, 중요한 EXAM 제외 0, 교육 계획/실제 전달 미분리 0이었다. 진료 행동과 진단 문자열은 저장된 실행 그대로 유지했다. 이 재생은 결정론적 기록 계층 검증이며 새 API 실행이나 공식 채점은 아니다.

## 판단과 남은 검증

구조 채택 기준인 포착률·처리율 100%, 무사유 중요 누락 0, 비정상 종료 0, 진단 불일치 0은 공개 세 증례에서 충족했다. overlay는 환자 행동을 추가하지 않으며 Doctor를 호출하지 않는다. 실행별 Doctor 호출 수 차이는 원본 E2의 기존 흐름과 모델 변동이며 ledger가 만든 호출이 아니다.

아직 제출 권장 후보는 아니다. SOAP가 길어져 평가 효율이나 의사소통 점수에 미치는 영향은 개발 API로 측정할 수 없고, 공식 샘플에서 원본 E2의 안전 15점·효율 19.42점을 보존하는지 확인하지 않았다. 제출 ZIP도 이번 단계에서는 만들지 않는다. 다음 단계는 패키징 경로를 명시적으로 추가하고, 키·원문 audit 로그 제외를 검사한 뒤 사용자가 요청할 때 공식 샘플 비교용 ZIP을 만드는 것이다.
