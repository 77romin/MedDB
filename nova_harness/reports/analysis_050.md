# 50차: 구조 결함을 드러내는 엣지케이스와 실제 재현

## 목적과 범위

사용자가 현재 구조의 문제를 엣지케이스로 찾자는 접근을 제안했다. 새 프롬프트나 런타임을 고치지 않고 실제 코드의 관련 함수에 합성 입력을 넣어 관찰→상태/질문→발화 경계의 실패를 조사했다. 실행 도구는 `tools/probe_structural_edges.py`, 전체 결과와 실행 소스 해시는 `reports/structural_edges_050.json`이다. API·공개 정답·대본은 사용하지 않았다.

12개 진단 프로브 중7개는 명시한 기대 동작을 충족하지 못했고5개는 충족했다. 서로 다른 버전/구성요소를 포함하므로7/12를 현재 에이전트 오류율이나 임상 성능으로 표현하지 않는다. 기대값은 간단한 문장의 대상·시점·부정 범위에 대한 작성자 기준이며 독립 임상 골드셋이 아니다. 실패 항목을 expected-failure로 숨기거나 기존 회귀 테스트의 통과 수에 합산하지 않는다. 두 번 실행한 집계 파일은 바이트가 같았다.

## 재현한 결함

| ID | 합성 입력/조건 | 기대 | 실제 | 위치 |
|---|---|---|---|---|
| E01 | 복통 질문에 “설사는 없어요” | 복통은 미확인 | 복통 없음(-) | E2 read_answer |
| E02 | 현재 설사 질문에 “예전에는 있었지만 지금은 없어요” | 현재 없음(-) | 있음(+) | E2 read_answer |
| E03 | “거의 없어요” | 완전한 부재로 확정하지 않음(?) | 없음(-) | E2 read_answer |
| E04 | “아니요, 없다는 뜻이 아니라 설사가 있어요” | 명시된 설사 있음(+) | 없음(-) | E2 read_answer |
| E05 | “어머니는 두근거림이 있어요” | 환자 본인 증상으로 등록하지 않음 | 환자 palpitations 양성 | E2 Tracker.note_seen |
| E06 | 수면 시간에 “잘 모르겠어요” | 보충 확인 기회 유지 | 기존 required 후보에서 제외 | 원본 CareCoverage |
| E12 | 원안/생성 결과에 구체적인 조건·즉시 행동 경고가 있으나30자 초과 | 조건·긴급성을 발화 준비 과정에서 보존 | 일반적인 “더 힘들면 진료”로 교체 | 원본 E2/R3a closing helper |

E01은 질문과 답변의 주제가 어긋난 경우다. 짧은 부정어를 발견했다고 질문의 target을 음성으로 확정하면 안 된다. E02는 YES 접두의 '예'가 '예전'에도 맞는 실제 단축 경로를 통과한다. E03은 빈도 제한을 절대 부재와 구분하지 못하고 E04는 답변 전체의 정정 의미보다 첫 부정어를 따른다. 모두 이번 입력에서는 모델 호출 전에 결과가 결정됐다.

E05는 가족의 양성 정보를 환자 소견으로 옮기는 대상 범위 결함이다. E06은 시도/응답 수신과 정보 확보를 구분하지 못하는 원본 경로의 결함이다. E12는 합성 모델 출력을 주입한 실제 마무리 준비 함수를 실행한 것으로 실제 환자에게 전달됐다는 뜻은 아니다. S1/S3의 복구 기능 전체 실패를 검증한 것도 아니다.

## 이미 방어되는 경로

| ID | 사례 | 결과/범위 |
|---|---|---|
| E07 | E06과 같은 모호한 수면 답변을47차 상태 관리에 입력 | 제한된 명확화 후보 유지 |
| E08 | 과거 기침 경험을 현재 지속 target에 연결 |49차 연결기 보류 |
| E09 | 기간·현재 범위가 같은 기침 질문 표현 변형 |49차 연결기 chronic_cough 연결 |
| E10 | 빈도 제한을 추가한 설사 질문을 일반 설사와 연결 |49차 연결기 보류 |
| E11 | SAY가 성공 관찰 전에 실패 |TimelineClient의 성공 발화0 |

모든 계층이 실패한다고 결론내리지 않는다. E06은 원본의 결함이지만 E07은 이미 후보에서 보완됐다. E09는 합성 질문 연결 함수의 동작으로49차 live 양성 연결 효과를 새로 입증한 것이 아니다.

## 구조적 원인과 다음 개발 단위

1. **질문-답변을 원자 관찰로 해석하는 경로가 없다.** 현재 E2는 답변 앞부분/단어로 +/-/?를 먼저 정하고, 이후 별도 note_seen이 같은 원문을 키워드로 다시 해석한다. 대상·시점·빈도·부분 부정·정정의 의미가 두 경로에서 일관되지 않을 수 있다. E01–E05는 이 경계를 직접 드러낸다. 다음 개발은 단어 예외를 더 추가하는 대신 관찰의 대상/시점/속성/값/부정 범위/원문 출처를 함께 표현하고 상태 갱신을 한 경로로 처리하는 것이다. 기존 PatientState 계열도 검사·재사용하되 과거 하네스 저득점 때문에 재사용만으로 개선을 주장하지 않는다.
2. **완료 기준이 질문 단위에 치우친다.** 약물 여부·약 이름·용량·횟수·기간을 각각 관리하고 일부만 답한 경우 나머지를 미확인으로 남겨야 한다. E06–E07은 일부 후보가 이미 구분하는 범위를 보여준다. 이 결과를 모든 복합 문진의 해결로 일반화하지 않는다.
3. **계획과 발화가 분리된 생성 경로다.** 원안의 조건·행동·긴급성을 독립적인 계획 객체로 유지하고 실제 성공 발화 및 SOAP가 이를 각각 참조해야 한다. E12에서 확인한 준비 단계 손실과, 별도로 이미 관찰한 미발화 수행 주장 문제를 분리 검증한다.

현재 최종 E2 기록 생성에는 전체 transcript가 전달된다. 위 중간 상태 오류가 있어도 모델이 원문을 보고 최종 기록에서 바로잡을 수 있다. 반대로 다음 질문 선택은 잘못된 중간 상태의 영향을 받을 수 있다. 따라서 이번 함수 수준 재현을 최종 SOAP 오류나 공식 감점 원인으로 단정하지 않는다. 다음에는 같은 합성 세션을 끝까지 실행해 다음 행동·최종 기록까지 연결하는 통합 검증을 해야 한다.

## 추가 도출한 순차 엣지케이스 — 아직 미실행

| 계열 | 입력/상황 | 확인할 불변조건 |
|---|---|---|
| 복합 문진 | 우울/흥미저하 중 하나만 답변 | 나머지는 미확인, 전체 음성으로 처리하지 않음 |
| 조건부 증상 | 약 복용 시와 미복용 시 수면 상태가 다름 | 두 조건·시점을 보존하고 하나로 덮어쓰지 않음 |
| 약물 세부 | 약 이름은 모르고2알 복용만 앎 | 약 이름/mg/횟수/기간 미확인 유지,2알을2mg으로 바꾸지 않음 |
| 자기정정 | 이전 수치나 병력을 명시적으로 정정 | 이전 이벤트 보존, 정정 근거와 현재 유효값 연결 |
| 후기 위험 응답 | 설명 중 새 위험 증상/알레르기 확인 | 기존 계획 적용 가능성을 재검토하고 변경된 안내를 실제 전달 |
| 계획 버전 | 표현만 바뀐 계획 vs 행동/시점이 바뀐 계획 | 같은 임상 의무와 변경된 의무를 구분, 완료 자동 승계 금지 |
| 턴 경계 | 조건+대처 설명 그룹보다 남은 턴이 적음 | 중간 절을 전달 완료로 간주하지 않고 미전달을 명시 |
| 전송 경계 | 서버 처리 후 응답만 유실 | 같은 요청 ID 재시도와 실제1회 수행/턴을 구분 |
| 늦은 대화 | 중요한 근거 뒤60줄 이상 대화 | 질문 선택 문맥과 최종 기록 양쪽에 필요한 근거 보존 |
| 근거 부재 | 모델/검색 실패·확인하지 않은 진찰 | 정상/음성/시행 완료를 만들어내지 않음 |

이 표는 설계 목록이며 테스트 통과나 실제 재현이라고 표현하지 않는다. 공개 증례 정답에 맞추기보다 같은 의미를 다르게 표현한 변형과 의미가 달라지는 최소 변형을 쌍으로 만들고 평가한다.

## 판단

엣지케이스로 구조를 진단하는 접근이 현재 단계에 적절하다. 다음 우선순위는 관찰 해석의 단일화(E01–E05)와 계획→발화 손실(E12)이며 이미 방어된 E07–E11에 어미 예외를 더 붙이는 작업은 우선하지 않는다. 이번에는 런타임 수정·새 모델/API 실행·새 ZIP·공식 업로드를 하지 않았다. 합성 재현은 실제 대회 점수 개선의 증거가 아니며, 수정 후에는 이 동일 사례와 변형·전체 세션·동시점 대조·공식 샘플을 순서대로 확인해야 한다.
