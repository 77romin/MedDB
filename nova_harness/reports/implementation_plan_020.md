# 구현 계획 20차 — E2 Evidence Ledger와 SOAP 완전성 감사

2026-10-20. 목표는 긴 대화에서 초기에 얻은 임상정보가 SOAP에서 조용히 소실되는 문제를 막는 것이다. 원본 E2의 공식 샘플 77.714점 경로를 기준으로 유지하고, 질문 정책이나 진단 로직을 동시에 바꾸지 않는다.

## 설계 원칙

모든 성공한 SAY·EXAM 결과를 append-only Evidence Ledger에 보존한다. 모든 근거를 SOAP에 그대로 나열하지는 않는다. 각 근거는 제출 전에 `included`, `duplicate`, `nonclinical`, `superseded`, `conflict`, `excluded_with_reason` 중 하나의 처리 상태를 가져야 한다. 중요한 임상 근거가 아무 이유 없이 사라진 상태에서는 제출하지 않고 결정론적 fallback으로 보완한다.

계획과 수행을 구분한다. 검사는 P의 계획일 수 있지만 O의 결과가 아니다. 교육 계획은 P에 남길 수 있으나 실제 설명 완료는 성공한 SAY 원문이 있을 때만 별도 표시한다. 상충 답변은 최신 답 하나로 조용히 덮어쓰지 않고 두 원문과 재확인 필요 상태를 보존한다.

## 구현 모듈

### 1. `e2_evidence_ledger.py`

- `LedgerEntry`: evidence_id, turn, action, clinician_text, patient_or_exam_text, target, source_kind, communication_tag.
- 성공한 `client.say`와 `client.exam`만 원장에 추가한다.
- 거절·전송 실패는 임상 근거가 아니라 별도 오류 사건으로 기록한다.
- `CareCoverage.observe`와 연결해 동일 턴의 자유응답에 target과 SOAP section을 후첨한다.
- 원문은 수정하지 않고 정규화 값은 별도 필드에 둔다.

### 2. `e2_tracking_client.py`

- 원본 E2에 전달되는 client를 proxy로 감싼다.
- `session`, `chat`은 그대로 위임한다.
- `say`, `exam`의 성공 응답을 ledger에 기록한다.
- `diagnose(note, diagnosis)` 직전에 SOAP 완전성 감사를 호출한다.
- API request ID·재시도 의미는 원본 SDK에 맡겨 턴 중복 소비를 만들지 않는다.

### 3. `e2_soap_router.py`

- target이 확인된 문진은 온톨로지/coverage의 SOAP field로 결정론적으로 보낸다.
- 가족 대상은 FH, 약물·과거력·알레르기는 PMH, 생활력은 SH, 현 증상은 HPI/ROS로 보낸다.
- target이 없는 임상 응답은 HPI의 `미분류 관찰근거`에 원문과 턴을 남긴다.
- 인사, 단순 동의, 이해 확인 응답은 병력에서 제외하되 처리 사유를 기록한다.
- 모든 실제 EXAM 결과는 O.exam에 원문·턴과 함께 보존한다.
- 같은 질문의 같은 답은 duplicate로 표시하고 한 번만 렌더링한다.
- 다른 답은 conflict로 두 원문을 보존하며 정상/음성으로 합치지 않는다.

### 4. `e2_soap_audit.py`

- ledger의 모든 항목이 SOAP 또는 처리 목록에 존재하는지 검사한다.
- 검사 계획을 시행 결과로 쓴 경우, 미확인 사실을 음성으로 쓴 경우, SAY 없는 교육을 완료로 쓴 경우를 탐지한다.
- 필드 길이 제한이 예상되면 인사·중복·비임상 응답부터 제외하고 이유를 남긴다.
- 핵심 약물 노출, 위험증상, 기능손상, 진찰 결과, 알레르기는 우선 보존한다.
- 중요한 누락은 LLM 재호출보다 결정론적 원문 append로 수리해 모델 호출과 변동을 늘리지 않는다.

### 5. `e2_ledger_overlay.py`

- 원본 E2 진료 로직을 직접 수정하지 않고 tracking client와 coverage annotation을 설치한다.
- 실행 종료 시 원본 클래스와 함수로 복구한다.
- 기존 턴 재배정, CBT-I, 약물 질문 변경과 분리하여 단일 요인으로 측정한다.

## 제출 직전 감사 흐름

1. 원본 E2가 진료와 SOAP 초안을 생성한다.
2. Tracking client가 `diagnose()` 호출을 가로챈다.
3. SOAP router가 전체 ledger를 S/O에 대조한다.
4. Audit가 각 evidence의 처리 상태를 확정한다.
5. 중요한 누락과 상충을 결정론적으로 보완한다.
6. P에서 계획·실제 설명·시행 완료 표현을 구분한다.
7. 수정된 SOAP과 원래 진단명을 원본 `diagnose()`에 전달한다.

## 테스트

- 45턴 뒤에도 1턴의 약물·알레르기·증상·진찰 원문이 남는다.
- 최근 60줄 밖으로 밀린 답변도 SOAP에 반영된다.
- 자유응답 target 매핑 실패 시 HPI fallback으로 남는다.
- 상충 답변 두 개가 모두 보존되고 음성/정상으로 자동 확정되지 않는다.
- 가족 답변을 환자 과거력으로 쓰지 않는다.
- 검사 계획이 O.tests 결과로 이동하지 않는다.
- 실패한 SAY를 실제 교육으로 기록하지 않는다.
- 반복 질문은 한 번만 기록하고 duplicate 사유를 남긴다.
- 길이 제한에서도 핵심 위험·약물·진찰 근거가 우선 보존된다.
- 설치·복구 후 원본 E2 객체가 동일하다.
- 제출 ZIP에 원문 로그·audit 개발 파일·키가 포함되지 않는다.

## 단계별 검증

1. 원본 E2 고정 fixture로 SOAP coverage 비교: 행동과 진단은 완전히 같고 기록만 달라야 한다.
2. 합성 45턴 회귀 세트로 evidence disposition 100%를 확인한다.
3. 개발 API C01에서 원본 E2와 ledger-only 후보를 각각 실행한다.
4. C03·C10에서도 동일하게 실행해 진단·턴·시간·SOAP 차이를 비교한다.
5. 세 증례 모두 정상 종료하고 중요한 근거 누락이 감소하며 안전·효율 회귀가 없을 때만 ZIP을 만든다.
6. 공식 샘플 검증에서 원본 77.714와 영역별 비교 후 리더보드 여부를 결정한다.

## 채택 기준

- 성공한 임상 SAY/EXAM의 ledger 포착률 100%.
- 모든 ledger 항목의 처리 상태 부여율 100%.
- 중요한 관찰근거의 무사유 SOAP 누락 0건.
- 미시행 검사·미전달 교육을 완료로 기록한 건수 0건.
- C01·C03·C10 진단 불일치 0건, 비정상 종료 0건.
- 원본 대비 추가 환자 턴 0, 추가 Doctor 호출 0을 목표로 한다.
- 로컬 추정 총점은 채택 기준으로 사용하지 않는다.
- 공식 샘플에서 원본 E2의 안전 15점과 효율 19.42점이 하락하면 폐기한다.

## 범위에서 제외

이번 단계에서는 질문 우선순위, 진단 후보, 종료 문구, 약물 문진, CBT-I 응답을 동시에 변경하지 않는다. 공개 정답·대본·모범 SOAP은 런타임에 넣지 않는다. Evidence Ledger는 기억 장치와 감사 계층이며 진단 확률 계산기로 사용하지 않는다.
