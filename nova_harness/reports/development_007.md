# 개발 7차 — 승인된 우선순위·근거·전달 개선

2026-10-18 KST. 사용자가 6차 분석 계획을 승인했다. 공식 제출·PR 병합은 범위 밖이다. Doctor는 openai/gpt-6-luna, 세션 밖 개발 검토자는 openai/gpt-6.1-sol이다.

## 구현과 상태

- 수집 상태는 참고로 제공하고 미질문 큐가 자유 질문·계획·DONE을 강제 교체하지 않는다. 잘못 연결한 SAY target도 원문 질문을 바꾸지 않는다. EXAM의 알려진 target에 한해 정규 동작 연결을 유지한다.
- 같은 target의 진찰 결과가 이미 있으면 바꿔 말한 요청도 차단한다. 이후의 실제 새 응답 ID와 재평가 이유가 있으면 허용한다. 새로운 소견의 임상적 중요성은 모델 판단이며 출처 ID 검증만으로 보증하지 않는다. target을 식별하지 못한 자유 문구의 모든 의미 중복까지 검출하는 기능은 아니다.
- 사실에 attribute/value/unit/time_anchor를 추가했다. 같은 정확한 환자 인용 안에 값·단위·시간이 있어야 하며 단위 환산·하루 총량을 임의 계산하지 않는다. 기존 사실 구조와 원문은 유지한다.
- 개발 모델로 합성 반례 12개를 생성해 수동 문자열 검토 후 재생했다. 처음에는 10/12 일치했고, 값에 붙은 불확실성을 양성으로 바꾸는 사례와 가족의 값을 환자에게 옮기는 사례가 남았다. 좁은 어휘·문법 가드를 추가해 이 12개는 모두 일치했다. 개발에 사용한 회귀 세트이며 독립 검증·임상 정확도가 아니다. 전체 의미·부정·주체 해석은 여전히 미해결이다.
- 종료 큐는 목적별 핵심 하나를 먼저 전달한 뒤 필수 보완·계획·추적 내용을 반복적인 판단 설명보다 먼저 전한다. 모델의 essential 태그는 전송 우선순위 제안이며 임상 충분성 검증이 아니다. follow_up의 시점·목적과 실제 SAY 연결을 명시했다.
- 관련 없는 미확인 개념 ID는 Planner에서 제거하고 관련 후보만 남긴다. 원문 응답·사실은 삭제하지 않는다. --full-context로 이전 입력 목록을 복원해 비교할 수 있다. 같은 답변을 같은 SOAP 칸에서 여러 번 전문 재출력하는 중복을 줄였다.
- 지침 검색은 MedDB 고정 커밋의 읽기 전용 검색기를 참고해 별도 모듈로 이식했다. 공식 자료 경로·메타데이터 색인과 소수 원문 발췌만 사용하며 --guidelines로 활성화한다. 기본 비활성화다. FTS5가 없으면 제목 부분일치로 후퇴한다. 관련성·최신성·환자 적합성은 추가 검토가 필요하다. 원문·검색 발췌·변경본을 Git·제출물에 포함하지 않는다.
- 자체 검토의 --review-tag는 같은 로그의 별도 검토를 기존 점수에 덮어쓰지 않고 저장한다. 버전 이름은 검토 payload에 보내지 않지만, 로그 문체·기록 형식의 차이는 남는다.

고정 v0.7.2 런타임 준비 당시 테스트 108개 통과. 검토 복제 파일과 캐시 회귀 검증을 추가한 현재 도구 포함 테스트는 109개 통과. 검사 항목은 질문 보존, target 중복과 재평가, 정량 문자열 출처, 합성 반례, 문맥 제거 시 원문 보존, 필수 계획 우선 전달, 지침 검색의 원문 보존·경로 범위·미설치 후퇴 등이다. 유닛 테스트와 API 임상 평가를 구분한다.

## 비교 설계

v0.6.1 기준 두 실행과 v0.7.0 초기 후보 두 실행을 시작했다. 초기 후보를 개발하는 동안 소스를 별도 경로에 고정했으며 실행 중 수정하지 않았다. 합성 반례에서 발견한 범위 문제와 지침 옵션 등을 보완한 v0.7.2는 별도 소스다. v0.7.0 점수를 v0.7.2 성적으로 사용하지 않는다.

주 비교는 v0.4.1/v0.6.1/v0.7.2 × 공개 C01/C03/C10 × 2회다. 같은 소스·옵션의 v0.6.1 초기 두 회만 재사용한다. 초기 v0.7.0 두 회는 별도로 보고한다. 문맥과 지침 제거 비교는 동일 v0.7.2의 옵션만 바꿔 별도 분리한다. 공개 증례는 이미 개발에 사용했으므로 독립 검증이라고 부르지 않는다.

각 실행은 고정 소스 경로·manifest·source_snapshot·trace·analysis·개발용 검토를 보존한다. 새 고정 소스로 옮긴 결과는 같은 조건 반복으로 합치지 않는다. 런타임에는 공개 대본·모범 기록·증례 ID를 입력하지 않는다. 장애·중단 결과도 남긴다.

## 측정 도구 보완

병렬 프로세스 두 개가 과거 도구의 같은 시각 폴더명을 사용해 한 프로세스가 API 호출 전에 종료했다. 고정 소스를 바꾸는 대신 배치 실행기의 시작을 순차화했고, 누락된 한 실행만 재개했다. 이 로컬 시작 실패는 진료·점수 측정 횟수에 넣지 않는다.

검토 복제 기능의 저장 경로가 기본 파일을 가리키는 오류를 발견했다. API 응답 원문으로 첫 점수와 복제 점수를 각각 복구했고 저장 대상·캐시 테스트를 추가했다. 새 검토 호출로 점수를 대체하지 않았다. C10 v0.6.1의 동일 입력 해시에서 70/74점이 나왔으며, 이 4점 차이는 검토자 변동의 한 사례다. 복제를 별도 진료로 세거나 높은 값을 기본 점수로 고르지 않는다.
