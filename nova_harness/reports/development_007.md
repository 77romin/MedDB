# 개발 7차 — 승인된 개선 구현과 반복 비교

2026-10-18 KST. 최종 런타임 v0.7.3. Doctor는 `openai/gpt-6-luna`, 세션 밖 개발 검토자는 `openai/gpt-6.1-sol`이다. 사용자 승인에 따라 구현·개발 API 비교·로그 분석을 진행했다. 공식 제출·PR 병합은 하지 않는다.

## 결론

질문을 강제 교체하는 결함을 제거하고 입력 문맥·출처 검사·설명 순서를 보완했다. 기본 조건의 공개 3증례에서 v0.6.1보다 평균 추정이 각각 4·3·1점 높았고 입력 토큰은 감소했다. 그러나 정보수집·의사소통의 큰 개선은 확인하지 못했다. 각 조건 2회와 이미 사용한 공개 증례, 단일 검토자에 한정돼 일반화 성능·유의한 효과를 주장하지 않는다. 공식 ≥78·≥85·≥90 목표는 아직 미달성이다.

기존 공식 67.132는 다른 MedDB 제출물의 결과다. 아래 개발 추정과 직접 증감을 비교하지 않는다. 새 프로젝트 공식 점수는 미측정이다.

세부 코드 해시·옵션·실행 폴더와 요청/사용량은 [반복 집계](repeated_007.md)에 있다.

## 구현한 변경과 검증 범위

1. **수집 큐를 강제 제어에서 조언으로 변경.** 미질문 항목을 채우기 위해 자유 SAY·계획·DONE을 바꾸지 않는다. 잘못 연결된 SAY target 때문에 실제 위험 확인 질문이 일반 병력으로 치환되는 것도 막았다. 환자에게 필요한 긴급 대응을 금지하거나 낮은 점수를 피하려고 응급 판단을 강제로 억제하는 규칙은 추가하지 않았다.
2. **진찰 target의 반복과 재평가 분리.** 같은 target의 결과가 있으면 바꿔 말한 요청도 차단한다. 이후 실제 새 응답 ID와 재평가 이유가 있으면 허용한다. target을 식별하지 못한 모든 자유 문구의 의미 중복을 검출하지는 못하며, 출처 ID 검증은 재평가의 임상적 타당성 증명이 아니다.
3. **정량·시간 속성.** attribute/value/unit/time_anchor를 같은 정확한 환자 인용에 연결한다. 질문에서 값을 빌리거나 단위를 바꾸지 않는다. 값에 붙은 명시적 불확실성, 가족 주체, 비교·범위·근사값을 정확한 환자 값으로 확정하는 일부 형태를 보수적으로 거절한다. 거절해도 원문은 보존한다. 전체 의미·부정 범위 검증기는 아니다.
4. **설명 순서.** 목적별 핵심을 먼저 전달하고 필수 보완·계획·추적을 반복적인 판단 설명보다 앞세운다. 생성 문장 수를 남은 턴 안으로 요구하고 실제 SAY만 교육 수행으로 남긴다. essential 태그는 모델의 전송 우선순위 제안이며 임상 충분성 증명이 아니다. 직접적인 환자 질문 대응과 구체적인 추적 안내는 여전히 부족한 사례가 있었다.
5. **관련 문맥과 기록 중복.** 미확인 개념 325개 전체 대신 관련 후보만 Planner에 보낸다. 원문 응답·사실은 삭제하지 않는다. --full-context로 기존 문맥을 복원할 수 있다. 같은 SOAP 칸에 같은 응답 전문을 여러 번 쓰는 중복을 줄였다. 미분류 응답의 HPI 집중·일부 과거력 분류·기록 가독성은 미해결이다. 새 임상 서술로 원문을 마음대로 대체하지 않았다.
6. **선택적 지침.** MedDB 고정 커밋의 읽기 전용 검색기를 이식했다. `NOVA_GUIDELINES_DIR`의 메타데이터 색인과 소수 원문 발췌를 사용한다. 지침은 문진 종료 후 최종 판단/계획에만 제공되며 문진 단계의 정보수집 개선 기능으로 평가하지 않는다. 원문·발췌·변경본을 Git·제출물에 넣지 않는다. FTS5 미지원 시 제목 검색으로 후퇴하며, 자료 미설치는 명시적으로 표시한다. 기본은 비활성화다.
7. **측정 도구.** 고정 소스의 제한된 실행·중단 후 재개, 별도 검토 복제, 코드 해시·옵션별 반복 집계를 추가했다. 개발 모델은 최종 점수뿐 아니라 합성 근거 추출 반례 생성에도 활용했다. 공개 정답·대본·모범 기록은 오프라인 평가 도구만 읽는다.

최종 코드 테스트 110개 통과. API 임상 성능과 단위 테스트를 구분한다. ZIP의 키 없는 독립 prepare와 허용 목록 검사도 테스트에 포함된다. Docker와 공식 서버 환경·공식 점수 검증은 하지 않았다.

## 합성 반례: 개선에 사용한 데이터는 독립 검증으로 쓰지 않음

첫 합성 12개는 초기 검사에서 10/12가 생성 라벨과 일치했다. 값에 붙은 불확실성과 가족 주체 오류를 보완한 뒤 해당 회귀 세트는 모두 일치했다. 생성 라벨과 원문 문자열을 점검했으며 임상적으로 검수된 증례가 아니다.

이후 다른 합성 12개를 고정 v0.7.2에 대조하니 11/12였고 기존 질문·답변 쌍의 정확한 중복은 0개였다. 비교 기준의 함량을 실제 환자 값으로 처리한 실패 하나를 공개 회귀 세트로 전환해 v0.7.3에서 고쳤다. 최종 회귀 세트는 13개이며, 두 번째 세트도 수정 후 독립 검증 성적으로 사용하지 않는다. 모델 생성 자료의 편향·라벨 오류 가능성과 미검증 문법이 남는다.

## 초기 후보와 분리 비교

v0.7.0 C01 72/C10 76, v0.7.2 C01 75/C10 73은 각각 단일 초기 실행이다. 최종 v0.7.3의 반복 성적으로 합치지 않는다. v0.6.1의 초기 두 실행만 코드·조건이 같은 주 비교에 재사용했다.

문맥·지침의 분리 비교는 같은 고정 v0.7.3에서 옵션만 바꿔 C01·C10 각 1회씩 수행한다. 단일 시행이므로 환자·Doctor·검토자 변동을 제거하지 못했다. 문맥 옵션은 문진과 최종·설명 입력 모두에 영향을 준다.

| 조건 | C01 | C10 | 반복 수 |
| --- | ---: | ---: | --- |
| 기본 관련 문맥, 지침 없음 | 69.5 (67–72) | 73.5 (73–74) | 각 2회 평균·범위 |
| 전체 문맥, 지침 없음 | 53 | 80 | 각 1회 |
| 관련 문맥, 최종 지침 검색 | 72 | 73 | 각 1회 |

전체 문맥은 C01에서 낮고 C10에서 높았다. 비용만 보고 문맥 축소를 전반적 성능 최적화로 채택할 근거는 부족하다. 필요한 개념을 더 잘 선택하는 방식이 후속 과제다. 지침은 검색됐다는 이유로 임상적 적합성을 인정하지 않는다. 실제 C10 지침 실행에는 Graves Disease와 함께 다른 질환인 COPD 지침이 검색됐다. 제목의 공통 단어가 만든 잘못된 관련성 후보로, 현재 검색은 임상 판단을 대체할 수준이 아니다.

공식 지침 ZIP의 공개 SHA-256을 확인했으며 카탈로그 문서는 15,904개다. 메타데이터 검색의 로컬 확인은 약 0.14초였으나 이를 대회 환경 성능이나 진료 정확도로 해석하지 않는다. 실제 검색 원문·파일·행·라이선스·출처 URL·해시는 로컬 trace에 남긴다.

## 측정 무결성과 실행 산출물

주 비교 18회+초기 후보 4회+옵션 비교 4회, 총 26회 진료를 구분한다. 같은 C10 로그의 재검토 한 회는 별도 복제다. 원문 임상 로그는 Git에서 제외한다. 모든 실행은 독립 환자 상태와 별도 프로세스를 사용했다.

과거 도구의 병렬 실행에서 시각 기반 폴더명이 충돌해 한 프로세스가 API 호출 전에 끝났다. 고정 소스를 수정하지 않고 시작을 순차화했으며 누락된 한 회만 재개했다. 이 로컬 시작 실패는 진료 횟수나 점수에 넣지 않았다.

검토 복제의 출력 경로가 기본 파일을 가리키는 오류도 발견했다. 원래 API 응답으로 70/74점을 각각 복구하고, 기본 검토 보존·복제 캐시 테스트를 추가했다. 점수를 바꾸기 위한 새 검토 호출은 하지 않았다. 같은 검토 입력 해시를 확인했다.

로컬 테스트 110개 전체 통과, 별도 게시본 109개 통과·선택 E2 의존성 1개 건너뜀을 확인했다. 패키지는 24파일·72,700바이트, SHA-256 `88497f8db1c5045ef82c6414485511cf9ccc688e778dcf819f5e2747707308b9`다. 코드·SDK·경량 JSON·출처 통지만 포함하며 키·원문 결과·공개 대본·지침 코퍼스·개발 도구·테스트를 제외했다. ZIP은 개발용 산출물이며 자동 제출하지 않았다. 상세 26회는 [개별 실행 비교](benchmark_007.md)에 있다.

## 채택 판단과 남은 우선순위

출처·질문 보존과 측정 재현성을 보완한 개발 소스로 유지한다. 그러나 이번 공개 소규모 추정만으로 공식 제출 권장 후보나 성능 검증 완료로 승격하지 않는다. 기본 문맥 축소와 선택적 전체 문맥은 증례별 차이를 더 확인해야 하며, 지침 검색은 기본 비활성화를 유지한다. 목표 78점 도달을 보장하거나 한 증례의 80점을 공식 목표 달성으로 쓰지 않는다.

다음의 핵심은 더 많은 호출이 아니라 처분·중증도·약물 노출과 연결된 필요한 정보의 우선순위, 환자 질문에 직접 답하는 설명과 치료·추적 계획, 근거에 맞는 SOAP 요약이다. 초안 관계의 의학적 검수와 관련 개념 선택이 필요하다. 단순히 지침 문서 수나 슬롯 수를 늘리는 방식은 지지되지 않는다.

새 공식 점수는 사용자가 제출한 고정 ZIP에 대한 공식 평가로만 확인한다. 이번에는 코드·테스트·보고서를 기존 PR #5에 반영하고 병합·공식 업로드는 하지 않는다.
