# 개발 1차 보고 — 실행 하네스와 로그 기반 개선

기준일: 2026-10-18 KST. Doctor는 `openai/gpt-6-luna`, 개발용 독립 검토자는 `openai/gpt-6.1-sol`이다. 공개 샘플 C01만 사용한 초기 개발 실험이다. **공식 점수·임상 검증·일반화 성능을 확인한 결과가 아니다.**

## 구현한 내용

공식 SDK 1.0.1을 그대로 사용해 예선 진입점, 같은 요청 ID를 유지하는 통신 재시도, 무효 응답의 새 ID 재시도, 턴·시간·토큰 회계, 출처가 연결된 환자 사실, SOAP 15칸 생성과 검증, 비밀정보를 제외한 실험 로그, 비교·자가평가·제출 ZIP 도구를 만들었다.

온톨로지는 초진 정보 항목과 약물 사용 확인 관계의 **구조 시드**다. 검토된 전체 의료 지식 그래프나 질환별 추론 규칙은 아직 없다. 현재 S/O 기록은 원문 증거를 보존하는 초안이며, 모델 추출의 의미·부정·주체·시간이 의학적으로 맞는지는 별도 검증이 필요하다. 임상 근거 검색과 벡터 임베딩은 아직 구현하지 않았다.

## 비교 조건

- 공식 원본 baseline과 하네스를 동일 공개 UUID·30턴 상한·동일 Doctor에서 각각 실행했다.
- 각 버전은 1회다. 가상환자 응답과 모델 출력이 달라질 수 있어 버전 차이만의 인과 효과로 해석할 수 없다.
- runtime은 시작 정보와 실제 응답만 읽는다. 공개 대본·모범 기록은 별도의 개발용 평가 도구만 사용한다.
- 입력/출력 토큰은 Doctor 응답 usage 기준이며 가상환자 비용·검토자 비용을 포함한 실제 청구액이 아니다.
- 공식 리더보드 평가나 제출 코드의 서버 컨테이너 검증을 수행한 실험은 아니다. 코드는 로컬에서 돌고 진료·Doctor API는 대회 서버를 사용했다.

## 로그에서 확인한 원인과 수정

| 버전 | 확인된 문제 | 대응 |
| --- | --- | --- |
| baseline | 실제 복용 정수·시간대별 복용량 확인 부족, 한 알 함량을 일일 용량처럼 기록. 진찰 거절 1건. P의 4칸 공란 | 약물 사실을 나누어 수집하고 S/O를 원문에서 구성. 계획은 별도 구조로 작성 |
| v0.1 | 이전 사실을 매 호출 다시 출력해 출력 한도 초과·JSON 잘림, 불필요한 재생성 | 새 응답에서 바뀐 사실만 최대 3개 출력, 가설·설명 길이 제한, 온톨로지 문맥 축소 |
| v0.1.1 | 위험 가능성에 집중해 문진 조기 종료. 설명 태그 조건이 DONE을 반복 거절 | 긴급도와 주진단 구분 지시, 장기 복용의 변화·조절·기능 영향 항목 추가, 복수 설명 태그와 종료 조건 수정 |

첫 두 하네스의 비공식 추정 점수는 baseline보다 낮았다. 속도 개선을 진료 품질 개선으로 보고하지 않았다. 자동 검증기가 프로토콜 오류를 줄여도, 적절한 정보수집과 진단이 따라오지 않으면 점수가 오르지 않는 사례다.

## C01 1차 실행 결과

| 버전 | 제출 | 턴 | Doctor 고유 요청 | 출력 토큰 | 실행 시간 | 개발용 추정 점수 |
| --- | --- | --- | --- | --- | --- | --- |
| baseline | 성공 | 29 | 33 | 7,035 | 228초 | 40/100 |
| v0.1 | 성공 | 17 | 28 | 32,560 | 487초 | 37/100 |
| v0.1.1 | 성공 | 11 | 17 | 11,402 | 170초 | 36/100 |
| v0.1.2 | 성공 | 11 | 15 | 10,691 | 179초 | 44/100 |

v0.1.2는 JSON 잘림 0건, 파싱 오류 1건을 복구하고 정상 종료했다. 기록의 나이·복용량·빈도 변조를 줄인 점은 긍정적이지만, 공개 비교 진단과 주진단이 여전히 달랐다. 핵심 감별에 필요한 문진·표적 진찰·교육을 마치지 않고 종료하는 문제가 남았다. 44점은 개발용 평가 모델의 단일 추정치이며 4점 차이를 검증된 성능 향상으로 해석하지 않는다.

실제 비교 데이터는 `results/comparison.md`, 실행별 모델 검토는 `local_review.json`에 있다. 개선 버전은 C01에서 튜닝되었으므로 C01을 독립 검증 세트라고 부르지 않는다.

자가평가자의 비판도 정답으로 간주하지 않는다. 로그의 근거 인용을 사람이 확인해야 하며, 공개 비교 기록의 모든 행동을 필수로 시행하도록 강제하지 않는다. 약물의 추가 과량 복용 방지와 장기 복용약의 갑작스러운 중단을 구분하는 문제는 임상 검토 항목으로 남겼다. 관련 외부 근거는 [NICE NG215 권고](https://www.nice.org.uk/guidance/ng215/chapter/Recommendations)를 참고하되, 고정 감량 용량·확진 기준을 코드에 추가하지 않았다.

## 검증과 한계

- 자동 테스트는 재시도 멱등성, 무효 응답 호출 회계, NFC 경계, 중복 행동, 출처 없는 사실 거절, 원문 복용량 보존, 예산 소진 시 제출, 종료 제어, 실제 잘린 JSON 회귀, 제출 ZIP 격리 실행을 확인한다.
- ZIP을 별도 임시 폴더에 풀고 개발 파일·키가 없는 상태에서 prepare를 실행했다.
- Docker 데몬이 실행되지 않아 공식 local.Dockerfile의 컨테이너 빌드·자원 제한 검증은 완료하지 못했다.
- 현재의 비공식 검토 결과는 임상 전문가가 검증하지 않았다. 다른 공개 증례와 독립 검증 세트에서의 성능도 아직 측정하지 않았다.

## 다음 구현 우선순위

1. 진료 프로토콜과 기록 보존을 유지하면서 주호소별 필요한 정보·구분 질문을 보강한다.
2. C10·C03에서 같은 설정을 검증해 C01에 맞춘 개선인지 확인한다.
3. 출처·라이선스를 확인한 임상 근거 검색과 소규모 검토 온톨로지를 추가하고, 기존 버전 대비 제거 실험을 한다.
4. 사실 누락·부정 오류·주진단 근거·실제 설명 여부를 독립 검증 세트에서 반복 측정한다.

원본 로그·코드 스냅샷·자가평가는 프로젝트 `results/`에 보관한다. `.env`와 결과·정답 파일은 Git 및 제출 ZIP에 포함하지 않는다.
