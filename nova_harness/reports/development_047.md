# 47차 개발: 응답 기반 문진 상태 관리와 R3a 대조

## 구현 범위

사용자 승인(D088)에 따라 `response_state.py`를 R3a의 CareCoverage에만 연결하는 가역 실험 모드 `R3a_response_state`를 추가했다. S3 의무/안전 렌더러·R3b/R3c/R4는 연결하지 않았다. 원본 MedDB는 변경하지 않는다.

환자 응답을 받았다는 이유만으로 확인 완료로 취급하지 않도록 원문 질문/답변/턴/target과 received·ambiguous·partial·declined 상태를 별도로 보관한다. received는 명시적으로 모호하지 않은 응답 수신이라는 뜻이며 관련성·임상 완전성·정상/음성 판정을 보장하지 않는다. 부정이나 약물 정보는 정규화로 대체하지 않고 기존 원문 관찰에 보존한다. 새 임상 사실을 생성하거나 Tracker의 소견·진단을 바꾸지 않는다.

명시적 모호함과 세 수면 수치 항목의 단위 미확보에 한해 주제와 30자 한도를 지킨 명확화를 최대1회 허용한다. 거부 답변은 추가 명확화 대상으로 삼지 않는다. 성공 응답을 받은 동일 문구 질문은 공백·문장부호 변형을 포함해 차단한다. 상충 소견 자체는 유지하며 해결됐다고 처리하지 않는다. 기존 위험 우선순위와 문진/마무리 턴 예산·검색·기록 생성은 유지한다. 모든 자유 서술의 의료 의미 추출·감별 가치 기반 질문 재정렬·새 종료 정책은 아직 포함하지 않는다.

## 발견 및 보완

첫 구현에서 저장 실제 응답의 한글 수치 '삼십 분'을 미확보로 오탐했다. 첫 C03 대조 실행이 끝난 뒤 한글 수치와 몰라요/모릅니다 표현을 보완했다. 새 테스트는 보완된 모호함 분류에 맞게 기대값을 수정한 뒤 통과했다. 최종 회귀는256개 통과다.

저장된 이전 세 증례의 성공 SAY 중 표준 질문에 유일하게 매핑되는57건을 최종 코드로 분류했다. 모두 received였으며, 이는 의미가 정확히 추출됐다는 검증이 아니다. 미매핑 자유 질문·복합 응답의 세부 항목은 평가하지 않는다. `response_state_replay_047.json`에 원문 없이 집계했다.

## 실제 개발 API 비교

Doctor는 반환 모델 기준 모두 openai/gpt-6-luna다. 아래는 공개 개발 세션 실측이며 공식 채점 점수나 진단 정확도 검증이 아니다. 두 버전은 같은 공개 증례를 별도 세션으로 실행했으므로 환자/모델 관찰이 같지 않다.

| 증례 | R3a 턴·초 | 후보 턴·초 | Doctor 성공/시도 R3a→후보 | 오류 |
|---|---|---|---|---|
| C01 | 45·569.649 | 45·542.077 | 21/21→23/23 | 후보 EXAM_NOT_SPECIFIC 1 |
| C03 | 33·238.533 | 33·233.299 | 12/12→12/12 | 양쪽0 |
| C10 | 44·456.386 | 41·381.804 | 30/30→25/25 | 양쪽0 |

6세션 모두 정상 종료, 출력 절단0이었다. C03은 한글 수치 보완 전 소스의 실제 실행이다. 최종 소스로 C03 두 세션 전체를 재생해 모델 입력·행동·최종 SOAP가 저장본과 일치함을 확인했지만, 이를 최종 소스의 새 C03 API 세션이라고 표현하지 않는다. C01/C10은 최종 모듈 지문과 실행 시작/종료 Nova 지문이 일치한다. C10 두 세션도 전체 재생을 통과했다. C01 오류 세션의 전체 재생은 실행하지 않았다. 집계는 `response_state_validation_047.json`, 재생은 `response_state_session_replay_047.json`이다.

C01 후보에서는 같은 상충 대상의 동일 질문 후보를16번 필터했다. 반복된 선택 검사의 횟수로16턴을 절약했다는 뜻은 아니다. 실제 성공 SAY의 물음표 질문에서 같은 문구 재전송은 R3a 1→후보0회였다. C03/C10은 양쪽0이었다. 다른 문구의 의미상 중복까지 검증한 수치는 아니다.

후보에서 target이 연결된 응답은 C01 22/C03 17/C10 20건으로 모두 received였다. 따라서 이번 실제 세션에서 모호/부분 응답 명확화 분기는 발생하지 않았다. 이 경로는 단위 테스트로 검증했고 실제 운영 효과는 아직 입증되지 않았다. 상충 대상1개는 그대로 남겨, 명료한 문구를 받았다는 사실과 임상적으로 상충이 해결됐다는 판단을 구분했다.

## 판단과 다음 실험

상태 관리·동일 질문 차단의 작동은 확인했으나 점수 상승은 미측정이다. C10의3턴 감소를 코드 효과라고 주장하지 않는다. 각 버전의 기록 전 성공 SAY 순서도 같지 않아 같은 관찰의 인과 대조가 아니다. 오류 없는 종료로 안전점수나 누락 해소를 추정하지 않는다. 이 변경만으로 새 제출 권장본을 만들 근거는 부족하며 공식 업로드·새 제출 ZIP은 실행하지 않았다.

코드상 주요 제약은 required 목록이 있으면 대부분 첫 항목을 그대로 선택한다는 점이다. 다음 별도 실험은 실제 확보 근거와 미확보 필수 정보를 이용해 기존 후보 중 다음 질문을 고르는 정책이다. 위험/처치 안전을 보존하고 중복·정보 획득 가치·남은 턴을 비교해야 한다. 정답 대본이나 공개 증례 식별자를 런타임에 넣지 않는다. 이번 패치에 해당 정책을 섞지는 않았다.

Docker·공식 채점·임상 완전성은 미검증이다. 원문 로그와 환자 인용은 results에만 두고 소스·테스트·안전한 집계를 기존 브랜치/PR에 게시한다.
