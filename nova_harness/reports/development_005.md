# 개발 5차 보고 — 고정 기준 실행과 수집·근거 검증

기준일: 2026-10-18 KST. 사용자 요청은 개발 API 측정 → 로그 분석 → 성능 개선이다. Doctor는 `openai/gpt-6-luna`, 별도 개발 검토자는 `openai/gpt-6.1-sol`이다. 새 프로젝트의 공식 점수는 아직 없으며 목표 ≥78 → ≥85 → ≥90은 공식 제출 결과로 판단한다.

## 비교 설계

- 기준: v0.4.1 소스를 별도 폴더에 고정해 실행했다. 수정본 개발 중 import가 섞이지 않도록 독립 프로세스·경로를 사용했고 키 파일은 복사하지 않았다.
- 수정본: v0.5.0. 공개 C01·C10을 기준·수정본 각각 한 번 실행한다. 전체 45턴, 종료 12턴 상한, 같은 Doctor·별도 검토 프롬프트를 사용한다.
- 비교는 새로운 v0.4.1 실행을 우선한다. 이전 v0.4.0의 낮은 점수만 골라 대조하지 않는다. 같은 증례라도 환자·Doctor·검토자 출력은 달라질 수 있다.
- 여러 기능을 함께 바꾼 전체 시스템 비교이며, 각 구성요소의 인과 효과를 분리한 제거 실험은 아니다. 이미 개발에서 관찰한 공개 증례로 독립 검증을 주장하지 않는다.
- 처음 계획한 범위는 진료 실행 4회와 완료된 로그 검토 4회였다. 실제 실패를 확인해 v0.5.1, v0.5.2를 각각 두 증례에 추가했다. v0.5.2까지 기준 2회+수정본 6회를 완료했으며, 계산량 프로필만 바꾼 v0.6.0 두 실행을 추가해 최종 범위는 진료·비공식 검토 각각 10회다. 추가 측정의 이유와 실패한 중간 결과도 보존하며 공식 제출·PR 병합은 하지 않는다.

## 로그에서 출발한 변경

이전 실행에서는 핵심 문진 전에 진단·이송 설명을 반복하거나 DONE을 선택했다. 질문에 대한 부분 답변을 나머지 항목까지 확인한 것으로 해석하고, 노출 위험을 확인된 병태로 서술하는 문제도 있었다. 이번에는 종료 문구보다 수집 상태와 근거 범위를 먼저 바꿨다.

### 수집 상태와 행동 연결

`coverage.py`는 MedDB의 주호소 슬롯·질문·진찰·기본 병력에서 후보를 만든다. 실제로 지지된 상위 가설에는 제한된 보조 질문을 추가한다. 나이·성별 적용 범위와 소아 진찰 제한을 유지한다. 증례 UUID·정답·모범 기록으로 분기하지 않는다.

상태를 `unasked`, `attempted_unresolved`, `resolved_model_extracted`, `conflicting`, `initial_model_mapped`, `exam_result_obtained` 등으로 나눈다. 질문을 했거나 모른다는 답을 받았다는 이유로 정상·해결로 바꾸지 않는다. 진찰 결과 획득은 질환 배제나 모든 징후의 정상과 다르다.

미질문 핵심 항목이 있으면 DONE·이른 판단/계획 설명·남은 수집 여유가 부족할 때의 일반 질문을 다음 핵심 행동으로 돌린다. 즉시 안전 안내는 대체하지 않는다. 의사가 `urgent_exit`와 실제 출처 ID·이유를 명시하면 수집 유보를 허용한다. 이 출처 검증은 긴급성의 임상적 타당성을 보증하지 않으며, 긴급 치료를 지연하도록 강제하는 규칙이 아니다.

초기 제공 정보는 실제 opening의 정확한 인용이 있을 때만 모델 매핑으로 인정한다. 인용 일치는 의미의 정확성을 보장하지 않는다. 모델이 엉뚱한 항목에 연결할 가능성은 남아 있다.

### 소견과 기록 범위

- 명확한 '모르겠어요'를 양성·음성으로 확정하지 않는다.
- SAY에서 음성을 추출할 때 명시적인 부정 표현을 요구하고, '평소보다 심하지 않다' 같은 비교 부정을 절대적인 증상 부재로 만들지 않는다. 보수적 어휘 검사이며 완전한 의미 검증은 아니다.
- EXAM의 정상에서 음성 징후를 만들 때 해당 징후의 그래프상 진찰과 실제 target을 대조한다. 다른 진찰의 정상 결과를 확대하지 않는다.
- 가족의 소견을 환자 자신의 소견처럼 후보 순위에 반영하지 않는다.
- 기록의 HPI에서 교육 발화 자체를 제거하되 그 과정의 새로운 환자 응답은 보존한다. 교육 원문은 P.education에 출처 ID·턴으로 남긴다.
- 주진단의 `certainty`, `diagnostic_basis`와 별도 `risk_assessment`를 구분한다. 모델이 노출 위험만 확인했다고 선언하면 확정형으로 렌더링하지 않는다. 모델이 분류 자체를 잘못하면 여전히 오류가 가능하다.

## 중간 로그에 따른 v0.5.1 후속 비교

v0.5.0 C01은 긴급 경로로 종료해 미질문 핵심 항목이 18개 남았다. 긴급성 예외를 삭제해 점수를 얻는 방식은 사용하지 않았다. 대신 행동 후보에서 문진이 상위 8개를 모두 차지해 진찰이 보이지 않는 구조와 target 연결이 자유 문구에서 사라지는 문제를 수정했다.

v0.5.1은 상위 행동 8개 중 적합한 EXAM 후보 최대 2개를 초반부터 보여 준다. 미질문 핵심 항목의 target을 모델이 선택하면 실제 질문·진찰은 그 항목의 정규 문구로 연결한다. 이미 적절한 핵심 행동을 고른 경우에는 턴 부족 규칙이 다른 질문으로 바꾸지 않는다. 즉시 안전 안내와 근거가 제시된 긴급 종료는 유지한다.

초기 진료 환경을 보존하도록 지시를 보강하고, 이해 확인 문구를 집에서의 행동을 가정하지 않는 문장으로 바꿨다. 이 후속 후보는 별도 경로에서 테스트 83개를 통과한 뒤 개발 API에 실행했으며, 실행 중인 v0.5.0 소스를 수정하지 않았다.


## 동반 증상 연결과 v0.5.2

v0.5.0 C10은 핵심 행동을 11회 보완했지만 정보수집 추정은 기준과 같은 18/25였다. 주호소 목록을 더 많이 채우는 것만으로 중증도 관련 정보가 확보되지 않았고, v0.5.1도 중복 진찰과 효율 문제가 남았다.

v0.5.2는 환자 자신의 양성 소견과 동일한 ID를 가진 동반 주호소 그래프를 최대 하나 연결한다. 예를 들어 체중 감소 평가 중 두근거림이 확인되면 두근거림의 질문·진찰 관계를 사용한다. 원문 단어만 보고 임의로 진단하지 않으며 가족의 소견·음성·상충은 확장의 근거로 삼지 않는다. 확장이 여러 새 증상으로 연쇄적으로 번지지 않게 하고, 관련 질문 최대 4개·진찰 최대 2개로 제한한다.

실제 EXAM에서 모델이 출처와 연결한 징후가 있으면 같은 진찰을 다시 미수행 필수 항목으로 강제하지 않는다. 모델 매핑은 검증된 임상 해석과 구분해 상태에 표시한다. 모델이 자발적으로 반복 진찰을 요청하는 모든 상황을 금지하는 기능은 아니다.

실행 전 테스트 89개 통과 후 같은 C01·C10에 마지막 비교를 추가했다. 실행 소스는 별도로 고정했으며, 결과가 나온 뒤 문장이나 정책을 바꾼 버전을 같은 성적으로 보고하지 않는다.

## 계산량 프로필 비교 v0.6.0

v0.5.2 C01은 JSON 잘림 2회·무효 응답 3회와 723초 실행을 기록했다. 문진에서도 매번 medium 추론을 사용해 출력 2,048 토큰 한도 안에서 추론과 JSON이 경쟁했다. 임상 로직·문진 45턴/종료 12턴 상한은 유지하고 문진 Planner만 low, 최종 판단·종료 설명은 medium으로 분리했다. `--planner-effort medium`으로 기존 계산량을 복원할 수 있다. 변경 전 테스트 91개를 통과했다.

이 비교는 같은 소스의 프로필 차이를 보지만 각 조건 한 번뿐이며 환자·모델·검토 변동을 제거하지 못한다. low 설정이 사실 추출이나 안전 판단을 약화할 수도 있어 비용 감소만으로 채택하지 않는다. 두 진료·검토를 완료했으며 아래에 결과를 기록한다.


## 실행 비용과 장애

다음 표의 토큰은 Doctor 응답에서 관찰한 입력/출력 합계이며, 별도 검토자 비용은 제외했다. 요청은 시도한 고유 Doctor 요청 ID 수다.

| 증례·버전 | 요청 | 입력/출력 토큰 | 경과 초 | 비공식 추정 |

low 실행의 출력은 v0.5.2 대비 약 56%/49%, 경과 시간은 약 52%/36% 줄었지만, 이번 기준보다 C10은 여전히 느리고 비싸다. C01은 502로 종료 설명이 중단됐으므로 시간 감소 전부를 추론 최적화 효과로 볼 수 없다. low 두 실행의 출력 잘림은 0회였으나 C01 형식 오류는 5회였다. 비용 절감이 임상·형식 성능 향상을 뜻하지 않는다.

C01 v0.6.0은 가장 걱정되는 점을 묻는 첫 종료 SAY에서 `INVALID_API_RESPONSE`·HTTP 502를 받았다. 기존 Gateway의 재시도 분류에 없어 종료 설명을 모두 포기하고 기록을 제출했다. 이 요청의 실제 전달 여부는 unknown이다. 점수 62를 장애가 없었을 때의 값으로 보정하지 않는다.

### 후속 v0.6.1: 제한된 전송 복구

비 JSON 응답의 HTTP 502/503/504에 한해 같은 요청 ID·같은 본문으로 기존 최대 3회 재시도를 사용하도록 바꿨다. 요청이 서버에서 처리됐을 가능성이 있어 새 ID를 발급하지 않는다. 200/400/401/403/429의 잘못된 응답과 영구 거절은 이 규칙으로 재시도하지 않는다. 실패가 계속되면 기존 종료·기록 보호 동작을 유지한다. 공식 개발가이드의 동일 요청 재시도 계약에 맞춘 보완이다.

94개 테스트가 통과했다. 추가 테스트는 502/503/504의 ID 유지·상한, 인증/잘못된 응답 재시도 제외, 종료 첫 질문의 502 후 실제 설명 재개를 검증한다. 이는 시뮬레이션 회귀 검증이며 **v0.6.1 전체 개발 API 재측정은 하지 않았다.** v0.6.0 점수를 v0.6.1 성적으로 쓰지 않는다.

| 안전·검사·추적 계획이 기록에 있으나 SAY로 전달되지 않음 | 생성된 계획과 실제 전달을 별도 검증. 종료 문장 수를 늘리는 것만으로 핵심 전달을 보장하지 못함 |

C01의 미해결 사항은 최근 복용 총량·획득 경로·병용·중증 금단 및 실질적 안전 안내, C10은 임신·월경·동반 호흡곤란·안증상 중증도·심폐 평가와 실제 추적 안내다. 이는 검토 모델이 지적한 로그의 누락으로, 의학 전문가가 검수한 범용 온톨로지 규칙이 아니다. 공개 정답을 증례별 런타임 답안으로 옮기지 않는다.

최종 개발 소스는 v0.6.1이다. 근거 검증·관측성·수집 실험 기능은 유지하되 전체 성능 향상은 입증하지 못했다. **Planner 기본 추론은 medium으로 복원**했고 low는 `--planner-effort low`, 수집 제어 제거는 `--no-coverage`로 비교할 수 있다. 이번 비교에서 가장 높은 전체 시스템은 v0.4.1 기준이며, 새 버전을 공식 제출 권장 후보로 승격하지 않는다. 추가로 수정한 안전한 전송 복구와 임상 점수 상승을 구분한다.

공식 67.132점은 기존 MedDB 제출 결과이며 새 프로젝트 공식 점수는 미측정이다. 공식 ≥78·≥85·≥90 목표는 그대로 남는다. 전체 10회는 이미 개발에 사용한 공개 C01·C10의 조건별 단일 실행이며 일반화·통계적 유의성·비공개 증례 성능을 주장할 수 없다. 세부 수치는 [실행 비교](benchmark_005.md), 실제 원문은 Git에서 제외한 로컬 results에 보존한다.
