# 개발 9차 — 단계별 구현·18회 비교·로그 기반 복구

2026-10-18 KST. 개발 소스 v0.8.3. Doctor `openai/gpt-6-luna`, 세션 밖 개발 검토자 `openai/gpt-6.1-sol`. 사용자 승인에 따라 구현·기능별 커밋·API 비교·로그 분석을 완료했다.

## 결론: 일관된 점수 상승을 확인하지 못함

코드 결함 두 가지와 출처·기록·질문 추적을 보완했지만 최종 개발 추정은 **C01 66 / C03 66 / C10 75**다. 이번 기준 61/69/78 대비 +5/−3/−3이며, 같은 코드인 이전 v0.7.3 두 회 평균 69.5/69.5/73.5와 비교하면 −3.5/−3.5/+1.5다. 낮은 기준 실행만 골라 개선으로 보고하지 않는다.

개발 입력·출력 토큰과 일부 기록 크기도 늘었다. 개발 소스로 보존하되 **공식 제출 권장 후보로 승격하지 않는다.** 새 공식 점수는 미측정이며 ≥78/85/90 목표는 미달성이다. 기존 MedDB 공식 67.132와 아래 비공식 추정은 직접 증감 비교하지 않는다. 병합·공식 업로드는 하지 않았다.

## 1. 단계별 점수와 측정 조건

개발 진료의 DIAGNOSE 반환은 `score_status: not_scored`였다. 아래 숫자는 실제 API 로그·제출 기록을 별도 sol 모델로 검토한 자체 루브릭 추정이며, 대회 사이트의 샘플 검증 참고 점수나 공식 점수가 아니다.

모든 셀은 공개 증례 **각 1회**의 비공식 추정이다. 다른 코드·옵션의 점수를 같은 반복 평균으로 합치지 않았다.

| 고정 소스와 목적 | C01 | C03 | C10 |
| --- | ---: | ---: | ---: |
| v0.7.3 동시기 기준 | 61 | 69 | 78 |
| v0.8.0 초기 목표(필드 미출력) | 70 | 68 | 74 |
| v0.8.0.1 목표 계약 보완 | 68 | 71 | 79 |
| v0.8.1 상담 | 66 | 71 | 76 |
| v0.8.2 기록 | 66 | 72 | 73 |
| v0.8.3 결함 복구 | 66 | 66 | 75 |

v0.8.0.1의 동시기 세 점수에는 상승 신호가 있었지만, 각 1회이고 과거 같은 기준의 변동 범위도 커 중간 최고 조건을 그대로 승격하지 않았다.

초기 계획 15회(기준/초기 목표/계약 보완/상담/기록 × 3증례)를 완료한 뒤, 실제 구현 결함을 복구한 3회만 추가했다. 총 진료 **18회**, 기본 개발 검토 **18회**, 미리 선택한 고정 C03 로그 재검토 **1회**다. 복구 후보를 v0.8.2 결과에 섞지 않았다.

v0.8.2 C03의 동일 검토 입력은 72/70점이었다. 기본 점수를 덮어쓰거나 두 점수를 독립 진료로 세지 않았다. 입력 메시지 SHA-256은 `0d5e8cc563534cc6ee7394f6db9c2799298b0f43338d020b486e57937d0433c9`로 같았다. 이전 회차에서도 같은 로그 70/74가 있었다. 단일 실행의 몇 점 차이를 유의한 개선으로 해석하지 않는다.

이번 v0.7.3 기준과 7차 v0.7.3은 전체 fingerprint가 같다. 이전 두 회 평균은 C01 69.5(67–72), C03 69.5(66–73), C10 73.5(73–74)였다. 이번 기준 61/69/78이 그 변동을 더 보여 준다. 이미 반복 개발한 3증례와 단일 개발 검토자에 한정돼 독립 검증·공식 성능 검증이 아니다.

모든 기본 검토의 프롬프트 SHA-256은 `bd7516d97974fcb9c1bbf4105235779643a206266fcf949f4cb3a6257481135f`이며 증례별 공개 비교 자료 해시도 같다. 반환 Doctor/검토 모델을 각각 확인했다. 일부 검토의 설명 언어가 한국어 요청과 달랐으나 원문을 유지했고 점수를 고르기 위한 재검토는 하지 않았다.

## 2. 영역별 결과와 비용

이번 v0.7.3 → 최종 v0.8.3의 비교다. 영역 점수도 검토 모델의 추정이다.

| 증례 | 정보 /25 | 추론 /15 | 검사·추적 /10 | 안전 /15 | 소통 /15 | 효율 /20 |
| --- | --- | --- | --- | --- | --- | --- |
| C01 | 17→17 | 12→13 | 4→5 | 10→9 | 9→10 | 9→12 |
| C03 | 18→16 | 10→11 | 6→7 | 12→11 | 8→9 | 15→12 |
| C10 | 18→18 | 14→14 | 8→8 | 12→12 | 11→9 | 15→14 |

| 증례 | 입력 토큰 | 출력 토큰 | Doctor 고유 요청 | 기록 UTF-8 바이트 |
| --- | ---: | ---: | ---: | ---: |
| C01 | 159,482→375,960 | 33,039→70,801 | 30→51 | 8,545→11,340 |
| C03 | 161,468→204,420 | 35,034→39,459 | 31→31 | 8,083→9,121 |
| C10 | 223,340→325,237 | 31,546→55,624 | 33→42 | 9,846→11,869 |

C01은 요청 30→51, 입력 159,482→375,960으로 늘었지만 정보수집은 17→17, 안전은 10→9였다. 더 많은 질문·목표 메타데이터·호출이 핵심 누락을 해결하지 못했다. C03·C10도 정보를 더 많이 전달했다는 일관된 근거가 없다. 토큰 수는 실제 사용량이며 원화 비용·공식 효율 산식으로 환산하지 않는다. 동시 API 부하 때문에 실행 시간을 코드의 속도 효과로 단정하지 않는다.

질문·목표 계측이 없던 버전은 모니터에서 —로 표시한다. 미계측을 0건으로 해석하지 않는다.

전체 조건·상태·질문 ID 연결·목표 갱신·기록 크기는 [단계 모니터](staged_009.md), 정확한 소스 해시·옵션·요청 집계는 [조건별 집계](repeated_009.md)에 있다.

## 3. 구현한 기능과 확인 범위

### 3.1 대상·시간 범위를 가진 결정 목표

`goals.py`에 need/scope/status/priority/reason과 실제 응답 인용을 둔다. 같은 ID의 scope를 뒤에서 넓힐 수 없고, 질문·의사 계획만으로 완료 처리하지 않는다. 원문 일치가 의미·임상적 완결성을 보증하지는 않는다.

초기 v0.8.0은 필드를 설명문에만 두어 실제 모델이 목표 갱신을 생략했다. 출력 JSON 스키마와 첫 목표 출력을 명시한 v0.8.0.1부터 실제 상태 생성이 확인됐다. 실행 중인 소스는 수정하지 않았다.

일반 DONE 직전에는 중요 누락을 한 번 검토하고 표적 행동 하나를 제안할 수 있다. 일반 설명은 별도 마무리 예정이므로 수집 누락으로 다시 요구하지 않는다. 즉시 필요한 안전 행동은 수집 중에도 할 수 있으며, 근거 ID·이유가 있는 긴급 종료는 추가 검토를 기다리지 않는다. 인용이 임상 긴급성을 보증한다는 뜻은 아니다.

### 3.2 새 질문·우려와 마무리 예산

답변 중 새 질문이 나오면 남은 이전 보완 설명을 멈추고 새 질문을 처리한다. 질문·구체적 두려움을 휴리스틱으로 찾으며, 전체 답변 생성은 최대 3회다. 실제 전송한 답의 ID를 연결하되 `answer_sent_unverified`는 내용 충족·환자 이해의 확인이 아니다.

계획·추적·안전 목적의 첫 문장, 이해 확인·교정을 위한 예산을 보호한다. **목적별 첫 문장 보호가 모든 임상 필수 의미 단위의 전달을 보장하지는 않는다.** 복구 C03에서 연속 질문에 즉시 답한 것은 실제 로그로 확인됐지만, 추가 답변에 턴을 쓰면서 3~6개월 성장 추적 안내가 빠졌다. 정보·안전 문진 누락도 남아 총점은 낮았다.

### 3.3 출처 기반 SOAP 분류

최종 모델은 환자 사실을 새 문장으로 생성하는 대신 실제 SAY 응답 ID를 `history_routes`로 분류한다. 코드는 응답 전체를 유지한다. 존재하지 않는 ID·EXAM·되말하기를 병력으로 라우팅하지 않으며 가족력에는 명시적 가족 맥락을 요구한다. 분류가 충돌하면 원문을 HPI에 남긴다.

같은 원문에서 fact 여러 개를 추출해도 제출 기록에는 전체 응답을 한 번만 쓴다. bare absent 같은 추출 메타데이터를 임상 문장 앞에 붙이지 않는다. fact·목표·원문·분류는 감사 로그에 보존한다. 주호소는 opening의 정확한 짧은 인용일 때만 줄이고 전체 초진 정보는 유지한다. 실제 이해 확인은 교육 기록으로 옮긴다.

이는 검증된 자유 문장 임상 요약이 아니라 **원문을 보존한 추출형 정리**다. 가족력 분류 회귀 테스트는 통과했지만 실제로 질문하지 않은 C10 가족력을 채우지 않는다. 설명 중 동의 응답이 HPI에 남는 문제와 긴 감별 이유도 있어, 전체 기록 크기는 줄지 않았다.

## 4. 로그가 드러낸 실제 결함과 복구

### 완료 목표가 새 목표를 막음

v0.8.2는 활성 목표가 아니라 전체 목표 8개를 제한했다. C01에서 1건, C03에서 2건의 새 목표를 막았다. 같은 실제 응답·모델 출력을 복구 코드로 오프라인 재생하자 상한 거절이 모두 0건이 되고 목표 이력은 9개·10개로 보존됐다. 이는 구조 결함 재현이지 새 진료나 점수 개선 검증이 아니다.

v0.8.3은 open/partial 활성 목표만 최대 8개로 제한한다. 전체 이력은 별도 보존하고 프롬프트에는 활성 목표와 최근 완료·유보 4개를 보인다. 실제 복구 C01에서도 전체 목표 이력 12개·활성 1개를 유지했으며 완료 목표 때문에 거절된 갱신은 없었다. 일반 인용 검증 등의 거절과 이 상한 결함을 구분한다.

### 형식 실패가 첫 질문의 답을 지연시킴

v0.8.1 C01 턴 32의 “약을 줄일 수 있을까요?”에 Doctor가 JSON 대신 긴 일반 문장을 반환했다. 이를 임의 실행하지 않은 것은 적절하지만 같은 질문을 즉시 재생성하지 않아 뒤의 계획 큐가 이어졌다. 턴 36의 다른 우려 답변에서 같은 주제를 일부 설명했으나 첫 질문에는 답변 ID가 연결되지 않았다.

v0.8.3은 무효 형식이면 같은 질문을 남겨 최대 한 번 재생성한다. 전체 답변 호출 3회와 남은 안내 예산을 유지한다. 실제 비 JSON 형태를 일반화한 회귀 테스트에서 무효 문장은 보내지 않고 같은 질문의 검증된 답을 다음 큐보다 먼저 보냈다. 복구 3진료에는 비 JSON 답변 실패가 발생하지 않아, 이 실패 복구 경로의 검증은 **회귀 테스트 범위**다.

## 5. 남은 핵심 원인과 다음 구현 우선순위

1. **자유 형식 목표만으로 임상적 완결성이 생기지 않는다.** C01은 낮 추가 복용·최근 24시간 총량·간헐적 일반약 병용과 지지체계가 계속 미확인이다. 다음 목표는 약물 노출의 실제/통상 사용, 시간 구간, 병용 범위, 처분 전 필요 정보를 분리한 타입으로 정의한다. 야간 1회 복용량 목표가 해결됐다는 사실을 하루 노출량 완료로 확대하지 않는다.
2. **치료 전 안전·합병증 정보가 목표에 충분히 생성되지 않는다.** C10은 유력 진단을 찾고도 임신·안병증 증상·흡연 등 판단에 필요한 정보가 남는다. 자유 문자열 목표 개수 대신 현재 가설·예정 치료·실제 증상에서 적용 조건이 있는 확인 목표를 도출해야 한다. 모든 체크리스트 강제 수집을 되살리지 않는다.
3. **실제 계획 전달은 목적 태그보다 세밀해야 한다.** 즉시 대응과 안정 후 감량, 검사 결과 확인과 장기 성장 추적, 경고와 구체적 행동·담당자·시점을 의미 단위로 나눈다. 새 질문 응답 이후에도 빠진 중요한 단위를 재선정해야 한다. 질문 ID 연결률을 소통 점수로 대신하지 않는다.
4. **임상 관계의 시간·대상 구분을 검수해야 한다.** C03에서 부친의 어린 시절 작은 키, 성인 최종 키, 사춘기 지연을 같은 가족 저신장 근거로 취급하는 표현이 남았다. 다음 관계는 이를 분리하고 가설의 지지/반박에 적용 조건을 붙인다. PES/AAP 자료도 부모 성인 키와 가족의 늦은 성숙 패턴을 구분한다. 단일 소견의 확진 규칙은 아니다. [PES/AAP, 2018](https://pedsendo.org/wp-content/uploads/2020/06/E-Constitutional-Growth-Delay.pdf).
5. **불필요한 문맥·중복 행동을 줄여야 한다.** 복구 C03은 성장도표에서 이미 받은 성장속도·중간부모키를 다른 EXAM target으로 다시 요청했다. target 동일성만으로 결과 의미의 중복을 막지 못한다. 추가한 목표·원문·판단 이유의 비용도 각각 분리 측정한다. 전체 문맥 복원이나 지침 검색 기본 활성화는 이번 결과로 지지되지 않는다.

코드 결함 복구는 유지하되 전체 v0.8.3은 개발 후보로 보존한다. 점수 개선이 검증됐다고 표시하거나 공식 제출을 권하지 않는다. 다음 비교는 위 의미·임상 관계를 작게 나눠 검증해야 하며, 이번 회차에 더 많은 유료 진료를 추가하지 않았다.

## 6. 검증·산출물·재현
