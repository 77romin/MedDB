# 개발 9차 — 단계별 개선과 실험 검증

2026-10-18 KST. **진행 중 보고**: 표본 진료와 개발 검토가 끝나면 이 문서를 완료 결과로 갱신한다. 공식 제출·PR 병합은 하지 않는다.

## 범위와 측정 설계

사용자 승인에 따라 결정 정보 완결성, 상담 중 질문 응답, 출처 기반 SOAP 분류를 차례로 구현하고 기능별 커밋했다. Doctor는 `openai/gpt-6-luna`, 세션 밖 개발 검토자는 `openai/gpt-6.1-sol`이다. 기존 공식 67.132와 개발 검토 추정은 다른 평가다. 공식 ≥78/85/90 달성 여부는 별도 공식 평가 전에는 판단할 수 없다.

초기 계획은 기준/목표/상담/기록 각 공개 3증례 1회와 마지막 후보의 추가 반복 3회였다. 실제 초기 목표 후보가 새 상태 필드를 출력하지 않아, 추가 반복분을 계약 보완 후보 확인에 사용했다. 실행 중인 소스는 수정하지 않았고 5조건 × 3증례 = 최대 15회로 유지했다. 최종 후보의 동일 조건 반복이 없어 단일 실행의 점수 변동과 구성요소 효과를 확정하지 못한다. 이미 반복 개발한 공개 증례이며 독립 검증도 아니다.

## 구현과 의미상의 한계

### 결정 목표·종료 검토

목표는 need/scope/status/priority/reason과 실제 응답 인용을 갖는다. 동일 ID의 scope를 뒤에서 넓힐 수 없고, 질문이나 의사의 계획만으로 resolved가 될 수 없다. 명시적 모름을 확정 완료로 받지 않는다. 최대 8개를 보존하고 변경분만 출력한다.

이 검사는 출처·형식의 검사다. 처음부터 너무 넓은 scope를 정하거나 부분 인용의 의미를 잘못 해석하는 경우까지 보증하지 않는다. resolved는 임상적으로 확인됐다는 코드의 보증이 아니다. 중요한 상태는 원문·검토와 대조한다.

일반 DONE 직전에는 한 번만 주요 결정 누락을 검토하고 추가 행동 하나를 제안할 수 있다. 모든 슬롯 채우기를 강제하지 않으며, 별도 마무리에서 할 일반 설명을 추가 수집 이유로 쓰지 않는다. 긴급 종료는 실제 인용 ID와 이유가 있으면 검토를 기다리지 않는다. 인용이 임상 긴급성 자체를 입증하는 것은 아니다. 시간·턴·검토 실패 한계를 두어 무한 재질문을 막는다.

### 상담의 새 질문·우려

답변 첫 문장 뒤 환자가 다시 질문하면, 남아 있던 이전 보완 문장을 중단하고 새 질문을 처리한다. 최대 3회 답변 생성과 실제 남은 턴을 함께 제한하고, 안전·다음 행동·추적의 아직 미전송된 핵심 문장과 이해 확인·교정 예산을 남긴다. 모든 SAY는 NFC 30자 이내 완결 문장이다.

구체적인 두려움도 휴리스틱으로 감지하지만 모든 우려를 찾는 것은 아니다. 질문 상태는 실제 전송한 답의 evidence_id에 연결하며, `answer_sent_unverified`는 답을 보냈다는 뜻이다. 직접적인 답인지, 환자가 이해했는지는 별도 검토다. 마지막 교정도 명시적 질문 ID와 실제 성공한 SAY가 연결됐을 때만 답변 근거에 넣는다.

조건부 전망·계획의 이유·치료 경로와 모르는 범위를 구분해 설명하도록 했다. 새로운 처방·용량·확진·예약 사실을 추가하라는 의미가 아니다. 실제 즉시 필요한 안전 안내는 수집 중에도 할 수 있다.

### 출처 기반 SOAP

최종 모델은 병력 문장을 새로 생성하는 대신 실제 SAY 응답 ID를 history_routes로 분류한다. 코드는 응답 전체를 보존한다. EXAM·존재하지 않는 ID·되말하기를 병력으로 라우팅하지 않으며, 가족력에는 명시적 가족 맥락을 요구한다. 충돌하는 라우팅은 일반 병력에 원문으로 남기는 보수적 경로를 쓴다.

같은 원문에서 fact 여러 개를 추출했어도 제출 기록에는 전체 응답을 한 번만 쓴다. 원문의 혼합 양성·음성은 그대로 유지하고, fact의 bare absent 같은 메타데이터를 임상 문장 앞에 붙이지 않는다. fact·원문·목표·분류는 별도 감사 로그에 보존한다. 이 방식은 검증된 자유 문장 임상 요약이 아니라 **출처를 보존한 추출형 정리**다. 분류의 의미·완결성 검수는 남는다.

주호소는 opening에 실제 있는 짧은 인용일 때만 줄이고 전체 초진 정보는 HPI에 유지한다. 실제 이해 확인 질문·응답은 P.education으로 옮긴다. 감별의 판단 이유는 실제 근거 ID가 있을 때 모델 해석으로 표시한다. 인용 존재만으로 해석이 맞다는 보증은 하지 않는다.

## 모니터링과 채택 기준

`tools/stage_report.py`가 실행 전/진행 중/완료/실패/미검토를 구분하고, 비공식 영역 점수·사용량·목표 갱신·감지 질문과 답변 연결·기록 크기를 함께 집계한다. 데이터가 없을 때 0점으로 채우지 않는다. 공식 점수는 항상 별도로 둔다. `suite_report.py`도 decision_review/closure_audit 옵션을 구분하며 이전 회차 JSON을 덮어쓰지 않는다.

목표 수·질문 감지 수·빈 칸 수 자체를 점수로 삼지 않는다. 원문 근거를 확인한 핵심 정보, 실제 설명, 안전·사실성 회귀를 먼저 검토한다. 단일 최고점·평균 비용 감소만으로 채택하지 않는다.

현재 테스트는 126개 통과이며 테스트 성적과 API 임상 성능을 구분한다. Docker·공식 서버 환경·공식 점수는 새로 검증하지 않았다. 완료 시 최종 테스트·게시본·ZIP 검사와 각 단계의 점수·로그 판정을 추가한다.

현재 실행 상태와 비공식 점수는 [단계별 실험 모니터](staged_009.md)에 있다. 진행 중 집계이며 완료 후 갱신한다.
