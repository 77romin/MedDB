# 개발 12차 — 종료 걱정 중복 응답 제한

2026-10-19. **v0.9.7 비교 완료**. Doctor는 `openai/gpt-6-luna`, 세션 밖 개발 검토자는 `openai/gpt-6.1-sol`이다. 공식 점수는 미측정이다.

## 관찰된 병목

v0.9.5 C01은 최초 걱정을 설명 묶음의 `patient_concern`으로 전달하면서도 pending 질문으로 등록해 별도 답변을 생성했다. 답변 뒤 환자가 같은 두려움을 다시 표현하면 이를 새 질문으로 등록해 최대 3회 답변했다. 실제 로그에서는 걱정과 답변 2회가 추가됐고, 일부 답변은 불확실성만 반복했다.

이 경로는 핵심 안전·계획 전달 전에 턴과 모델 호출을 소비하고, 설명을 짧은 지시문으로 더 분절한다. C03·C10에서도 최초 걱정은 종료 묶음이 직접 답할 수 있으므로 이중 처리가 필요하지 않다.

## v0.9.6 변경

1. 최초 걱정 질문의 환자 응답은 pending 질문으로 다시 만들지 않는다. 그대로 종료 묶음의 concern 입력과 환자 증거로 보존한다.
2. 설명 도중 처음 나타난 질문·구체적 두려움은 기존처럼 직접 답한다.
3. answer 뒤에는 물음표·의문형·`궁금`이 있는 명시적 새 질문만 추가 답변한다. 반복 두려움은 연쇄 답변을 만들지 않고 남은 concern 설명이나 최종 조정에서 다룬다.
4. 최초 걱정의 묶음 처리와 반복 두려움의 비연쇄 처리를 회귀 테스트로 추가했다. 전체 148개 테스트가 통과했다.

## 검증 계획

- 고정 v0.9.6 C01을 먼저 실행한다.
- v0.9.5 C01의 64점, 44턴, 1,236초, 질문 답변 호출 3회와 비교한다.
- 안전·소통 점수를 유지하면서 질문 답변 호출과 종료 턴이 줄어드는지를 채택 기준으로 삼는다.
- C01이 지지할 때만 C03/C10으로 확장한다. 공식 점수나 독립 일반화 성능으로 해석하지 않는다.

현재 80점 이상 기대 근거가 없으므로 제출 ZIP은 만들지 않는다. GitHub 인증 만료로 최종 결과 커밋의 푸시는 인증 갱신 후 재개한다.

중복 답변과 시간은 줄었지만 종료 생성이 concern 문장을 비운 실행에서 최초 걱정까지 pending에서 제외돼 직접 답변이 사라졌다. 최종 진단이 급성 독성 중심으로 달라져 추론 점수도 12→8로 변했으나, 의사소통 하락은 코드 변경과 직접 관련된 회귀다. 따라서 v0.9.6은 확장하지 않는다.

v0.9.7은 concern 문장이 정상 생성되면 별도 답변을 만들지 않고, 생성이 비었을 때만 최초 걱정을 pending으로 한 번 복구한다. 조건부 복구 테스트를 포함해 전체 149개가 통과했다. C01을 다시 실행해 걱정 답변과 효율의 균형을 확인한다.

C01의 질문 답변 호출은 3→1회로 줄었고 최초 걱정과 새 명시적 질문을 모두 다뤘다. C03/C10의 호출은 1→0회, 1→1회였다. 세 증례 모두 환자 질문 미답변은 0건이며 실제 concern·계획·추적·안전망을 전달했다.

실행 시간은 C01/C03/C10 759/733/670초로 v0.9.5의 1,236/1,144/921초보다 짧았다. 평균은 약 1,100→721초지만, C03의 25개 행동 조기 종료와 API 응답 변동이 섞여 있어 전부 코드 효과로 보지 않는다. C03 하락의 주된 검토 근거도 조기 종료로 인한 검사 목적·일정과 유력 잠정 진단 설명 부족이었다.

## 결론

v0.9.7은 종료 걱정 중복을 줄이고 직접 답변을 보존한 기술 개선으로 채택한다. 평균 점수 차이는 작고 C03 회귀가 있어 일반화된 성능 향상으로 주장하지 않는다. 다음 우선순위는 조기 DONE 전 진단별 핵심 판단, 검사 이유·결과 확인 시점, 치료 방향이 준비됐는지 검증하는 것이다.

최고 비공식 점수는 76점으로 원래 80점 기대 조건을 충족하지 않았다. 이후 사용자가 현재 후보를 먼저 제출해 공식 점수를 확인하도록 명시적으로 요청해 v0.9.7 ZIP을 생성했다.
