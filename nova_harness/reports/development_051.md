# 51차: 관찰 해석과 상태 갱신의 단일화

## 결론

50차 E01–E05를 만드는 이중 해석 경로를 별도 `R3a_observation_state` 후보에서 교체했다. 기존 답변 접두 기반 read_answer와 키워드 note_seen이 각각 상태를 바꾸던 경로 대신, 성공한 실제 답변을 한 번 구조화하여 질문 완료·환자 현재 소견·온톨로지 병력 소견·기록 입력에 공유한다. 공식 점수 개선은 미측정이며 제출 권장본으로 확정하지 않는다. E12 안전계획→실제 발화 손실은 이번 수정에 포함하지 않았다.

## 구현

- 기존 PatientState/Evidence를 재사용한다. 원문은 불변 근거로 보존하고 개념·주어·시점·양성/음성·범위·조건/빈도·정정 출처를 별도 원자로 기록한다. 질문 target 및 응답 용어 매칭은 후보 ID만 제안하며 사실을 확정하지 않는다.
- 후보가 있는 관찰에 Doctor `openai/gpt-6-luna` 추출을 최대1회 호출한다. 실패/절단/출처 불일치이면 원문과 미확인을 남긴다. 원문 인용 검증은 의미 정확성을 보증하지 않는다.
- 현재 환자의 전체 범위 관찰만 현재 이진 뷰에 반영한다. 빈도/조건 제한은 보존하되 무조건적 이진 소견으로 투영하지 않는다. 가족력·과거력·알레르기 개념은 DB의 SOAP 분류에 맞는 대상/시점으로 별도 KB 뷰에 반영한다. 따라서 가족의 두근거림과 가족력 개념을 혼동하지 않는다. 모듈 머리말의 current-only 설명보다 이 구체적인 두 뷰 구분이 정확하다.
- 질문의 대상/시점에 충분히 답했는지는 answer_contract로 따로 관리한다. 가족력 질문에 가족/과거 답변을 받았다고 환자의 현재 증상을 채우지 않으며, 현재 증상이 미확인이라는 이유만으로 가족력 질문을 반복하지 않는다. 완료에는 같은 target의 실제 수용 관찰이 필요하다.
- 동일 원장 스냅샷을 최종 기록 생성 입력에도 전달한다. 전체 transcript는 계속 보존한다. 원장이 입력됐다는 사실과 최종 SOAP의 모든 내용이 정확하다는 주장은 다르다.
- 진찰 해석·진단 순위 알고리즘·종료 예산·조기 종료·계획 발화 생성은 바꾸지 않았다. 48차 문진 순서/R3a 검색을 바탕으로 하며49차 자유 질문 연결 및 S3 안전 오버레이를 함께 적용하지 않는다.

## 단계별 실제 모델 엣지 검증

10개 작성자 기대 사례에 실제 Doctor를 호출했다. 기대값은 모델 입력에 주지 않았다. 임상 골드셋/공식 평가가 아니며 코호트를 합산한 정확도로 표현하지 않는다.

| 단계 | 기대 충족 | 조건/한계 | 집계 |
|---|---:|---|---|
| 초기 |9/10|거의 없음의 제한 해석 실패|observation_edges_live_051_initial.json|
| 제한 투영 보완 |10/10|질문 완료 계약 전|observation_edges_live_051_projection.json|
| 완료 계약 추가 |10/10|환자 문맥 없음|observation_edges_live_051_contract.json|
| 최종 런타임·빈 문맥 |7/10|대상 unknown/partial 보류가 작성자 기대와 불일치|observation_edges_live_051_contextless.json|
| 최종 런타임·대상 문맥 |10/10|모든 사례에 동일한 성인 본인 진료 문맥 추가|observation_edges_live_051.json|

마지막 두 실행은 입력 조건이 다르므로 동일 입력의 순수 코드 개선 비교가 아니다. 실제 전체 진료에서는 초기 호소·나이·성별 문맥을 제공한다. 최종 저장 재생은 같은 모델 입력과10개 판정을 재현했다(`observation_edges_final_replay_051.json`). 중간 재생 파일은 당시 소스 검증 결과로 동결한다.

## 전체 개발 API 검증

총12개 독립 전체 세션을 실행했다. 실제 가상환자·진찰 API를 사용했다. 서로 다른 환자/모델 응답이므로 아래 차이를 코드의 인과 효과나 공식 점수로 표현하지 않는다.

| 증례 | 앞선 대조군 턴/초/Doctor 시도 | 최종 후보 턴/초/Doctor 시도 | 최종 추출 호출 | 최종 명확화 |
|---|---|---|---:|---:|
|C01|43 /380.818 /23|42 /338.697 /29|18|4|
|C03|32 /185.994 /11|34 /228.752 /22|10|1|
|C10|44 /277.550 /28|42 /311.798 /38|15|2|

대조군은 같은 작업 중 먼저 실행한48차 coverage_order 모드이며 최종 후보와 동시 시작이 아니다. C01 대조는 PROVIDER_RESPONSE_INVALID1건, C03 대조는 절단1건을 포함한다. 최종 세 후보는 모두 DIAGNOSE 완료·오류0·절단0이며 시작/종료 소스 지문이 같다. 문자 그대로 같은 질문 반복0건은 의미상 중복0을 보증하지 않는다. 최종 수용 사실은 C01 17개/C03 10개/C10 15개로 출처 인용은 전부 원문과 일치했고 동일 원장이 기록 입력에 포함됐다. C01은 검증 거절3행과 partial8개가 남아 임상 완전성을 주장하지 않는다.

초기 후보3세션은45/36/45턴(C01/C03/C10)이었다. 가족/과거 답변을 현재 환자 뷰만으로 완료 판정해 불필요한 명확화를 만들었으므로 완료 계약과 온톨로지 병력 뷰를 분리했다. 중간 계약 단계는 C03 35턴·C10 45턴이며, C01은 환자 API503 오류8회 후20턴에서 기록을 제출했다. 이 C01은 정상적인 전체 문진 검증으로 간주하지 않는다. 모든 중간 실패를 집계에 보존했다.

초기6세션 집계/후보3재생은 `observation_session_initial_051.json`, `observation_session_initial_replay_051.json`, 계약3세션 집계/오류 없는2재생은 `observation_session_contract_051.json`, `observation_session_contract_replay_051.json`이다. 이 파일들의 당시 소스 일치 표시는 이후 수정까지 검증한다는 뜻이 아니다. 최종3세션 집계/엄격 재생은 `observation_session_final_051.json`, `observation_session_final_replay_051.json`이다. 최종 재생은 모델 입력·행동·최종 제출 SOAP가 저장 실행과 일치했다. 이는 SOAP 임상 정확성 검증이 아니다.

## 검증 범위와 남은 문제

전체303테스트 통과. 합성 전체 진료 테스트는 추출 모델 출력을 주입한 제어/기록 경로 검증이며 실제 모델 성공률과 구분한다. 최종 런타임 커밋은 f309281, ledger SHA256은 `1f433f085ae03fa8b4e8e57b86ce290c5a738e8af0c41660489a07134d215dd8`, E2 연결 모듈은 `11606a8f2e090962f0d7ef09087929c9280c856983ad4a7e8daaf772b0e14263`다. 원문 로그/키는 로컬 results/.env에만 유지한다.

추가 추출 호출과 지연 비용이 분명하다. 가족/과거/복합 답변의 일부 보수적 거절, 보호자가 아이를 설명할 때 기존 PatientState의 가족 표현 방어가 환자 아이 근거를 거절할 가능성, 약물 세부 속성 완성, 자유 질문 target 미연결이 남아 있다. 합성 무문맥7/10도 이러한 문맥 의존성을 드러낸다. 원문은 보존하지만 재질문을 완전히 제거하지 못했다. 모든 후보 개념/미지 질환을 포괄하는 범용 추출기가 아니다.

다음 구조적 우선순위는 E12의 조건·행동·긴급성을 하나의 계획 객체에서 실제 발화와 SOAP로 렌더링하고 성공 발화로만 수행을 확정하는 경로다. 이번 변경의 공식 안전/정보수집/의사소통 점수는 없다. 새 제출 ZIP·공식 업로드·Docker 실환경 검증·PR 병합은 하지 않았다.
