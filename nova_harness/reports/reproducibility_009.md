# 9차 고정 소스 재구성

실행별 `manifest.json`·`source_snapshot.zip`·원문 로그는 로컬 `results/`에 보존하며 Git에 올리지 않는다. 아래는 로그·키 없이 게시 저장소의 Git 객체만으로 각 후보의 런타임을 재구성하는 파일 조합이다. 병렬 실험 중에도 실행한 소스는 수정하지 않았다. 실행 전 준비 중인 소스에는 계약·검토 프롬프트 보완을 반영했다.

| 후보 | 기본 커밋 | 해당 파일만 가져올 커밋 | 대조 결과 |
| --- | --- | --- | --- |
| v0.7.3 기준 | `0d9e154` | 없음 | 진입점·SDK·agent Python/JSON 20파일 일치 |
| v0.8.0 초기 목표 | `c680443` | 없음 | 21파일 일치 |
| v0.8.0.1 보완 목표 | `c680443` | `prompts.py`, `__init__.py`: `685555f`; `closure.py`: `eab29f2` | 21파일 일치 |
| v0.8.1 상담 | `c680443` | `prompts.py`, `__init__.py`, `state.py`: `e56ff25`; `closing.py`: `1d414ee`; `closure.py`: `eab29f2` | 21파일 일치 |
| v0.8.2 기록 | `1d414ee` | 없음 | 22파일 일치 |
| v0.8.3 복구 | `fe9dbab` | 없음 | 22파일; 최종 대조 예정 |

표의 파일명은 `nova_harness/nova_agent/` 아래다. 기본 커밋의 `nova_harness/`를 별도 폴더로 내보낸 뒤 지정한 파일만 해당 Git 객체에서 덮어쓰는 방식이다. 원본 MedDB 루트나 현재 작업 checkout을 재설정할 필요가 없다. 대조는 파일 이름·내용의 바이트 일치이며 Docker·공식 서버 실행 검증을 뜻하지 않는다.

단계별 커밋을 기능 단위로 나누는 과정에서 준비 중인 후보의 독립 수정이 교차했으므로, 중간 커밋 하나를 후보 전체라고 가정하지 않는다. 최종 v0.8.2는 단일 커밋 트리로 복원할 수 있다.

v0.8.0.1 / v0.8.1 / v0.8.2의 `STEP` 문자열 SHA-256은 모두 아래와 같다.

`31880d0716f3a080bc49b2de710ac16f8e4ba975bff1ddd85fef6736fcd735e2`

세 버전의 수집 프롬프트가 같으므로 세션마다 달라진 문진 정보량을 상담·기록 수정의 인과 효과로 해석하지 않는다. 환자·Doctor의 응답 변동과 종료 검토 결과가 남는다. 최종 계획 프롬프트와 마무리 흐름은 단계에 따라 다르다.

개발 실행은 모두 Python 3.12를 사용한다. 로컬 회귀 테스트는 3.9·3.12에서 확인했다. 고정 소스에는 키 파일을 복사하지 않았고 실행 프로세스의 개발 환경변수만 사용했다. 원문 대본·모범 기록은 개발 검토 도구만 읽으며 런타임 재구성 파일에 포함하지 않는다.
