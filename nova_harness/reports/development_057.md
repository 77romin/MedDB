# 57차: 병합된 팀원 B1을 기반으로 개발 경로 전환

사용자가 팀원 PR 병합 코드를 기반으로 개선하고 향후 병합 충돌을 줄이도록 승인했다. 최신 origin/main05f9ed09ae49c0ecbf79e9af091a74fad1a658a1을 작업 브랜치에 일반 병합했다(18c9af2). 충돌 없이 반영됐으며 main 직접 변경·PR 병합·force push는 하지 않았다. 이 승인은 D098의 main 미반영 방침을 대체한다.

## 코드와 병합 경계

- 현재 개발 대상은 실제 저장소 루트의 examples/agent_b1.py와 새로운 agent_b1_observed.py/reader_b1_observed.py다. 별도 로컬 폴더에서는 vendor/meddb-publish가 그 checkout이다. vendor/meddb는 과거 비교용으로 보존한다.
- B1의29턴·DONE·선택·기록·마무리·모델 설정을 유지한다. 기본 reader_g 경로도 유지한다. 공통 B1 파일에 선택적 reader 연결만 추가하고, 후보는 새 고유 파일/별도 진입점으로 둔다. Q1·추가 추출 모델·RAG를 이식하지 않는다.
- 원문 질문/답변/턴과 연결을 메모리에 보존하며, 표준 질문의 정확한 항목을 우선해 짧은 예·아니요를 한 항목에 연결한다. 단어 별칭으로 한 질문이 복수 개념에 걸리는 경우를 표준 질문으로 좁힌다. 부분/가족/과거/모호 응답은 임의의 현재 정상으로 바꾸지 않는다. 같은 관찰을 note_seen/read_qa 두 경로로 중복 해석하지 않는다.
- 정규식 보수적 해석이다. 초기 진술/진찰은 기존대로며 복합 의미·주체/시점 변형의 해석 완전성·의미 반복·마무리 완전성은 보장하지 않는다. 원문은 SOAP 생성에 남지만 임상 추출 누락 가능성도 남는다.
- 기존 tools/make_submission.py를 수정하지 않고 별도 make_b1_observed_submission.py에서 B1 패키지를 재사용한다. 팀원 공통 파일 변경을 줄였으나 미래 동일 부분 수정의 충돌까지 보장할 수는 없다.

## 검증

main 기반143테스트 통과(4개 skip), 기존 독립 하네스331테스트 통과. 신규11개는 단일 예/아니요·다른 증상 부정·부분 부정·가족/과거·불확실·복수 개념·상충 처리, 실제 B1 실행→관찰 연결→기록→제출, 기본 B1 경로 유지다. 기존 진찰 거절 테스트의 가짜 RuntimeError가 실제 SDK 예외와 달라 실패해 NovaError로 교체했다(61227f2); 생산 오류 처리를 바꾼 것은 아니다. SDK 경로를 제공한 환경과4개 skip을 숨기지 않는다.

후보 런타임 커밋734d0d6. 시험용 ZIP은 기존 B1 패키저 재사용·새 진입점·독립 prepare를 확인했다. 사용자 제출용 ZIP/공식 업로드는 이번에 요청되지 않았다. 전체 API는 B1/B1O1 각각 C01/C03/C10 총6세션을 동일 시간대에 시작하고 런타임을 고정했다. 최종 결과와 엄격 재생은 아래에 추가한다. 점수 개선으로 선행 해석하지 않는다.

후보 관찰 C01/C03/C10의 raw_only는17/14/14회, scoped_or_uncertain은4/4/1회, explicit은8/2/5회다. 단순 예·아니요 single_question_link 분기는 실제6세션의 후보3개에서0회였다. 해당 분기는 합성 테스트 범위이며 회수율 개선을 입증하지 않았다. 범위가 있는 응답을 현재 이진 소견으로 확대하지 않는 보수적 처리는 확인했지만, 그 판단의 임상 정확성·증례 정보수집 점수는 미검증이다. 전면적 의미 해석 엔진이라고 표현하지 않는다.

엄격 재생 도구는 진행 중 로그에서 요청 응답이 아직 없을 때 실패한 뒤, 완료 이벤트를 요구하는 검사를 추가했다. 최종 완주6개에 대한 재생만 성공 검증으로 센다. AssertionError를 삼키는 기존 fallback으로 실패를 숨기지 않도록 입력 불일치는 별도 BaseException으로 종료한다. 저장 원문은 results에만 있으며 공개 집계는 b1_rebase_sessions_057.json과 b1_rebase_replay_057.json이다.

판단: 최신 main 기반 개발 전환·별도 개선 후보·패키지 경로·기능 검증은 완료했다. 기본 B1을 바꾸지 않고 후보는 opt-in으로 유지한다. 공식 점수 상승·제출 권장은 아직 미확정이며 자동 병합/공식 제출은 없다. 현재 main은 브랜치 조상으로 충돌 없음을 확인하되 미래 팀원 변경까지 무충돌을 보장하지 않는다.
