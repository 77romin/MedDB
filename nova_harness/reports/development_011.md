# 개발 11차 — 실제 마무리 전달 복구

2026-10-19. **v0.9.5 비교 완료**. Doctor는 `openai/gpt-6-luna`, 세션 밖 개발 검토자는 `openai/gpt-6.1-sol`이다. 공식 점수는 미측정이다.

## 문제

v0.9.4 C01은 정보수집 18점에도 안전 8점·의사소통 5점으로 전체 58점이었다. 실제 로그에서 마무리 설명 생성 요청이 524 이후 `REQUEST_PENDING` 네 번과 `PROVIDER_UNAVAILABLE`로 끝났다. 하네스는 assessment·plan·follow_up·safety_net·concern을 모두 비운 뒤 `앞으로 어떻게 하실지 말씀해 주세요`만 전송했다. 환자는 추가 처방을 원한다고 답했지만 핵심 설명과 합의 없이 종료됐다.

기록에는 이후 계획이 있었으나 실제 환자 SAY가 아니므로 수행으로 인정하지 않는다. 이는 임상 판단 생성과 실제 전달 사이의 전송 복구 결함이다.

## v0.9.5 변경

1. 기본 설명 묶음은 최대 2400 출력 토큰으로 제한한다.
2. 생성이 전송·형식 오류로 실패하면 최종 판단·계획·환자 걱정만 포함한 소형 입력으로 새 요청을 한 번 시도한다. 출력은 최대 1600 토큰이다.
3. 소형 요청은 잠정 판단, 지금의 안전 행동, 이후 치료 방향, 담당자·시점, 경고 증상, 걱정에 대한 직접 답만 작성하며 새 진단·검사·처방·예약을 만들 수 없다.
4. 실제 설명 문장이 하나도 전달되지 않았으면 이해 확인을 보내지 않는다. 걱정 질문 자체는 교육으로 세지 않는다.

## 검증 결과

- 로컬 단위·회귀 테스트 146개가 통과했다.
- C01 기본 설명 생성은 전송 오류로 최종 실패했고, 소형 복구가 실제로 발동해 성공했다. 안전망·계획·추적·걱정 대응을 전송한 뒤에만 이해 확인을 수행했다.
- C01 결과가 지지해 같은 고정본을 C03·C10에 확장했다. C03·C10에서는 기본 설명이 생성돼 소형 복구는 발동하지 않았다.

## 결론과 다음 변경

전송 장애가 재현된 C01에서 소형 복구가 의도대로 작동했고 안전·소통이 회복됐으므로 v0.9.5를 채택한다. 다만 C10은 하락했고 세 결과는 반복 공개 증례의 비공식 단일 실행이므로 일반화된 성능 향상이나 공식 목표 달성으로 보지 않는다.

다음 변경은 종료 단계에서 새 걱정 표현을 반복 질문으로 처리하지 않도록 범위를 제한하고, 진단·검사 이유·담당자와 시점·안전망을 연결된 의미 단위로 전달하는 방향을 별도 실험한다.

현재 80점 이상 기대 근거가 없으므로 제출 ZIP을 만들지 않는다.
