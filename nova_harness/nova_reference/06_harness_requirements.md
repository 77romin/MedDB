# NOVA 하네스 엔지니어링 기준

기준일: 2026-10-18 KST. **공식 계약 요약**과 **설계 권고**를 구분한다. 실제 에이전트 코드나 테스트를 구현한 문서는 아니다. 모델명은 `openai/gpt-6-luna`로 확정됐으며, 파라미터 등 남은 미해결 사항은 [07](07_changes_and_conflicts.md)에 있다.

## H01 — 실행 생명주기와 환경

공식 계약: 증례마다 새 컨테이너에서 `python run.py`를 실행한다. `run_agent(prepare, consult)`가 `Client() → prepare() → client.ready() → consult(client, state)`를 연결한다. 준비 중 환자 접근 불가, 준비 10분·ready 이후 진료 30분. 대회 최대 50턴. 빌드는 제출 버전 기준 20분이며 재사용 후 정리·재빌드될 수 있다.

설계 권고: 검색 인덱스·정적 자산은 prepare에서 로드하고, 환자별 상태는 consult 시작 때 만든다. 서버가 준 deadline과 turns_remaining을 기준으로 종료 여유를 계산한다. 항상 마지막 기록 작성·검증·제출 시간을 남긴다. 코드의 성공 종료만으로 기록 제출 완료를 판단하지 않는다.

근거: [규칙 제출](02_rules.md#submission), [실행 예시 3–5](05_run_agent.md#slide-03), [코드 계약](03_docs.md#package).

## H02 — 모델 어댑터와 예산

공식 계약: 예선은 고정 Doctor를 증례당 최소 1회 호출해야 하며 0회면 해당 증례 0점이다. 증례당 최대 200회, 누적 입력 500,000·출력 100,000토큰. chat은 진료 턴을 쓰지 않는다. 빈 Doctor 응답은 200회에는 포함되지만 토큰·효율 비용에는 포함되지 않는다. 개발 가이드는 Doctor 요청당 입력 100,000토큰·max_tokens 8,000을 명시한다. 추론 토큰도 출력 예산에 포함된다.

설계 권고: 모델 ID를 프롬프트에 박아 넣지 않고 `doctor_model_id`, 역할, capability, 가격·예산 설정으로 관리한다. 모델 출력은 구조 검증을 거쳐 행동 후보로 취급한다. JSON 파싱 실패·빈 choices·빈 content·잘못된 action·과도한 길이에 대한 수정 경로를 둔다. 마지막 기록 생성을 위한 호출·출력 예산을 예약하고, 예산 소진 시 이미 수집한 사실로 기록을 만드는 결정적 fallback을 준비한다. 현재 `temperature` 해석은 충돌하므로 효과를 전제하지 않는다.

근거: [규칙](02_rules.md#submission), [개발 모델](03_docs.md#dev-models), [실행 예시 7](05_run_agent.md#slide-07), [모델 변경 및 문서 충돌](07_changes_and_conflicts.md).

## H03 — 행동 검증과 턴 회계

| 행동·결과 | 서버 턴 | 하네스 처리 권고 |
| --- | --- | --- |
| 정상 SAY·EXAM | 1 | 서버 turn·turns_remaining과 자체 ledger 대조 |
| 정상 TEST | 1, 본선만 | 예선 action 후보에서 제외 |
| DIAGNOSE | 0, 세션 종료 | 성공 응답을 확인하고 추가 행동 차단 |
| session·chat | 0 | chat 호출·토큰 예산은 별도 추적 |
| SAY·EXAM 빈 값·30자 초과를 서버로 전송 | 1 | 전송 전 차단. SDK ValueError는 서버 턴 차감과 구분 |
| EXAM_NOT_SPECIFIC·EXAM_NOT_RECOGNIZED | 1 | 같은 잘못된 진찰 반복 금지, 문구 또는 행동 수정 |
| TEST_NOT_SPECIFIC·TEST_NOT_OFFERED | 0 | 본선 검사 후보 수정 |
| ACTION_NOT_AVAILABLE | 0 | 현재 단계·available actions 확인 |
| PATIENT_RESPONSE_INVALID·EXAMINER_RESPONSE_INVALID | 0 | 서버 실패로 분류, 유한 재시도 |
| INVALID_RECORD_FIELDS | 0 | 필드 교정 후 제출 재시도 |

공식 계약: 문자열은 NFC 정규화 후 유니코드 코드 포인트로 센다. 공백·문장부호·줄바꿈을 포함한다. SAY·EXAM·TEST는 30자 이하, SAY는 한 번에 하나의 질문, EXAM·TEST도 구체적인 동작/검사 하나다. 50번째 행동 응답 이후에도 제한 시간 안에 DIAGNOSE할 수 있다.

설계 권고: `len(unicodedata.normalize('NFC', text))`를 사용한다. 자동 잘라내기는 의미가 바뀔 수 있으므로 문장을 다시 생성한다. 정상 HTTP 응답이라도 “한 번에 하나씩 물어봐 주세요”는 정보 획득 실패로 기록한다. 최초 활력징후를 전송 행동과 혼동하지 않는다.

근거: [규칙 상호작용](02_rules.md#interaction), [API](03_docs.md#actions), [오류 표](03_docs.md#errors), [턴 예시 9](05_run_agent.md#slide-09).

## H04 — 재시도와 멱등성

| 상황 | 요청 ID 정책 | 비고 |
| --- | --- | --- |
| 네트워크 단절·같은 작업의 응답 불명 | 같은 request_id와 동일 내용 | 중복 행동·중복 턴 방지 |
| PROVIDER_UNAVAILABLE | 잠시 뒤 같은 request_id | Doctor가 180초 내 응답 시작 못한 경우 포함 |
| REQUEST_PENDING 503/409 | 같은 request_id | 새 Doctor 호출을 병렬 발행하지 않음 |
| PROVIDER_RESPONSE_INVALID 등 무효 모델 응답 | 새 요청으로 재시도 | 개발 가이드가 새 요청 권고. Doctor 호출 수는 계속 증가 |
| 422 진찰 거절 | 수정한 행동은 새 request_id | 같은 ID 재전송은 같은 거절을 반환하며 추가 턴 없음 |

설계 권고: 요청 ID와 payload를 전송 전에 고정한다. 응답이 불명인 작업을 새 ID로 재발행하지 않는다. 무한 재시도 대신 남은 deadline·호출 수로 제한한다. SDK 기본 대기 240초와 서버 180초의 차이를 고려한다. 예시의 2·5·10초 재시도는 과거 기본 에이전트 예시이지 공식 강제 스케줄이 아니다.

근거: [API 요청과 재시도](03_docs.md#actions), [문제 해결](03_docs.md#errors), [실행 예시 4·8](05_run_agent.md#slide-04).

## H05 — 상태·증거·기록

공식 계약: 공식 실행의 `session()`에는 개발 샘플과 달리 지난 행동 events가 오지 않는다. 참가자 코드가 대화를 보관해야 한다. 수집하지 않은 내용을 기록해도 수행으로 인정되지 않으며, 실제 확인한 내용과 다르면 감점된다. 음성 소견은 실제 확인한 경우에만 쓴다. 미확인·미시행·향후 계획을 구별한다.

설계 권고: 각 사실에 source(시작 정보/환자/EXAM/TEST), 턴, 원문, 정규화 값, 확인 여부를 연결한다. 관찰된 사실과 진단 가설을 별도 필드로 둔다. 약물은 이름·1정 용량·1회 정수·횟수·시점·실제 총량을 구별하고, 숫자·단위·나이·부정 여부를 기록 제출 전 대조한다. 거절·서버 오류도 transcript에 표시하되 진찰 소견으로 만들지 않는다. 다른 증례의 환자 데이터·기억·통계를 재사용하지 않는다.

근거: [기록 안내](03_docs.md#clinical-note), [규칙 보안](02_rules.md#data), [실행 예시 11–12](05_run_agent.md#slide-11).

## H06 — SOAP 출력 계약

공식 계약: `client.diagnose(note=note, diagnosis=diagnosis)`로 SOAP 기록과 주진단 하나를 보낸다. 빈 칸은 빈 문자열로 둔다. 필드 누락·추가는 `INVALID_RECORD_FIELDS`. note 전체 UTF-8 100,000바이트, 주진단 500바이트. 최종 기록에는 30자 제한이 없다.

최신 SDK의 `empty_record()`를 스키마 기준으로 확인할 **예상 15칸 구조**는 다음과 같다. A의 주진단은 note 바깥 최상위 `diagnosis`이며 `A.diagnosis`를 임의 추가하지 않는다.

```json
{
  "S": {"cc": "", "hpi": "", "pmh": "", "fh": "", "sh": "", "ros": ""},
  "O": {"exam": "", "tests": ""},
  "A": {"evidence": "", "differential": ""},
  "P": {"tests": "", "treatment": "", "disposition": "", "follow_up": "", "education": ""}
}
```

설계 권고: JSON 구조·값의 자료형·필드 키의 정확한 일치를 검증한다. `O.tests`는 예선에서 비워 두고 필요한 추가 검사는 `P.tests`에 이유와 함께 쓴다. O의 결과에는 받은 턴을 붙인다. 기록에 교육 계획을 써도 환자와 소통한 것으로 인정되지 않으므로 필요한 설명은 DIAGNOSE 전 짧은 SAY로 수행한다. 모델 호출이 실패해도 비어 있지 않은 근거 기반 기록을 제출할 수 있도록 구조화 사실로 fallback을 만든다.

근거: [초진 의무기록](03_docs.md#clinical-note), [실행 예시 6·21](05_run_agent.md#slide-06). 예상 스키마는 자료를 종합했으며 SDK 다운로드·실행으로 검증한 것은 아니다.

## H08 — 배포·검색 자산

공식 계약: 코드 ZIP 50,000,000바이트, 해제 500,000,000바이트, 5,000파일 이하. 루트 `run.py`·`requirements.txt` 필수. 의존성은 `name==version`의 PyPI 휠만 허용한다. 런타임 인터넷 없음. 예선 CPU 2코어·RAM 8GB·GPU 없음. 본선 CPU 8코어·RAM 32GB·A6000 48GB급 GPU 1장, 모델 ZIP 32GB. 본선은 참가자 모델을 `NOVA_MODEL_DIR`에서 로드하고 예선 `client.chat()`을 쓰지 않는다.

공식 계약: 임상 자료 15,904문서는 `NOVA_GUIDELINES_DIR`(`/opt/nova/guidelines`)에 읽기 전용으로 제공된다. CPU 보조 임베딩·검색 인덱스는 제출·실행 한도 안에서 사용할 수 있다. 문서별 출처·라이선스를 준수한다. 자료를 처음 사용할 때 모델·tokenizer·캐시를 인터넷에서 받는 코드는 실패한다.

설계 권고: 대회 운영 규칙 검색과 임상 지침 검색을 논리적으로 분리한다. 이 모음 5개는 운영 계약 자료이지 임상 지침 대체물이 아니다. 정적 검색 자산만 재사용하고 환자 상태는 증례별 초기화한다. 런타임 쓰기는 허용 경로만 사용한다. `/tmp` 512MB·`/output`은 실행 PPT의 설명이므로 최신 local.Dockerfile과 SDK로 재확인한다. 모델 가중치 파일 32GB와 실제 GPU 메모리 48GB는 서로 다른 제한이다.

## H09 — 공개 C01 예시에서 얻을 회귀 시나리오

이 절은 공개된 실패 사례의 분석이며 임상 조언이나 비공개 평가 정답 추정이 아니다.

공개 예시는 62세 여성, 자료상 정답 수면제 의존인데 기본 에이전트는 주요 불면증으로 오진했다. 30턴 중 진찰 거절 6턴, 제시 점수 41.2/100(3회 채점 기준)이었다. 약물의 실제 복용량 “밤 4알·새벽 2알”이 기록에서 빠졌고, 나이를 66세로 바꾸었으며, 음주 “가끔 한두 잔”을 “주 1–2잔”으로 임의 정량화했다. 정보수집·추적·의사소통 점수가 낮아 효율 점수만 높여서는 충분하지 않음을 보여 준다.

설계 권고: 환자 숫자·용량·빈도 보존, 핵심 양성 정보 누락 방지, 거절된 진찰을 정상 소견으로 기록하지 않기, 종료 전 계획·교육 전달을 회귀 시나리오로 삼는다. 예시의 비용 116.85원·Doctor 5.91원·4분20초는 과거 모델과 특정 실행의 관찰값이며 현재 예산 예측 상수로 쓰지 않는다.

근거: [실행 예시 14](05_run_agent.md#slide-14), [18–22](05_run_agent.md#slide-18).

## H10 — 후속 구현의 검증 시나리오

아래는 테스트 명세이며 이번 자료 정리에서 실행한 테스트가 아니다.

- NFC 한글 조합·공백·줄바꿈·이모지를 포함한 30/31 코드 포인트 경계와 빈 내용 차단.
- 단일 진찰 거절 후 실제 남은 턴 동기화, SDK 로컬 거절과 서버 거절 구분.
- 요청 전송 후 연결 단절·REQUEST_PENDING에서 동일 ID 재시도, 중복 턴 방지.
- 빈 Doctor 응답의 새 요청 재시도·호출 수 증가·토큰 미차감, 유한 종료.
- 공식 session에 events가 없어도 자체 transcript로 진료·기록 완성.
- 모델 JSON 실패·나이 불일치·복용량 누락·허위 음성 소견 검출.
- 50턴 도달·deadline 임박·호출 한도 임박 시 SOAP 작성·제출 완료.
- SOAP 15칸과 별도 diagnosis, 추가 키·빠진 키·UTF-8 바이트 제한 검사.
- 서버와 같은 local.Dockerfile로 PyPI 휠 빌드·인터넷 없는 prepare·읽기 전용 실행.
- 샘플 검증 결과에 실행 성공과 참고 점수를 구분하고, 공식 평가 횟수·최종 제출 선택을 별도 기록.

개발 샘플 생성은 팀당 하루 100개, 제출 샘플 검증 10회, 공식 평가 팀·단계별 3회(KST)로 서로 다른 예산이다. 공식 평가 시작 후 코드 오류·시간 초과·기록 누락도 횟수를 소비하므로 로컬 검증 후 진행한다. 대회 개발 키를 코딩 도구에 연결하지 않는다.
