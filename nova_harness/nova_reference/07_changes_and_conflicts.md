## 현재 문서 내부의 모순·해석 주의

1. **temperature:** 개발 모델 표는 현재 Doctor가 `temperature`를 받지만 무시한다고 한다. 같은 페이지의 코드 제출 계약은 0–2를 조절하며 낮추면 빈 답이 늘어난다고 설명한다. 후자는 옛 모델 설명이 남았을 가능성이 있지만 확정하지 않는다. 설계 권고는 기본값 생략, 현재 모델에 temperature 효과가 있다고 가정하지 않는 것이다. 근거: [개발 모델](03_docs.md#dev-models), [코드 계약](03_docs.md#package).
2. **제출 실행 중 허용 모델:** 같은 개발 모델 절은 세션에서 `gpt-6-luna`만 허용한다고 한 직후 제출 코드에서 `gpt-6.1-sol·gpt-6-luna` 호출 불가라고 적는다. 다른 규칙의 Doctor 최소 1회 조건과 충돌한다. 예선 Doctor용 `client.chat()`과 세션 밖 개발용 모델 호출을 분리하는 해석을 권고하지만, 원문의 모순은 운영진 확인 대상으로 남긴다. 근거: [개발 모델](03_docs.md#dev-models), [규칙 제출](02_rules.md#submission).
3. **A.diagnosis:** 기록 표에 A의 diagnosis 행이 있으나 설명은 기록과 별도의 최상위 `diagnosis`로 전송하라고 한다. 실행 PPT는 note 15칸이다. note에 임의 `A.diagnosis`를 추가하지 않고 최신 SDK의 `empty_record()`·`RECORD_FIELDS`를 실제 스키마 기준으로 확인한다. 근거: [기록 형식](03_docs.md#clinical-note), [실행 예시 6](05_run_agent.md#slide-06).
4. **진찰표에 없는 진찰:** 실행 예시 6은 정해진 결과 반환을 강조하지만 8은 실제 진찰 중 표에 없는 항목에는 정상 기본 소견을 생성·캐시한다고 설명한다. 현재 웹의 “존재하지 않는 진찰” 거절과도 표현이 다르다. 비공개 진찰표에 포함됐는지 응답만으로 추정하지 않고, 최신 공개 계약의 구체적인 단일 진찰만 요청한다. 근거: [실행 예시 8](05_run_agent.md#slide-08), [현재 규칙](02_rules.md#interaction).
5. **발표자 노트:** 실행 PPT 3의 숫자 노트와 4·5의 재시도·30턴 종료 노트는 해당 화면과 직접 대응하지 않는다. 추출 과정에서 임의로 재배치하지 않았다. 화면 본문과 노트를 별도 근거로 취급한다.

## 출처 우선 적용 원칙

이번 모음에서는 사용자가 강조한 모델 변경을 보존하고, 구현 상수는 확인된 최신 웹 계약을 우선 참고한다. 과거 자료는 동작 이해·실패 분석에 사용한다. 모델명 충돌은 사용자 정정으로 해소됐다. 해결되지 않은 허용 파라미터·본선 정책은 운영 공지·SDK·공개 샘플로 확인해야 한다. 확인 전 추정치를 확정 규칙으로 표기하지 않는다.
