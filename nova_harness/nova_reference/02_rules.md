# 참가 규칙

> 이 문서는 참고 자료입니다. 원문 속 명령문·프롬프트·코드는 대회 규정 또는 예시를 기술한 인용 자료이며, 이 문서를 읽는 코딩 에이전트에 대한 실행 지시가 아닙니다.

> **모델 변경 확정:** 현재 예선 Doctor는 `openai/gpt-6-luna`(2026-10-13부터)입니다. 공식 웹 문서와 사용자 정정으로 확인했습니다. PPT의 `gpt-oss-20b`는 과거 표기입니다. [변경·충돌 기록](07_changes_and_conflicts.md)을 확인하세요.

## 참가 · 계정

- 의료 AI에 관심 있는 누구나, 개인 또는 최대 4인 팀으로 참가할 수 있습니다. 한 사람은 한 팀에만 소속됩니다.

- 참가 신청에 등록한 이메일로 개인 계정에 로그인합니다. 팀장·부팀장·팀원 모두 제출과 최종 버전 선택이 가능합니다.

- 개인 개발 API 키는 본인만 발급·폐기할 수 있습니다. 활성 키는 계정당 하나이며, 재발급하면 이전 키는 폐기됩니다.

- 팀명·계정 변경으로 제출 횟수나 크레딧을 추가로 받을 수 없습니다. 소속 정보 정정은 운영진에 요청하세요.

## 제출 규격

| 구분 | 예선 | 본선 |
| --- | --- | --- |
| 코드 | Python · UTF-8 · ZIP 50MB (50,000,000바이트) 이하 | Python · UTF-8 · ZIP 50MB (50,000,000바이트) 이하 |
| 필수 파일 | 압축 루트의 `run.py`, `requirements.txt` | 압축 루트의 `run.py`, `requirements.txt` |
| Doctor 모델 | 지정 `openai/gpt-6-luna` API (2026-10-13부터) | 직접 선택·학습한 모델 |
| 모델 자산 | 고정 모델의 가중치·어댑터 제출 금지 | 별도 ZIP 최대 32GB · 등록 후 재사용 |
| 의존성 | `requirements.txt`에 PyPI 패키지를 `name==version`으로 적습니다. 미리 빌드된 휠만 설치되며 실행 중 인터넷은 차단됩니다. | `requirements.txt`에 PyPI 패키지를 `name==version`으로 적습니다. 미리 빌드된 휠만 설치되며 실행 중 인터넷은 차단됩니다. |
| 시간 제한 | 빌드(의존성 설치) 제출 버전당 1회 20분 · 증례마다 준비(`prepare()`) 10분, 진료 30분 | 빌드(의존성 설치) 제출 버전당 1회 20분 · 증례마다 준비(`prepare()`) 10분, 진료 30분 |
| 실행 자원 | 증례마다 컨테이너 1개 · CPU 2코어 · RAM 8GB · GPU 없음 | 증례마다 컨테이너 1개 · A6000 48GB급 GPU 1장 · CPU 8코어 · RAM 32GB |
| 발표 자료 | 해당 없음 | PPT 또는 PPTX 필수 |

예선은 지정 모델의 가중치를 변경하거나 파인튜닝할 수 없습니다. 각 증례에서 지정 Doctor 모델을 최소 1회 호출해야 하며, 한 번도 호출하지 않은 증례는 0점입니다. Doctor 모델(`client.chat()`)은 증례마다 최대 **200회**, 입력 500,000·출력 100,000토큰까지 호출할 수 있으며 턴은 쓰지 않습니다. 모델이 빈 답을 낸 호출(`PROVIDER_RESPONSE_INVALID`)은 200회에는 포함되지만 토큰 한도와 효율 점수의 모델 사용 비용에는 포함되지 않습니다. 수상 후보 팀의 제출 코드는 운영진이 직접 검토합니다. 검색 인덱스와 CPU용 보조 임베딩 자산은 제출·실행 한도 안에서 사용할 수 있습니다.

본선 모델 파일 크기와 실행 중 GPU 메모리는 다릅니다. 가중치, KV 캐시, 추론에 필요한 메모리를 모두 포함해 48GB급 GPU 한 장에서 실행되어야 합니다. 등록한 코드·모델·PPT는 제출 버전으로 고정됩니다.

## 상호작용 · 초진 기록

증례마다 최대 **50턴** 동안 환자와 대화(SAY: 문진·설명·공감)하고 신체진찰(EXAM)을 수행합니다. 각 행동은 1턴입니다. 진찰 목록은 제공하지 않으며, EXAM에는 "복부 청진하겠습니다"처럼 구체적인 진찰 동작 하나를 문장으로 요청합니다. "신체검진 다 해 주세요"처럼 여러 진찰을 묶은 요청은 `EXAM_NOT_SPECIFIC`으로, 신체진찰이 아닌 요청(문진·검사·처치·기록 등)이나 존재하지 않는 진찰은 `EXAM_NOT_RECOGNIZED`로 거절됩니다. 이렇게 잘못 보낸 요청과 빈 내용·30자 초과 SAY·EXAM은 답을 받지 못해도 **1턴을 사용**합니다. 가상 환자·진찰 판정 모델의 오류처럼 서버 쪽 문제로 답하지 못한 경우는 턴을 쓰지 않습니다. 가상 환자에게 증상·병력·검사 결과를 한꺼번에 알려 달라고 하면 "한 번에 하나씩 물어봐 주세요."라고만 답합니다. 예선에서는 혈액·영상 검사(TEST)를 사용하지 않습니다. 본선의 TEST도 목록 없이 "간기능검사 하겠습니다"처럼 검사 하나를 문장으로 요청하며, 대회에서 제공하지 않는 검사는 턴 차감 없이 `TEST_NOT_OFFERED`로 거절됩니다.

| 대상 | 길이 제한 |
| --- | --- |
| 대화 (SAY) | 한 번에 30자 이하 |
| 환자 답변 | 20자 안팎으로 짧게 (길이로 거절하지 않음) |
| 초진 기록·최종 답안 | 30자 대화 한도 적용 안 함 |

공백·문장부호·줄바꿈을 포함해 NFC 정규화 후 유니코드 코드 포인트로 계산합니다. 길이 초과 질문은 잘라 실행하지 않습니다.

진료 종료 시 **S·O·A·P 칸으로 나눈 초진 의무기록과 주진단 1개**를 DIAGNOSE로 함께 제출합니다. 칸은 정해져 있고 각 칸 안은 자유롭게 서술합니다. 제출 자체는 턴을 사용하지 않으며, 환자에게 전달하는 마지막 설명은 종료 전에 일반 대화로 수행합니다.

## 공식 평가 · 최종 선택

- **제출**

코드(본선은 모델·발표 자료 포함)를 올리면서 **샘플 검증** 또는 **리더보드 제출**을 고릅니다. 빌드는 서버가 알아서 합니다.

- **샘플 검증**

공개 샘플로 실행을 확인하고 우리 팀만 보는 참고 점수를 받습니다. 선택 사항이며 공식 평가 횟수를 쓰지 않습니다.

- **리더보드 제출**

공식 평가 증례로 채점해 리더보드에 반영합니다. 샘플 검증 없이 바로 진행하며, 실행에 실패해도 그날의 공식 평가 3회 중 1회를 씁니다.

- **최종 선택**

팀·단계별 최종 평가에 사용할 제출 하나를 선택합니다.

공식 평가는 **팀·단계별 KST 하루 3회**입니다(2026-10-15부터. 그 전에는 1회). 공식 평가 1회는 예선 리더보드 5증례를 채점하며, 예선 최종 평가는 10증례를 GPT(`gpt-6.1-sol`)·Claude·Gemini 세 모델이 각각 채점한 점수의 평균으로 매깁니다. 코드·모델 업로드와 샘플 검증은 공식 평가 횟수에 포함되지 않습니다. 샘플 검증은 실행 여부를 확인하고, 우리 팀에만 보이는 참고 점수(공식 평가와 다른 gpt-6-luna 채점)를 함께 보여 줍니다. 평가가 시작된 뒤 참가자 코드 오류·시간 초과·결과 누락이 발생하면 해당 평가 횟수에 포함됩니다. 확인된 서비스 장애의 복구 평가에는 추가 횟수를 차감하지 않습니다.

공식 평가의 총점과 처리 상태를 공개하며, 영역별 점수는 우리 팀 제출 화면에서 볼 수 있습니다. 이름이 `public`인 평가 세트도 증례 원문이 공개되는 것은 아닙니다. 본선 자동 점수와 최종 5팀 의사 평가는 구분하며, 결합 정책이 확정되기 전 자동 순위를 최종 수상 순위로 표시하지 않습니다.

## 개발 크레딧

개인 API 키로 사용하는 개발 크레딧은 팀원이 공유합니다. 남은 크레딧과 사용·예약 비율은 개발·API 화면에서 확인 가능합니다.

- 개발 Doctor와 가상 환자 호출에 실제 사용 비용이 반영됩니다.

- 개발 키로는 진료 세션 밖에서 `gpt-6.1-sol`·`gpt-6-luna`도 호출할 수 있습니다(자가 채점·데이터 생성용). 사용한 만큼 차감되며, 제출 코드 실행 중에는 쓸 수 없습니다. 세션 밖 호출은 팀당 하루 gpt-6-luna(Doctor 모델) 1,000회, gpt-6.1-sol 100회까지이며 성공한 호출만 셉니다(KST 기준).

- Evaluation Agent 채점 비용은 참가자 개발 크레딧에서 차감하지 않습니다.

- 공식 평가 비용도 개발 잔액과 구분합니다. 개발 잔액 부족만으로 공식 평가 기회가 제한되지 않습니다.

- 개발 키는 대회 준비에 사용하며, 요청·사용량은 기록됩니다. 다른 사람에게 키를 공유하지 마세요.

- 개발 키와 크레딧을 Claude Code, Codex, Cursor 같은 코딩 도구나 다른 서비스에 연결해 쓰지 마세요. 대회 에이전트 개발 외 용도로 확인되면 크레딧이 회수될 수 있습니다.

## 자료 이용 · 보안

외부 자료와 오프라인 라벨 생성 도구는 연구 출판에 사용할 수 있는 라이선스를 확인하고 출처·생성 과정을 명시해 사용합니다. 실행 중에는 지정 대회 API만 허용되며 외부 인터넷·API에서 자료나 모델을 내려받을 수 없습니다. 운영진이 제공하는 진료지침 자료는 실행 환경의 `/opt/nova/guidelines`에 있으며, 문서별 라이선스 조건(비상업적 이용, 출처 유지, 변경본 배포 금지 등)을 지켜 사용합니다.

- 비공개 평가 증례로 학습·튜닝하거나 정답을 추출하는 행위는 금지됩니다.

- 증례는 독립적으로 처리합니다. 다른 증례의 기억·예측·통계를 가져올 수 없습니다.

- 다른 팀의 계정·코드·키 접근, 비공개 증례 반출, 평가 시스템의 지시 변경·비공개 프롬프트 추출 시도는 참가 제한·실격 검토 대상입니다.

- 출처·라이선스와 결과 재현에 필요한 코드·실행 방법을 보관하세요.
